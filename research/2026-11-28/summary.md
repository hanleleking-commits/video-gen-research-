# 数字人、世界模型与互动作品研究日报：2026-11-28

检索窗口：2026-11-22 至 2026-11-28。  
说明：截至 11 月 28 日，未发现当天新发布且达到收录标准的一手成果；本期重点核验过去 7 天项目的论文日期、代码交付、许可证与可运行性，并标注相对最近日报的新变化。

## 1. 本日摘要

过去一周最重要的变化不是又出现一个更大的视频模型，而是数字人和世界模型开始交付可被程序消费的结构：分层 mesh、SMPL-X、动作程序、碰撞判定、物理冲量、模拟器状态和可执行车辆动力学代码。数字人侧，AvatarAnyone、Head Anything 和 Motion Mamba 2.0 分别补足资产分层、少图头模一致性和长时动作控制，但真正接近实时产品接口的是 BASE：它只依赖对话后端输出的语音流，使全双工语音模型、云 API 与 3D 角色可以解耦替换。世界模型侧，ShowNow 把“生成吞吐量”和“用户输入响应延迟”明确分开，并以预计算多条动作未来把中位响应延迟降至 208 ms；NoPeWorld、WorldInteract 和 SimPWM 则共同表明，可靠互动不能只依赖隐式视频生成，必须引入碰撞头、冲量接口或显式模拟器状态。Coding 的角色也在变化：GameAnything 和 3AGameFactory-Motion 让 coding agent 生成、执行和测试持久运行的游戏逻辑或动作程序；CodeWAM 更进一步，把可执行代码直接纳入世界表示。当前最有落地价值的架构不是“让一个模型负责整个世界”，而是代码与规则系统持有状态和约束、生成模型负责感知与写实表现、agent 负责规划和修复。可运行证据主要集中在研究代码、benchmark 和单机 demo，尚未出现新的客户试点、规模化并发或可核验 ROI。数字人身份授权、水印、撤销和肖像治理本周期没有高质量新增，仍明显落后于生成能力。

## 3. 最值得关注的 12 个进展

### 1. ShowNow：用预测式生成换取可玩的输入响应

- **类型 / 主线**：模型、GitHub、dataset、demo / 世界模型、Coding × 互动作品
- **发布**：2026-11-25；[论文](https://arxiv.org/abs/2611.34693)、[代码与权重入口](https://github.com/showlab/ShowNow)
- **相对上期**：无新版本；本日确认仓库含训练、推理、浏览器 demo、权重、数据集和延迟测试脚本，Apache-2.0。
- **贡献**：播放期间并行准备最多八种 action future，只提交用户最终选择的分支。作者在单张 H100 上报告 480p、16 FPS，并把 ViZDoom 中位输入到显示延迟从 620 ms 降至 208 ms。
- **Coding 接口**：八种离散动作、WebSocket/浏览器运行时、可重放按键轨迹与 P50/P95 latency harness。
- **场景 / 成熟度**：可玩视频、生成式关卡、品牌互动；已开源可运行原型。
- **证据 / 评级**：论文实测＋官方代码；**高 / 必读**。

### 2. WorldInteract：把多材质互动统一成“速度增量”接口

- **类型 / 主线**：论文、demo / 世界模型
- **发布**：2026-11-25；[论文](https://arxiv.org/abs/2611.34730)
- **相对上期**：暂无代码交付更新。
- **贡献**：将材质行为生成与接触响应分离；物理控制器把推力和碰撞转换为统一的 velocity-increment，因果视频生成器负责表现材料运动。
- **Coding 接口**：程序只需提交对象、质量、恢复系数和冲量，适合状态机、物理控制器或交互设备调用。
- **场景 / 成熟度**：材质互动装置、物理教学、游戏特效、软体仿真；论文 demo。
- **证据 / 评级**：论文实测；**高 / 必读**。

### 3. SimPWM：模拟器保存真值，视频模型负责写实渲染

- **类型 / 主线**：论文、GitHub / 世界模型、机器人
- **发布**：2026-11-24；[论文](https://arxiv.org/abs/2611.32786)、[MIT 代码](https://github.com/TingtingLiao/SimPWM)
- **相对上期**：确认仓库已包含配置、示例、补丁和 Python 包，而非只有项目页。
- **贡献**：规则模拟器显式推进机器人及可交互物体，视频模型将代理状态渲染成真实视频，同时保留模拟状态用于检查模型是否服从条件。
- **Coding 接口**：相机标定、机器人模型、点云对象、动作序列和 `info.json` 式状态记录。
- **场景 / 成熟度**：机器人训练、反事实评测、合成数据；已开源研究原型。
- **证据 / 评级**：论文实测＋官方代码；**高 / 必读**。

### 4. CodeWAM：可执行代码成为世界模型的一部分

- **类型 / 主线**：论文、GitHub / Coding × 世界模型
- **发布**：2026-11-24；[论文](https://arxiv.org/abs/2611.32483)、[仓库](https://github.com/Zhisheng-researcher/CodeWAM)

- **Coding 接口**：动力学函数、候选轨迹、历史状态和计划比较器。
- **场景 / 成熟度**：自动驾驶规划与验证；benchmark 原型。
- **证据 / 评级**：论文实测，代码待补齐；**高 / 必读**。

### 5. AvatarAnyone：agent 规划分层 mesh 数字人重建

- **类型 / 主线**：论文、demo / 数字人、Coding × 资产管线
- **发布**：2026-11-23；[论文](https://arxiv.org/abs/2611.30777)、[项目页](https://miraymen.github.io/avataranyone/)

- **场景 / 成熟度**：虚拟试穿、数字演员、机器人仿真人体；可运行 demo、代码未开放。
- **证据 / 评级**：论文实测＋官方演示；**高 / 必读**。

### 6. BASE：以语音流作为数字人的通用表演总线

- **类型 / 主线**：论文、系统 demo / 数字人
- **发布**：2026-11-23；[论文](https://arxiv.org/abs/2611.30388)

- **Coding 接口**：PCM 音频流、会话状态机、角色/声音/动作风格/3D 外观独立配置。
- **场景 / 成熟度**：数字员工、教育讲师、陪伴角色、虚拟主播；研究系统。

### 9. Head Anything：少图、多表情下生成一致的 3D 头部

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动**：BASE 把语音变成可替换的全身表演接口，Motion Mamba 2.0 提供长时、可续接动作。前者更适合对话数字人，后者更适合游戏角色和机器人。
- **3D/4D 表示**：AvatarAnyone 的分层 mesh 比融合 mesh 或纯 Gaussian 更适合换装、布料、碰撞和引擎编辑；Head Anything 改善少图身份一致性，但尚未交付代码。
- **实时交互**：动作生成已接近交互速率，但 BASE 的额外启动延迟、Motion Mamba 的约 276 ms 窗口耗时仍需与 ASR、LLM、TTS、渲染和网络延迟合并评估。
- **音视频与情感**：本周期重点是全身表演和 turn-taking，而非新的高质量 talking-head 或原生音视频数字人基座。视线、细粒度面部情绪与手势语义仍未形成统一可开源栈。
- **工程部署**：Blender、Unreal、MuJoCo、VRM/骨架运行时成为主要接口；“模型直接生成最终视频”正在让位于“模型生成资产或动作，传统引擎持续运行”。
- **安全治理**：本周期没有新的身份授权、水印、肖像撤销或内容溯源机制。AvatarAnyone 和 Head Anything 能从公开视频或少量照片重建身份，使授权记录、训练来源和资产删除能力更加必要。

**产品判断**：动作程序、引擎绑定和语音状态机已能进入产品原型；高保真个人身份重建、全双工情感表演和自动换装仍以研究 demo 为主。

## 5. 世界模型进展

- **架构与训练**：视频生成器正与显式结构结合——WorldInteract 使用冲量接口，SimPWM 使用规则模拟器，CodeWAM 使用动力学代码，NoPeWorld 使用小型安全头。
- **可控 / 可玩生成**：ShowNow 解决输入响应，Residual Guidance 解决运行中改提示词；二者分别优化动作控制和语义控制。
- **长时与物理一致性**：预生成候选未来不能消除长时漂移；碰撞过滤也只覆盖有限安全约束。真实物理仍依赖传统模拟器、规则或外部验证器。
- **空间表示**：SimPWM 的显式对象状态比纯视频更适合规划和验收；视频负责感知质量，结构化状态负责可测量性。
- **机器人 / 游戏 / 仿真**：机器人侧倾向“模拟器状态＋神经渲染”，游戏侧倾向“状态机＋多未来视频”；两者都不再把像素序列当作唯一世界状态。
- **实时部署与评测**：ShowNow 提供了较完整的输入延迟 harness；NoPeBench 则提供碰撞违规回归。相比只报告 FPS，这两类评测更接近工业运行时要求。

## 6. Coding × 新型互动作品

### 链路一：预测式可玩视频

**ShowNow 多未来生成 → 浏览器/WebSocket 动作运行时 → 用户按键选择已准备分支 → 生成式探索游戏与品牌互动。**

代码负责输入采样、分支提交、缓存和延迟监控；模型负责生成视觉未来；传统规则系统负责分数、任务和不可违反的游戏规则。已有开源 demo，但动作仍是离散集合，H100 成本不适合大规模消费者并发。

### 链路二：带碰撞守卫的生成世界

**NoPeWorld 隐状态安全头 → action filter → 视频世界模型 rollout → 不穿墙的导航与训练场景。**

代码负责定义安全策略和替代动作；模型负责视觉生成；Unreal 几何负责训练标签和验收。已有代码、权重和 benchmark，是本周期最完整的“模型＋运行时守卫”案例。

### 链路三：可替换大脑的全身数字员工

**任意全双工语音模型或云 API → PCM 音频流 → BASE 会话状态机与动作生成 → VRM/Unity/Unreal 角色 → 客服、教育讲师、直播角色。**

代码负责工具调用、权限、对话状态和业务流程；BASE 负责说话/倾听动作；引擎负责骨骼、灯光和渲染。论文已验证多个后端，但代码、并发和生产 SLA 未披露。

### 链路四：agent 驱动的角色资产工厂

**视频/GLB 输入 → VLM 或 coding agent 判断结构 → AvatarAnyone 分层优化或 3AGameFactory 动作程序 → Blender/Unreal/MuJoCo → 换装、布料、动画和接触。**

模型负责语义判断与外观补全；agent 负责为不同资产生成流程或程序；确定性优化器和引擎负责几何正确性。3AGameFactory 可运行，AvatarAnyone 尚待代码。

### 链路五：显式状态的机器人世界模型

**相机与机器人模型 → SimPWM 规则模拟器推进动作 → 视频模型写实渲染 → 状态/视频一致性检查 → 机器人策略训练。**

代码和模拟器负责对象真值、动作与可审计状态；生成模型负责缩小仿真视觉域差距。已有开源原型，软体、绳索和复杂接触仍容易偏离真实物理。

### 链路六：可执行驾驶世界表示

**候选轨迹 → CodeWAM 动力学代码执行 → 学习模型预测场景后果 → planner 排序 → 下一决策状态。**

代码负责自车动力学，模型负责难以手写的环境响应，规划器负责安全选择。当前证据来自 NAVSIM benchmark，不等于真车部署或安全认证。

### 链路七：运行中可改写的互动叙事

**剧情状态机/观众投票 → prompt switch → Residual Guidance → 连续流式视频 → 互动电影、直播背景和数字展演。**

代码持有剧情、角色关系和审核规则；模型生成视觉转场；Residual Guidance 抵消旧上下文惯性。组件已开源，但多人状态、跨镜头角色一致性和生产并发仍无证据。

## 9. 系统架构与技术趋势判断

1. **明显升温：显式状态与神经渲染分工。** SimPWM、WorldInteract、CodeWAM 和 NoPeWorld 都不再要求视频模型独立承担全部物理与规则。
2. **明显升温：预测式运行时。** ShowNow 说明工业指标应从 FPS 扩展到 action-to-display latency、空帧率、按时响应率和分支准备成本。
3. **正在成为主流：窄而稳定的接口。** 语音 PCM、速度增量、动作 token、候选轨迹、分层 mesh 和可执行程序比“万能自然语言提示词”更容易组合、测试和部署。
4. **Coding 的位置前移。** 代码不只是外围胶水，而是动作生成、动力学、世界状态、验证器和安全策略本身。
5. **可复用架构正在形成：**

   `agent/剧情规划 → 结构化动作或代码 → 规则/物理状态 → 生成模型渲染 → 安全与一致性验证 → 引擎/RTC 输出 → 遥测与回放`

6. **数字人主流路线趋向双层结构。** 上层是语音 agent、长期记忆和工具调用；下层是可替换的动作、mesh、表情与渲染运行时。
7. **尚未解决**：分钟级身份与几何漂移、多主体持久状态、低成本并发、复杂接触物理、P95/P99 延迟、审核回滚、资产版权和个人身份撤销。
8. **营销风险**：只有视频演示、没有代码、权重、接口、延迟或可复现 benchmark 的“实时世界”应视为概念展示；只报告 FPS 而不报告输入响应延迟也不足以证明可玩。

## 10. 论文精读候选

1. **[ShowNow](https://arxiv.org/abs/2611.34693)**  
   值得读：首次把多未来推测执行系统化用于互动视频。重点看方法中的 shared-history tree、single-latent commitment，以及延迟和长时一致性的权衡。复现风险是 H100 依赖和 304 GB 级数据。

2. **[WorldInteract](https://arxiv.org/abs/2611.34730)**  
   值得读：给不同材料提供统一、可编码的物理接口。重点看 velocity-increment 定义、physics controller、Material-Aware RL。复现风险是代码尚未核验、训练数据来自模拟环境。

3. **[SimPWM](https://arxiv.org/abs/2611.32786)**  
   值得读：清楚区分“模拟器做了什么”和“视频表现了什么”。重点看 counterfactual freeze、对象状态遵循度和不同基础视频模型的差异。风险是软体与绳索被刚体代理错误建模。

4. **[BASE](https://arxiv.org/abs/2611.30388)**  
   值得读：数字人运行时接口设计比单纯动作质量更有工程价值。重点看 conversation state manager、滑窗 continuation、DAHP 和延迟分解。风险是无公开代码，完整延迟需自行重建。

5. **[CodeWAM](https://arxiv.org/abs/2611.32483)**  
   值得读：展示代码表示与学习表示如何共同参与规划。重点看 executable ego dynamics、candidate comparison 和跨 planner 泛化。风险是主要证据来自离线 benchmark，不能外推到真车安全。

## 11. 下周跟踪与可行动建议

### 继续跟踪

1. ShowNow 是否出现非 H100、低显存或量化运行路径，以及八分支并行的单位会话成本。
2. AvatarAnyone 是否按计划开放代码、许可证、预训练模型和可导入引擎的样例资产。
3. BASE 是否开放 PCM 协议、状态机、动作模型或 Web/Unity 示例。
4. WorldInteract 是否发布代码、数据和实时帧率，冲量接口能否接入 Unity/Unreal 物理事件。
5. CodeWAM 仓库是否补齐训练、推理和 NAVSIM 评测脚本。
6. NoPeWorld 是否能扩展到门、楼梯、动态主体和第三人称角色碰撞，而不显著牺牲意图保持。
7. GameAnything 是否公布长时开发成功率、调用成本、失败恢复率和合法自有资产案例。
8. 数字人身份授权、水印、删除和撤销机制是否出现与模型 API 同层级的工程实现。

### 本周可动手实验

#### 实验一：可玩视频延迟基线

- **目标**：区分吞吐率和真实输入响应。
- **组件**：ShowNow、ViZDoom 示例、内置 latency harness。
- **难点**：H100 环境、CUDA/FlashAttention 版本。
- **成功判据**：完成 60 秒固定按键轨迹，获得 P50/P95 action-to-display、空帧率和视觉漂移样本。

#### 实验二：碰撞守卫回归测试

- **目标**：验证安全头能否成为世界模型 CI。
- **组件**：NoPeWorld、NoPeBench Task 2、一个公开世界模型。
- **难点**：上游权重和许可证、显存。
- **成功判据**：固定 20 条路线中穿透率显著下降，同时记录动作替换率和意图偏差。

#### 实验三：语音驱动数字人最小运行时

- **目标**：验证 BASE 的“后端无关”架构，而非复现模型质量。
- **组件**：任意流式 TTS/全双工语音模型、PCM 事件总线、VRM 角色、Unity/Godot/Web 渲染器。
- **难点**：抢话检测、音画时间线和动作续接。
- **成功判据**：替换两种语音后端无需修改角色层；说话、倾听、打断三种状态切换无明显跳帧。

#### 实验四：agent 生成非人形动作程序

- **目标**：验证“代码生成动作”是否比逐帧生成更可控。
- **组件**：3AGameFactory、一个自有 GLB、Blender 或 Godot。
- **难点**：部件语义、骨架轴向和碰撞修正。
- **成功判据**：同一资产完成包含时间、角度、重复次数和轨迹约束的三阶段动作，并可通过参数修改而非重新生成全部动画。
