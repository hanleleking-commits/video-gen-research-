# 数字人、世界模型与互动作品研究日报：2026-07-29

检索窗口：2026-07-23 至 2026-07-29。  
日期说明：当前日期按 Asia/Shanghai 核验。已与 7 月 24—28 日日报去重；论文日期采用 arXiv 实际提交/修订时间，不把 7 月 28 日批次展示时间当作发布日期。早期项目仅在本周期新增代码、权重或实质技术报告时纳入。

## 1. 本日摘要

本周期最强增量来自数字人：研究重心由“单段口型同步”转向开放时长、多轮对话、倾听—执行切换和显式非语言控制。TaoMate把固定容量音视频记忆、分阶段流水并行、ASR、对话模型和浏览器前端打包为可运行代码栈，是本批与 coding 连接最完整的项目；但其交互demo仍需四张约72GB GPU，距离规模化服务尚远。OmniMate进一步提出同时生成画面、语音和音效的开放式音视频数字人，并显式控制每个流式chunk的响应进度，但缺少公开代码和可核验硬件指标。STEER首次把对话中的视线接触、回避、点头节奏和情绪变成可由程序设置的控制量，并提供FLAME运动输出，适合接入传统3D运行时。世界模型新增不在大场景漫游，而在局部人—物和接触动力学：Human-Centric World Model以连续人体状态和离散“抓取/无接触”等命令驱动实时交互；FeelWorld则把触觉、接触和滑移状态显式加入机器人rollout与规划。AptAvatar、DynHair分别改善两步长视频生成和可控发丝动力学，但前者权重尚未公开，后者仍是资产研究原型。产业证据总体仍是作者实验、项目demo和开源研究栈，没有新的客户SLA、并发成本或规模化部署材料。

## 3. 最值得关注的 8 个进展

### 1. TaoMate：长时音视频数字人的可运行实时栈

- **类型 / 时间 / 主线：** 论文、GitHub、权重、浏览器demo；2026-07-27；数字人、Coding × 实时运行时。
- **官方链接：** [论文](https://arxiv.org/abs/2607.24359)、[项目页](https://taoliveaigc.github.io/TaoMate/)、[GitHub](https://github.com/TaoLiveAIGC/TaoMate)。
- **相对上期的新变化：** 全新条目；首次披露完整的命令行推理、resident worker、ASR—LLM—生成器编排和四GPU交互demo。
- **核心贡献：** 保留不可变视觉锚点，把完成的音视频块压缩为固定容量动态状态；通过模态专用残差注意力检索历史，并把不同去噪阶段分配到多GPU流水执行。
- **Coding接口：** JSON定义1—12个prompt片段和seed；仓库提供单/双GPU脚本、四GPU浏览器栈、`readyz`检查、日志和停机脚本。
- **指标与限制：** 项目页报告35 FPS分阶段输出、30分钟连续生成；但DiT表内速度为16.32 FPS且排除VAE与后处理。单卡60秒视频峰值66.8 GiB，交互demo需四张约72GB GPU。
- **场景 / 成熟度 / 证据：** 数字讲师、虚拟主播、长视频叙事；已开源研究demo，Apache-2.0；论文实测与官方代码，高、必读。

### 2. OmniMate：开放式多轮原生音视频数字人

- **类型 / 时间 / 主线：** 论文；v1为2026-07-25，v2修订于07-28；数字人、互动对话。
- **官方链接：** [论文](https://arxiv.org/abs/2607.23023)。
- **相对上期的新变化：** 全新条目。
- **核心贡献：** 同时生成视觉、语音和音效；Generation Progress Controller为每个流式chunk建模执行进度，使角色能完成动作后转入倾听；多图像与参考语音持续提供视觉和说话人身份。
- **Coding接口：** 可推断为对话状态机向GPC传递响应阶段和终止条件，但论文未公开稳定API、SDK或仓库。
- **场景 / 成熟度 / 证据：** 多轮虚拟陪伴、游戏NPC、互动节目；论文原型和作者评测，具体FPS、首帧延迟及硬件未披露；高、必读。

### 3. STEER：把视线、点头节奏和情绪变成程序控制量

- **类型 / 时间 / 主线：** SIGGRAPH Asia 2026论文、GitHub、标注、互动demo；2026-07-26；数字人、Coding × 角色表演。
- **官方链接：** [论文](https://arxiv.org/abs/2607.23840)、[项目页](https://kartik-teotia.github.io/STEER/)、[GitHub](https://github.com/Kartik-Teotia/STEER)。
- **相对上期的新变化：** 全新条目。
- **核心贡献：** 因果flow-matching模型同时接收双方音频、伙伴动作、情绪及行为控制，输出61维FLAME状态；再映射到冻结的通用Gaussian头部头像。
- **Coding接口：** CLI直接设置`gaze={contact,avert}`、`head={still,nod,shake,tilt}`和七类情绪；输出逐帧NPZ与视频，可接剧情状态机或传统头像渲染器。
- **成熟度 / 证据：** 推理代码与示例已开源，CC BY-NC 4.0；639MB主checkpoint链接仍标记TBA，商业使用还受FLAME及第三方许可证限制；高、必读。

### 4. Real-Time Human-Centric World Model：人体与物体状态联合生成

- **类型 / 时间 / 主线：** 论文、实时demo；2026-07-26；数字人、世界模型。
- **官方链接：** [论文](https://arxiv.org/abs/2607.23517)。
- **相对上期的新变化：** 全新条目；把世界模型控制从相机/按键推进到人体和对象接触状态。
- **核心贡献：** 用统一latent融合上身、手和脸部动作；将“无接触”“抓取”等语言编码为有限离散状态，而不是开放prompt；模型可同步改变人物动作和邻近物体状态。
- **Coding接口：** 动捕或角色控制器写入连续人体状态，状态机写入离散交互命令，生成器流式返回局部人—物画面。
- **成熟度 / 证据：** 作者报告两张H100上25 FPS；未发现代码、权重、首帧延迟或引擎插件；研究demo，高、必读。

### 5. FeelWorld：视觉—触觉世界模型进入接触规划

- **类型 / 时间 / 主线：** 论文、机器人规划实验；2026-07-27；世界模型、机器人。
- **官方链接：** [论文](https://arxiv.org/abs/2607.24267)。
- **相对上期的新变化：** 相比上期ViTacWorld的视觉—触觉数据生成，本次新增层级接触状态和直接的CEM规划接口。
- **核心贡献：** 联合预测视觉latent、接触状态、三维触觉latent和滑移；接触门控注意力在自由空间保持视觉路径，在接触后启用跨模态动力学。
- **Coding接口：** 规划器批量提交候选动作，世界模型rollout接触与滑移，CEM按成功和稳定性迭代动作分布。
- **指标 / 成熟度 / 证据：** 作者报告80步rollout的LPIPS较视觉基线低61%，零样本规划平均成功率81.7%；未公开代码或权重；研究原型，高、必读。

### 6. AptAvatar：两步720p长视频数字人

- **类型 / 时间 / 主线：** 论文、GitHub；2026-07-27；数字人、推理加速。
- **官方链接：** [论文](https://arxiv.org/abs/2607.24013)、[GitHub](https://github.com/TaoLiveAIGC/AptAvatar)。
- **相对上期的新变化：** 新增正式技术报告、两步蒸馏说明和结构化动作prompt接口。
- **核心贡献：** Endpoint-Anchored Distribution Distillation把多步教师压到2 NFE；Self-Generated History Replay用旧checkpoint输出模拟推理时污染历史，缓解长时身份漂移。
- **Coding接口：** Python/Gradio、单/多GPU脚本；文本可按帧区间指定1—3段姿态或手势。
- **成熟度 / 证据：** 论文声称720p、60倍加速；Apache-2.0推理框架已公开，但模型卡链接仍为占位且checkpoint未发布，当前不能完整复现；中高、可读。

### 7. DynHair：显式发丝进入可动画头像

- **类型 / 时间 / 主线：** 论文、项目demo；2026-07-26；3D/4D数字人。
- **官方链接：** [论文](https://arxiv.org/abs/2607.23861)、[项目页](https://dynhair.is.tue.mpg.de/)。
- **相对上期的新变化：** 全新条目。
- **核心贡献：** 用结构化3D Gaussian表达显式发丝；LSTM根据头部角速度、加速度、重力方向和运动历史预测发丝形变，并与Gaussian脸部联合优化。
- **Coding接口 / 场景：** 角色运行时可从头部骨骼运动推导动态条件，用于数字演员、VR头像和虚拟试发型；但尚无标准骨骼、USD/FBX导出或Unity/Unreal插件。
- **成熟度 / 证据：** 论文与项目展示，代码和权重未确认；研究原型，中高、可读。

### 8. OmniCache：训练-free视频扩散缓存

- **类型 / 时间 / 主线：** 论文、推理基础设施；2026-07-26；支撑基础设施。
- **官方链接：** [论文](https://arxiv.org/abs/2607.23844)。
- **相对上期的新变化：** 全新条目；与FlashRT的跨GPU编排互补，直接优化单模型内部重复计算。
- **核心贡献：** 分别复用token、帧、块和网络层特征，通过相似度匹配跳过重复计算，再恢复位置一致的缓存激活。
- **Coding接口 / 场景：** 可插入SD3、SVD-XT、Latte类推理循环；适合作为数字人或世界模型服务的可选加速层。
- **指标 / 成熟度 / 证据：** 作者报告三类模型延迟最多下降35%、25%和28%；无确认代码、硬件与第三方验证；研究原型，中、可读。

## 4. 数字人 / 虚拟形象能力进展

**生成与驱动。** TaoMate和AptAvatar都从短片推进到chunk级长时生成；OmniMate进一步把语音、画面和音效放进同一生成过程。仍需区分：TaoMate有可运行栈，AptAvatar缺权重，OmniMate只有论文证据。

**3D/4D表示。** STEER输出可编辑FLAME状态并桥接Gaussian头部，DynHair为发丝增加显式结构和动力学。它们比纯视频latent更容易进入DCC或引擎，但都没有标准化商业资产导出链。

**实时交互。** TaoMate的resident worker、健康检查和浏览器demo最接近可持续运行系统；OmniMate解决执行—倾听转换；STEER解决角色“如何听、如何看、如何回应”。首帧响应、被用户打断后的重规划和高并发仍缺少公开数据。

**音视频与情感表达。** 本批最大变化是非语言行为可控：视线、点头、摇头、倾斜和情绪不再完全从音频隐式涌现。OmniMate尝试原生生成语音和音效，但其声音身份、语言覆盖和安全机制仍待核验。

**工程部署。** 现实产品仍需要RTC、ASR、对话模型、工具调用、审核、生成worker和播放器分层。四张72GB GPU的TaoMate适合实验室或单路高价值体验，尚不适合默认推断为低成本客服方案。

**安全与身份治理。** 本周期暂无新的高质量授权、水印或深伪治理系统。生产部署必须在模型之外记录肖像和声音授权、输入资产哈希、生成日志、撤回状态和内容凭证。

## 5. 世界模型进展

**架构与训练。** 世界状态正在由通用视觉latent分解为更可监督的变量：Human-Centric模型使用连续人体状态和离散接触命令；FeelWorld显式预测接触、力相关触觉和滑移。

**可控/可玩生成。** “抓取”“无接触”这类有限状态比自然语言prompt更适合由代码调用，也更容易做自动测试。当前控制范围仍局限于上半身和近场对象，不是通用开放世界。

**长时与物理一致性。** FeelWorld的噪声注入和自回归rollout降低误差累积，但三项桌面任务不能证明通用物理规律。库存、物体所有权、刚体约束和安全边界仍需传统状态/物理引擎维护。

**空间与多模态表示。** 视觉、人体、对象状态和触觉分层后，模型可以在接触前关闭无意义触觉通道，接触后再进行联合预测；这比无条件拼接传感器更适合实时系统。

**机器人、游戏与仿真。** FeelWorld最合理的落地是候选动作排序和上线前评估，不是替代低层控制器。Human-Centric模型可用于互动角色和虚拟制作预演，但缺少权威物体状态回写接口。

**实时部署与评测。** 25 FPS来自双H100作者实验；FeelWorld未披露规划时延。当前证据不足以支持低延迟竞技游戏、遥操作或安全关键控制。

## 6. Coding × 新型互动作品

1. **麦克风/RTC → Whisper ASR → 对话与prompt规划 → TaoMate resident worker → 浏览器数字人**  
   代码负责会话、状态、健康检查、超时、日志和GPU进程；生成模型负责语音视频表演；播放器负责流式呈现。已有完整开源demo，但硬件成本高。

2. **伙伴视频与双方音频 → STEER语义控制 → FLAME运动 → Gaussian/传统头像 → 可反应NPC**  
   剧情代码可在角色倾听时设置视线接触、回避、点头或情绪；STEER生成连续面部运动；传统引擎处理身体、碰撞和网络同步。已有推理代码，checkpoint交付尚不完整。

3. **动捕状态＋“抓取/松开”等命令 → Human-Centric World Model → 人—物流式画面 → 互动展演**  
   状态机负责合法动作和对象权限，模型生成手、脸、身体及对象接触表现。25 FPS为组件证据；Unity/Unreal端到端实现属于本报告推断。

4. **机器人候选动作 → FeelWorld视觉/触觉rollout → CEM评分 → 安全控制器执行**  
   代码负责候选采样、评分、约束和回滚；模型预测接触与滑移；低层控制器保证执行安全。已有作者规划实验，不是生产部署。

5. **音频＋身份图＋逐帧动作脚本 → AptAvatar → 长视频虚拟主播**  
   创作工具可由LLM把演讲稿转换成帧区间手势，再调用生成器批量生产。结构化接口已公开，但无权重，端到端复现尚不可行。

6. **头部骨骼动力学 → DynHair → 显式发丝形变 → VR/虚拟制片角色**  
   引擎计算头部速度、加速度和重力，模型生成发丝形变，Gaussian渲染细节。组件级证据存在，引擎插件和商业资产管线尚无证据。

## 8. 可复现资源与开发者入口

- [TaoMate](https://github.com/TaoLiveAIGC/TaoMate)：Apache-2.0代码，提供checkpoint入口、哈希校验、单/双GPU批处理和四GPU浏览器demo。最小路径是先在单张72GB卡生成一个12段、约60秒案例；成功判据是显存不超过仓库报告的66.8 GiB且段落切换无明显身份跳变。
- [STEER](https://github.com/Kartik-Teotia/STEER)：CC BY-NC 4.0，需自行接受FLAME许可证。可先运行六个派生特征示例，比较同一输入下`gaze/head/emotion`组合的NPZ轨迹；主checkpoint下载仍待补全。
- [AptAvatar](https://github.com/TaoLiveAIGC/AptAvatar)：Apache-2.0推理框架、Gradio和逐帧结构化prompt已存在，但模型下载仍为占位，暂不能验证论文结果。
- [TaoMate项目页](https://taoliveaigc.github.io/TaoMate/)：提供30分钟、分钟级及短片demo和作者benchmark；复现时应分别测DiT吞吐、VAE解码、首块时间和端到端用户响应，不应只引用35 FPS。
- Human-Centric World Model、FeelWorld、DynHair、OmniMate与OmniCache均未确认公开完整代码和权重，当前适合架构研究，不宜作为近期交付依赖。

## 9. 系统架构与技术趋势判断

明显升温的是三类结构化接口：固定容量持久记忆、可枚举行为/接触状态，以及可由代码设置的角色表演参数。数字人不再只是“音频进、视频出”，而开始暴露响应进度、视线、头部节奏、情绪、prompt片段和健康状态。

正在形成的复用架构是：

`用户音视频 → RTC/ASR → 对话与工具agent → 权威会话/业务状态 → 表演计划 → 数字人或局部世界模型 → 流式播放器 → 审核、监控与回退`

代码负责身份授权、权限、业务事实、对象状态、打断、超时、缓存、日志和回滚；生成模型负责语音、画面、动作细节和未来预测；传统引擎或控制器负责物理、碰撞、骨骼、网络同步与安全约束。

世界模型路线也在从“预测所有像素”转向“显式状态＋选择性生成”：自由运动阶段只预测视觉，接触后再启用触觉；人物动作使用连续latent，抓取等语义使用离散命令。这种分解更适合测试和代码编排。

仍未解决的问题包括首帧延迟、真实打断、多人并发、GPU成本、生成画面向权威对象状态回写、跨传感器触觉迁移、长时人物授权撤回，以及Gaussian头像向标准商业资产格式转换。

需要降级看待“production-ready”“real-time”等命名。AptAvatar没有权重；OmniMate没有公开运行预算；TaoMate的35 FPS依赖多设备流水且不等同于低首响应；Human-Centric模型的25 FPS也不包含完整对话或游戏运行时。

## 10. 论文精读候选

1. [TaoMate](https://arxiv.org/abs/2607.24359)：重点读持久音视频状态、anchor-preserving distillation和stage-parallel执行。差异在于同时给出长时记忆与完整部署代码；风险是硬件昂贵、指标口径复杂。
2. [OmniMate](https://arxiv.org/abs/2607.23023)：重点读Generation Progress Controller、多参考身份条件和VerseBench改造。价值是理解开放式执行—倾听转换；风险是代码和实际延迟缺失。
3. [STEER](https://arxiv.org/abs/2607.23840)：重点读行为伪标注、因果motion prior和Gaussian头像映射。差异是显式控制非语言对话行为；风险是非商业许可证及checkpoint缺口。
4. [Real-Time Human-Centric World Modeling](https://arxiv.org/abs/2607.23517)：重点读连续—离散联合控制、交互状态数据渲染和实时蒸馏。风险是任务范围窄且无公开实现。
5. [FeelWorld](https://arxiv.org/abs/2607.24267)：重点读接触门控注意力、触觉层级状态和CEM规划。与ViTacWorld的差异是把触觉预测直接变成规划信号；风险是任务及传感器覆盖有限。

## 11. 下周跟踪与可行动建议

继续追踪：

1. OmniMate是否发布代码、硬件、首帧延迟和中途打断实验。
2. TaoMate在四GPU交互栈中的语音到首个可播放chunk延迟、并发和失败恢复。
3. STEER主checkpoint是否上线，以及Gaussian头像桥接代码是否开放。
4. AptAvatar权重是否发布，2 NFE结果能否在公开身份和长视频上复现。
5. Human-Centric模型是否提供对象状态schema和Unity/Unreal接口。
6. FeelWorld的真实规划时延、触觉传感器型号及跨设备迁移能力。
7. DynHair是否支持标准发丝、mesh、USD或游戏引擎导出。
8. 数字人系统是否补充水印、授权撤回、声音克隆限制和内容凭证。

本周适合动手验证：

1. **长时数字人运行预算实验**  
   目标：复现TaoMate一分钟生成。组件：72GB GPU、LTX-2.3、Gemma、TaoMate权重。难点：模型依赖和显存峰值。成功判据：完成12段生成，记录首块延迟、端到端FPS、峰值显存及段间身份变化。

2. **可控倾听行为实验**  
   目标：验证STEER的视线和点头是否可被剧情状态机稳定调用。组件：STEER示例、FLAME、简单Python状态机。难点：checkpoint交付和第三方许可证。成功判据：同一音频下三组控制产生可区分轨迹，且嘴部同步基本保持。

3. **离散人—物状态协议实验**  
   目标：为“无接触—接近—抓取—持有—释放”定义引擎与生成模型之间的JSON契约。组件：状态机、占位渲染器、WebSocket。难点：非法转换和超时回滚。成功判据：所有动作可审计、可重放，生成失败时一个状态周期内回退传统动画。

4. **接触规划最小代理实验**  
   目标：先用仿真触觉或规则模型代替FeelWorld，验证“候选动作→rollout→CEM选择→安全执行”管线。组件：MuJoCo/Isaac、CEM、接触与滑移评分。难点：模型预测与真实状态版本对齐。成功判据：相较随机候选提高插接或抓取成功率，且所有执行动作通过硬安全约束。
