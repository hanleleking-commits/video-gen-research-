# 数字人、世界模型与互动作品研究日报：2026-11-01

检索窗口：2026-10-26 至 2026-11-01。  
信息截点：2026-11-01（Asia/Shanghai）。已与 10 月 26—31 日日报去重；论文日期按 arXiv 原始提交记录核验。11 月 1 日为周日，截点前未发现新的 arXiv 发布批次。

## 1. 本日摘要

本周期最明确的趋势不是视频画质继续提高，而是世界模型开始形成“权威状态—控制编译—生成渲染—持久记忆—自动验收”的运行时架构。

Fight World Model 是最清晰的例子：代码引擎先执行技能、命中和血量规则，视频模型只渲染结果。这比让模型从提示词猜测游戏规则更可控，也更接近可测试的软件系统。

Hy-Nomas 则提供了本周期最完整的开放开发栈：多轮文本与相机控制、权重、LoRA、Diffusers、SGLang 服务和 WebSocket 流式接口均已出现。不过“可流式调用”不等于实时可玩，其端到端延迟、并发和单位会话成本仍未披露。

长时一致性正在被拆成多个独立工程问题：L3G-World用潜在3D Gaussian保存空间记忆，FutureWorld在生成前预测下一状态，GameVerse补充分钟级训练数据，WorldProbe则用主动探索agent测量远距离重访和对象状态漂移。没有一个系统同时解决记忆、物理、实时性与可编辑性。

数字人方向的新增明显弱于世界模型。HairDeck把单图发型变成带spring-bone的GLB/VRM资产，ReferStream支持在持续生成过程中加入新角色；但本周期没有新的高质量实时talking head、口型、情绪、视线、全双工turn-taking或规模客户部署证据。

Coding × 互动作品的角色正在变化：代码不再只是“调用生成API”，而是维护世界真相、规则、资产引用、上下文、回滚点和质量门禁；生成模型负责外观、动作候选和不可穷举的内容变化。

本日相对10月31日没有实质性新发布。复核结果显示：L3G-World仓库仍未发布核心代码与权重，WorldProbe声明的GitHub入口仍返回404，ReferStream仓库仍只有项目页和演示资产。因此成熟度不能上调。

产业侧仍以研究原型和开源组件为主，未发现新的客户试点、正式产品或规模部署，也没有新增生产级P95延迟、SLA、并发和成本数据。

## 3. 最值得关注的10个进展

### 1. Fight World Model：把规则执行与画面生成分开

- **类型 / 日期 / 主线：**论文、模型、demo、dataset；2026-10-29；世界模型、Coding × 互动作品。
- **官方链接：**[论文](https://arxiv.org/abs/2610.40607)、[项目页](https://fight-world-model.github.io/)。
- **相对上期：**无新代码或实时服务发布。
- **核心贡献：**可执行引擎维护角色、技能、命中和血量；确定性编译器将结果转为按身份、空间和时间对齐的interaction proxy。修改伤害倍率、免疫、吸血和多阶段技能时无需重训渲染器。
- **Coding接口：**规则配置、状态更新、事件流、身份绑定和代理编译器。
- **场景：**生成式格斗、IP角色互动、直播对战、可编辑互动电影。
- **成熟度 / 证据：**研究demo；论文实测。52种技能、187种角色外观、15个场景，无公开生产延迟。
- **重要性 / 阅读：**高 / 必读。

### 2. Hy-Nomas：开放的多轮互动世界运行时

- **类型 / 日期 / 主线：**模型、GitHub、权重、benchmark、服务接口；2026-10-27；世界模型、Coding。
- **官方链接：**[论文](https://arxiv.org/abs/2610.36729)、[代码](https://github.com/Tencent-Hunyuan/Hy-Nomas)、[模型](https://huggingface.co/tencent/Hy-Nomas)。
- **相对上期：**无新的正式版本；SGLang支持仍要求nightly构建。
- **核心贡献：**8B视频扩散模型支持多轮自然语言和相机控制；把长期场景描述与仅在指定时间窗生效的动作分开，减少旧动作重复执行。
- **Coding接口：**Diffusers、LoRA、结构化JSON、SGLang `/v1/videos`、WebSocket `/v1/realtime_video/generate`、Web demo。官方仓库称可在单RTX 4090低显存模式运行。
- **场景：**浏览器探索世界、互动叙事、品牌空间、机器人视觉预演。
- **成熟度 / 证据：**已开源研究平台；作者实测。尚无P95延迟、并发或SLA。
- **重要性 / 阅读：**高 / 必读。

### 3. L3G-World：潜在3D Gaussian长期记忆

- **类型 / 日期 / 主线：**论文、仓库、demo；2026-10-29；世界模型、运行时。
- **官方链接：**[论文](https://arxiv.org/abs/2610.40614)、[仓库](https://github.com/cvlab-kaist/L3G-World)。
- **相对上期：**截至本日，L3G-Mem、L3G-Gen、推理代码和快速模型仍全部处于release plan，未实际发布。
- **核心贡献：**每个Gaussian保存VAE latent，新区域新增primitive、旧区域持续细化；记忆随探索空间而不是视频时长增长。
- **Coding接口：**图像、文本、相机轨迹和会话记忆；未来可作为世界服务的持久状态。
- **场景：**持续漫游、虚拟摄影、空间计算、生成式关卡视觉层。
- **成熟度 / 证据：**论文demo、官方声称9 FPS；尚不可独立复现。
- **重要性 / 阅读：**高 / 必读。

### 4. WorldProbe：agent主动探索长时失效点

- **类型 / 日期 / 主线：**benchmark、agent harness；2026-10-29；世界模型评测。
- **官方链接：**[论文](https://arxiv.org/abs/2610.39721)、[声明的代码入口](https://github.com/Untitled-W/WorldProbe)。
- **相对上期：**GitHub仍返回404，开放状态没有改善。
- **核心贡献：**多模态agent在线选择相机动作；164个测试、10个模型、1,600余条rollout、约800分钟视频，最长测试180秒。
- **Coding接口：**任务agent、模型适配器、相机控制循环和长时指标服务，适合接入模型升级CI。
- **结论：**局部画质改善快于长期记忆、远距离重访和世界演化。
- **成熟度 / 证据：**论文实测；代码待核验。
- **重要性 / 阅读：**高 / 必读。

### 5. Gym-Anything for Robotics：coding agent生成并审计物理仿真

- **类型 / 日期 / 主线：**论文、代码、benchmark、RL环境；2026-10-29；Coding、机器人、仿真。
- **官方链接：**[论文](https://arxiv.org/abs/2610.40565)、[项目与开发入口](https://gym-anything.github.io/robotics/)。
- **相对上期：**无新版本。
- **核心贡献：**创建agent编写场景、物理、任务和奖励，多个audit agent检查可解性、奖励正确性并尝试破坏环境。RoboWorld含25个仿真、25个测试和175个训练环境。
- **Coding接口：**仿真源码、状态读取、自动测试、审计循环、代码策略和训练轨迹。
- **场景：**机器人训练、工业数字孪生、危险工艺演练、合成示范。
- **成熟度 / 证据：**已开放研究benchmark；作者报告最强受测模型在25个测试任务上成功率为0，平均reward仅0.06。
- **重要性 / 阅读：**高 / 必读。

### 6. HairDeck：从单图生成可动画发型资产

- **类型 / 日期 / 主线：**论文、GitHub、权重、资产工具；2026-10-29；数字人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.40599)、[Apache-2.0代码](https://github.com/hyz317/HairDeck)、[模型](https://huggingface.co/hyz317/HairDeck)。
- **相对上期：**无新版本；代码、训练和评测入口保持可用。
- **核心贡献：**将发型建模为无序hair-card集合，同时生成spring-bone chain；作者报告相对CHARM降低44% Chamfer distance，并提升33倍速度。
- **Coding接口：**CLI、Gradio demo、JSON几何与骨链、GLB、VRM和Blender 4.2工作流。
- **场景：**游戏角色、VTuber、社交avatar、UGC换装。
- **成熟度 / 证据：**已开源；论文实测。主要面向动漫/VRoid分布，不代表写实毛发。
- **重要性 / 阅读：**高 / 必读。

### 7. ReferStream：持续生成过程中注入新角色

- **类型 / 日期 / 主线：**论文、benchmark、demo；2026-10-27；数字人、互动叙事。
- **官方链接：**[论文](https://arxiv.org/abs/2610.37566)、[仓库](https://github.com/Xushuolin/ReferStream)。
- **相对上期：**仓库仍明确注明“不含推理代码”，仅托管网页和演示资产。
- **核心贡献：**把新参考图嵌入当前场景latent，并临时覆盖生成缓存；完成注入后恢复旧缓存，同时保留新角色的生成历史，不修改已输出帧。
- **Coding接口：**可抽象成`inject_reference(image, region, instruction, timestamp)`事件，但当前没有实际SDK。
- **场景：**互动电影临时加入演员、直播嘉宾、品牌角色入场。
- **成熟度 / 证据：**录制demo、论文实测；帧率、注入延迟和显存未披露。
- **重要性 / 阅读：**中高 / 必读。

### 8. GameVerse：分钟级互动世界训练数据

- **类型 / 日期 / 主线：**dataset、论文；v1 2026-10-27，v2 2026-10-29；世界模型基础设施。
- **官方链接：**[论文与版本记录](https://arxiv.org/abs/2610.37257)。
- **相对上期：**确认v2发布日期；未发现新的数据下载与许可证入口。
- **核心贡献：**69.7K片段、1,655小时、约3.496亿帧，其中1,358小时为连续两分钟序列；提供跨分钟相机轨迹和按事件边界组织的caption。
- **Coding接口：**适合训练action-conditioned模型，并用相机轨迹和事件标注构造长期回归测试。
- **场景：**生成式游戏、相机控制世界模型、长时互动视频。
- **成熟度 / 证据：**NeurIPS 2026论文；数据可获取性与商业许可待核验。
- **重要性 / 阅读：**高 / 必读。

### 9. FutureWorld：生成前先预测未来状态

- **类型 / 日期 / 主线：**论文、插件式模块、demo；2026-10-29；世界模型。
- **官方链接：**[论文](https://arxiv.org/abs/2610.39619)、[项目页](https://GuangYuanKK.github.io/futureworld)。
- **相对上期：**未发现公开推理代码。
- **核心贡献：**Causal Next-Chunk Predictor根据当前latent和下一动作先预测未来场景状态，再调制下一视频块，以减少错误历史被循环强化。
- **Coding接口：**可插入已有视频生成器之前，并由外部状态机提供动作与提交/回滚策略。
- **场景：**长时探索、分支互动电影、训练模拟。
- **成熟度 / 证据：**论文实测，已接入四个生成器、三个benchmark；额外延迟未披露。
- **重要性 / 阅读：**高 / 必读。

### 10. WorldFlow：从画面预测推进到可查询3D运动

- **类型 / 日期 / 主线：**论文、benchmark、机器人实验；2026-10-29；世界模型、机器人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.39278)、[项目页](https://worldflow-rbs.github.io/)。
- **相对上期：**无新SDK或权重发布。
- **核心贡献：**视频与连续三维位移token联合去噪；输入图像、语言和3D query point，输出可供控制器消费的运动轨迹。
- **Coding接口：**3D query/trajectory比纯RGB更容易接规划器、碰撞检测和安全控制器。
- **场景：**机器人预测、可交互仿真、动态对象预演。
- **成熟度 / 证据：**论文原型；外部比较受训练数据重合影响，需独立复测。
- **重要性 / 阅读：**中高 / 可读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**本周期没有新的高质量语音驱动头像、实时口型或全身共语动作模型。ReferStream的价值是运行中改变“演员表”，而不是改善单个角色表演。
- **3D/4D表示：**HairDeck证明结构化、引擎原生的hair card和spring bone比生成不可编辑的融合mesh更有生产价值。
- **实时交互：**ReferStream是因果流式框架，但没有端到端时延；HairDeck生成的是离线资产。两者均不能称为实时对话数字人。
- **音视频与情感：**本周期暂无情绪、视线、倾听动作、可打断TTS或跨语言表演的高质量新增。
- **工程部署：**HairDeck最接近可进入产品管线；输出可直接交给Blender、VRM和Unity类运行时，但仍需检查穿模、纹理和骨链稳定性。
- **安全与身份治理：**没有新增授权凭证、水印、肖像撤回或溯源闭环。ReferStream的动态人物注入反而提高了实时授权校验需求。

## 5. 世界模型进展

- **架构与训练：**分钟级数据、未来状态预测、潜在3D记忆和视频—3D运动联合建模同步升温。
- **可控/可玩生成：**Fight World Model显示，复杂规则应由代码执行后编译为控制信号；Hy-Nomas则覆盖开放语义指令和连续相机控制。
- **长时与物理一致性：**L3G解决空间记忆扩张，FutureWorld抑制错误递归，GameVerse补长序列数据，WorldProbe负责主动验收；当前仍是分散组件。
- **空间表示：**3D Gaussian latent、深度、mask、flow、3D trajectory和interaction proxy正在成为模型与引擎之间的中间协议。
- **机器人/游戏/仿真：**Gym-Anything把“创建世界”变成软件工程任务；WorldFlow把生成未来转成可供规划器查询的运动。
- **实时部署与评测：**L3G的9 FPS尚不可复现；Hy-Nomas的WebSocket表示流式协议可用，不证明交互延迟已达游戏要求。

## 6. Coding × 新型互动作品

### 链路一：规则可编辑的生成式格斗

**玩家输入 → 规则引擎执行 → interaction proxy → 视频模型渲染 → 客户端播放**

代码负责命中、伤害、血量、技能窗口和胜负；模型负责角色外观、特效和画面。已有论文demo，尚无实时网络服务。

### 链路二：持续运行的开放世界服务

**文本/相机输入 → Prompt Enhancer → 结构化动作时间窗 → Hy-Nomas → SGLang/WebSocket → 浏览器**

代码维护会话、权限、存档和成本预算；模型生成视觉观察。已有可运行服务接口，生产并发和P95延迟未验证。

### 链路三：带持久空间记忆的生成世界

**相机移动 → L3G记忆查询 → 视频块生成 → 新区域写入/旧区域更新 → 下一轮**

代码负责记忆生命周期和存档，模型负责外观补全。9 FPS仅有作者证据，核心代码尚未发布。

### 链路四：可恢复的互动电影

**剧情状态机 → 下一动作 → FutureWorld状态预测 → 视频生成 → 规则/视觉验收 → 提交或回滚**

代码保留分支、角色状态和回滚点；模型生成镜头。本系统整合属于本报告推断，FutureWorld模块本身已有论文证据。

### 链路五：动态加入角色的直播或互动叙事

**事件总线 → 参考图授权检查 → ReferStream临时缓存注入 → 新角色入场 → RTC播放**

模型负责视觉融合，代码负责触发时机、身份授权、审核和音频同步。现阶段只有录制demo，尚无SDK。

### 链路六：coding agent自动生产机器人训练世界

**任务规范 → 创建agent编写仿真 → audit agent破坏测试 → RL环境 → 策略训练**

代码本身就是世界，物理引擎提供权威动力学，模型负责创建和修复程序。Gym-Anything已开放环境，但测试成功率说明自动化质量仍不稳定。

## 9. 系统架构与技术趋势判断

明显升温的是混合运行时：权威状态由代码或物理引擎维护，生成模型提供画面与候选未来，中间通过interaction proxy、深度、3D轨迹、Gaussian latent或结构化动作连接。

第二个趋势是“上下文工程视频化”。缓存选择、空间记忆、未来状态预测、错误历史隔离和回滚正在成为独立于基础模型的运行时层。

第三个趋势是评测从精选视频转向持续执行：是否能重访、对象是否仍存在、规则是否执行、仿真任务是否可完成，比单段FVD或主观画质更接近工业价值。

数字人则出现明显断层：结构化资产生成进步较快，但语音驱动表演、全双工对话、RTC、审核、身份授权和生产可观测性没有同步提升。

尚未解决的关键问题包括：分钟级权威状态、多人同步、低于100毫秒的交互闭环、可编辑几何、稳定的角色身份、故障恢复、输出审核和单位会话成本。

应降级看待的说法包括：把SGLang“realtime session”直接解释为实时帧率；在代码未发布前接受L3G的9 FPS；把ReferStream项目页称为开源代码；把agent-harness架构讨论当成产品性能证明。

## 10. 论文精读候选

1. [Fight World Model](https://arxiv.org/abs/2610.40607)：重点读interaction proxy、identity binding、规则干预与状态一致性实验。差异在于先执行规则再渲染；风险是封闭格斗域和固定交互模式。
2. [Hy-Nomas](https://arxiv.org/abs/2610.36729)：重点读action-aware causal attention、Prompt Enhancer、模型历史训练和空间记忆评测。复现风险是8B模型训练成本和长时服务吞吐。
3. [L3G-World](https://arxiv.org/abs/2610.40614)：重点读latent Gaussian字段、memory updater和9 FPS计时口径。风险是代码未发布、权重许可证混合。
4. [WorldProbe](https://arxiv.org/abs/2610.39721)：重点读agent policy、四类probing和长时退化指标。风险是部分评价依赖模型、仓库不可访问。
5. [Gym-Anything](https://arxiv.org/abs/2610.40565)：重点读creation-audit loop、仿真质量标准和RoboWorld任务设计。差异是把仿真创建定义为软件工程；风险是环境正确性仍需大量人工验证。

## 11. 下周跟踪与可行动建议

持续跟踪：

1. L3G-World是否发布推理代码、快速模型、硬件配置和端到端9 FPS复现说明。
2. WorldProbe仓库是否恢复，以及是否支持Hy-Nomas、L3G-World等最新模型。
3. Hy-Nomas稳定版SGLang支持、首帧延迟、持续帧率、显存和多会话并发。
4. Fight World Model是否开放规则schema、代理编译器、数据和实时demo。
5. ReferStream是否发布推理代码，以及角色注入延迟和参考图授权机制。
6. GameVerse数据下载、相机轨迹格式、事件caption质量和商业许可证。
7. HairDeck导出资产在Unity、Godot、Web/Three.js和不同VRM版本中的兼容性。
8. Gym-Anything环境能否通过独立人工物理审计并产生可迁移的真机策略。

本周可做的小实验：

- **实验一：权威状态与生成渲染解耦。**用简单格斗状态机输出角色位置、命中、血量和技能窗口，再编译为JSON/遮罩控制视频生成。难点是身份与时间对齐；成功判据是修改伤害倍率后画面和UI状态一致。
- **实验二：HairDeck资产落地。**选三张不同风格角色图生成GLB/VRM并导入Unity或Web VRM viewer。难点是穿模和spring-bone参数；成功判据是自动导入、转头无明显穿插、连续运行60秒无骨链发散。
- **实验三：世界模型长时CI。**设计“离开房间—探索—返回”脚本，记录对象身份、布局、文本和几何变化。成功判据是生成可比较的版本退化曲线，而不是只保存精选视频。
- **实验四：Hy-Nomas服务测量。**用SGLang WebSocket连续提交10个动作段，测首帧、段间停顿、显存峰值和历史动作重复率。成功判据是获得完整P50/P95、失败恢复和单会话成本记录。
