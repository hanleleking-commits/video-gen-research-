# 数字人、世界模型与互动作品研究日报：2026-11-23

检索窗口：2026-11-17 至 2026-11-23（截至北京时间 09:00）。已对照 11 月 17–22 日日报去重；发布日期以官方页面、论文提交记录、软件包记录和状态页事件时间为准。

## 1. 本日摘要

截至截稿时间，本日没有新的高质量论文、模型、权重或开发者 API 发布；可确认的实质增量只有两项，因此不以旧闻补足 8–12 条。

第一项是 Tesla 相关的实时生成视频演示。Elon Musk 称该演示不使用游戏引擎、仅运行在半个 AI4 TRIP 加速器上；Tim Sweeney进一步将其称为世界模型超越传统引擎的实际用例。不过，公开材料没有模型名称、分辨率、帧率、输入方式、运行位置或独立测试，现阶段只能作为重要的端侧效率信号，不能视作已验证产品能力。

第二项来自 bitHuman 的真实生产状态：Expression 2虽能在手机、Mac、Linux和WebGPU端实时渲染，但部分客户头像的设备模型构建和下载仍依赖人工处理，自动流水线修复再次延期。这比单纯模型指标更直接地暴露了数字人产品化中的资产编译、跨端打包、发布一致性和故障恢复问题。

过去一周的主线判断没有改变：数字人正从离线生成转向流式或端侧运行；世界模型正从短视频生成转向可调用、可保存状态和可执行动作；Coding则逐渐承担权威状态、规则、资产构建、降级、审计与恢复。

产业成熟度仍呈明显分层：AURA、WM^MLLM和WAM-Policy已有可复现研究资源，Genie 4已有开发者API，bitHuman已有跨端SDK；但真实生产环境中的P95延迟、并发成本、长期稳定性和自动化交付仍缺系统披露。

- **官方链接：**[状态页](https://status.bithuman.ai/)、[Expression 2文档](https://docs.bithuman.ai/models/expression-2)、[端侧SDK](https://docs.bithuman.ai/start/on-device-avatar-sdk)。

- **证据级别：**官方产品文档＋官方生产状态记录。
- **重要性／阅读：**高／必读。

该事件说明数字人交付单位已不再只是一个通用checkpoint，而是“身份资产＋共享运行时＋平台专用构建产物＋发布元数据”。任何一个环节缺失，云端可运行的角色也可能无法下发至终端。

## 5. 世界模型进展

- **架构与训练：**本日无新论文。窗口内仍可观察到显式状态、动作敏感训练、反事实预测和少步蒸馏四条路线并行。
- **可控/可玩生成：**Tesla材料只证明发布者声称“实时生成”，没有证明支持键鼠、文本事件或动作条件，因此不能与[Genie 4 API](https://blog.google/innovation-and-ai/technology/developers-tools/genie-4-in-gemini-api/)的公开交互接口等量齐观。
- **长时与物理一致性：**Tesla演示未披露连续时长和状态保持。窗口内证据更强的仍是[WM^MLLM](https://arxiv.org/abs/2611.24193)的外置全景状态与revision机制。
- **空间表示：**暂无新增。无法确认Tesla模型是否使用3D、occupancy、BEV或纯视频latent。
- **机器人/游戏/仿真：**若AI4演示来自车载感知或FSD体系，其端侧效率可能对机器人视觉仿真有意义，但当前没有足够技术材料建立这一因果关系。
- **实时部署与评测：**端侧实时生成值得关注，然而真正可比较的披露至少应包含FPS、分辨率、事件响应延迟、功耗、模型大小、rollout长度和动作一致性。

## 6. Coding × 新型互动作品

### 链路一：端侧生成式车载界面

**摄像头/地图状态 → 权威驾驶状态与安全规则 → 生成式视觉重绘 → 车载显示**

代码必须保存导航、车辆和安全状态；生成模型只能负责视觉表达。Tesla演示提供效率信号，但没有证据证明其对应这一完整链路。当前属于官方声称＋本报告推断。

### 链路二：可降级的端侧数字员工

**角色创建API → 身份模型构建 → 平台产物发布 → Swift/Android/WebGPU运行时 → 语音agent**

模型负责嘴型、头部和表情生成；代码负责资产状态、版本、下载、缓存和失败重试。当端侧产物缺失时，运行时应回落到云渲染、静态头像或纯语音。bitHuman已有正式产品与真实故障证据。

### 链路三：云端创建、终端持续运行的品牌角色

**单张品牌角色图 → 身份构建服务 → CDN/模型仓库 → WebGPU或移动SDK → 活动事件系统**

传统前端负责交互、活动规则和埋点；数字人模型负责表演。过去难点是每次交互都需云端视频流，现在可以把角色包下载至终端，但需要解决50–200 MB级资产分发、缓存失效和授权撤销。资产大小以[bitHuman端侧文档](https://docs.bithuman.ai/deploy/on-device)为准。

### 链路四：引擎与世界模型的混合运行时

**代码状态机/物理引擎 → 可验证场景代理 → 世界模型重渲染 → 用户输入 → 状态回写**

Sweeney提出的产业判断是世界模型与引擎将趋向混合：工程数据结构擅长大规模、确定性仿真，生成模型擅长场景理解和视觉表现。该方向与[Coda-DaVinci](https://coda-davinci.github.io/)的“代码建模结构、视频模型合成细节”一致，但Tesla尚未公开对应实现。

### 链路五：数字人资产的CI/CD

**头像创建 → 平台构建矩阵 → 自动下载测试 → 画面/口型回归 → 签名发布 → 状态页与回滚**

bitHuman事件表明，数字人团队需要像维护移动应用二进制一样维护身份模型。成功标准不仅是模型能生成，还包括每个身份、平台和版本都能构建、下载、初始化并持续运行。

## 9. 系统架构与技术趋势判断

本日新增证据强化了两项判断：

1. **端侧推理正在升温，但资产供应链比单次推理更难。** 模型跑得动只是第一步；身份构建、平台编译、签名、下载、缓存和回滚决定产品是否真正可用。
2. **世界模型与传统引擎更可能融合，而非简单替代。** 规则、库存、权限、多人同步和安全状态适合显式代码；视觉重绘、细节生成和场景理解适合生成模型。

逐渐成形的系统架构为：

**用户/传感器事件 → 权威状态与权限层 → 规则或物理引擎 → 世界模型/数字人表现层 → 输出检查 → 端侧运行时 → 日志、回放、回滚与降级。**

仍未解决的关键问题包括：

- 世界模型端侧生成的可复现性能与功耗；
- 复杂动作对生成状态的可靠影响；
- 数分钟以上角色、对象和空间的一致性；
- 数字人模型包的自动化跨端构建；
- 身份授权撤销和已下载模型治理；
- P95延迟、并发成本、失败率和恢复时间；
- 模型更新与旧资产、旧SDK的兼容矩阵。

需要降级处理的宣传包括：只给出“实时”而没有帧率、延迟与输入协议；只展示视频但没有动作控制；把单个硬件演示直接称为世界模型正式部署；以及以平均吞吐替代生产端到端响应时间。

## 10. 论文精读候选

1. **[AURA](https://arxiv.org/abs/2611.26540)**  
   重点读因果注意力、rolling KV cache、四步蒸馏和流式延迟定义。与离线talking head的区别是无需未来音频；风险是H100依赖和非商业权重许可。

2. **[WM^MLLM](https://arxiv.org/abs/2611.24193)**  
   重点读operation routing、候选检查、revision和局部编辑边界。核心差异是将一致性变成状态系统属性；风险是全景图仍不是完整三维世界。

3. **[Counterfactual World Models](https://arxiv.org/abs/2611.24778)**  
   重点读反事实不可识别性、一阶校正和不连续动力学失效条件。适合机器人事故归因；代码开放度和真机外推仍有风险。

4. **[AFFECT](https://arxiv.org/abs/2611.25980)**  
   重点读动作扰动、effect matching loss及世界模型与真机成功率相关性。它直接检查模型是否响应动作，而非只看画面合理性。

5. **[WAM-Policy](https://arxiv.org/abs/2611.24011)**  
   重点读跨机器人形态适配、on-policy distillation和动作块时序。复现风险在于仿真资产、真机控制器及安全配置。

## 11. 下周跟踪与可行动建议

### 继续跟踪

1. Tesla是否公开AI4演示的模型、FPS、分辨率、功耗和动作接口。
2. 该演示究竟是视觉重绘器、action-conditioned生成器，还是完整世界模型。
3. bitHuman能否按计划恢复Expression 2设备模型的自动构建。

8. Coda-DaVinci是否开放完整coding-agent harness和视频后端适配层。

### 本周可动手实验

**实验一：数字人资产CI矩阵**

- **目标：**验证“头像已创建”到“各端可运行”的完整交付链。
- **组件：**bitHuman测试角色、iOS/Android/WebGPU客户端、自动下载与启动脚本。
- **预计难点：**区分身份构建、设备包生成、CDN发布和客户端缓存错误。
- **成功判据：**连续创建10个角色，所有目标平台均能在规定时间内下载并输出首帧；失败可自动降级到云端。

**实验二：端侧实时生成声明的最低评测协议**

- **目标：**建立评估Tesla类演示所需的统一指标。
- **组件：**任一实时视频生成模型、帧时间记录、功耗计、输入事件日志。
- **预计难点：**吞吐、首帧时间和事件响应延迟容易被混为一谈。
- **成功判据：**同时报告分辨率、平均/P95 FPS、首帧、事件到画面延迟、功耗、连续运行时长和状态漂移。

**实验三：世界模型—规则引擎混合原型**

- **目标：**验证生成模型只负责表现、代码维护权威状态的架构。
- **组件：**简单库存/任务状态机、Three.js或Godot、视频或图像生成后端。
- **预计难点：**把视觉变化重新对齐到确定性状态。
- **成功判据：**连续20次交互中库存与任务状态零错误；生成失败不污染权威状态，并可回滚重试。

**实验四：端侧身份资产撤销测试**

- **目标：**验证已下载数字人模型在授权撤销后的治理路径。
- **组件：**签名模型清单、版本服务、客户端缓存和失效策略。
- **预计难点：**离线设备无法即时接收撤销信息。
- **成功判据：**在线客户端能阻止已撤销资产启动；离线资产在下一次联网后完成封禁、审计和用户提示。
