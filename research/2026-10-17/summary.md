# 数字人、世界模型与互动作品研究日报：2026-10-17

检索窗口：2026-10-11 至 2026-10-17。  
信息截点：2026-10-17 09:02（Asia/Shanghai）。论文日期以 arXiv 提交记录为准；已与 10 月 12—16 日日报去重。

## 1. 本日摘要

本周期最明确的主线，是世界模型开始把“记住世界”拆成可编程状态、空间索引和长时视觉监督三类工程问题：StateCraft 用显式、可编辑的抽象状态保存不可见对象变化；Velox 用几何索引选择真正相关的历史 KV；LongForcing 则直接监督模型在自身长时 rollout 中产生的漂移。

这些工作共同支持一种更可靠的互动架构：代码和传统引擎持有权威状态、规则与时钟，生成模型负责渲染当前观察，而不是要求视频 latent 独自承担全部世界事实。

Coding 与世界模型的连接也从“代码调用生成 API”扩展到“代码作为可验证表示”。PhySimCode 要求模型从视频恢复物理参数并写出可运行模拟器，揭示当前模型会描述物理规律，却很难从画面准确反演规律与参数。

可控视频方面，Temporal Specification Guidance 首次把时序逻辑转成采样期可执行目标，使“先出现、持续多久、何时消失”等要求能够被代码化；这比自然语言 prompt 更适合作为互动剧情和工业流程的约束接口。

工业信号主要来自机器人和医疗仿真：PINT 用共享 Predictive Intent 协调语义、未来视频和动作专家；SonoWorld 则把 6-DoF 探头动作映射为临床超声未来画面，用于机器人策略评估，但两者仍是研究验证，不能视为医疗或机器人生产部署。

数字人方向本周期没有新的高质量直接模型、SDK或产品发布。最相关增量是 AVC-Reward：它可以把人物语音、动作事件和画面之间的同步质量变成可调用的 reward 服务，但它不是数字人生成器。

端侧部署方面，HeteroVDiff 在 Galaxy S25 上让 NPU 与 GPU 共享 INT8 权重并流水执行，证明视频生成能够利用移动 SoC 异构算力；不过论文只披露相对吞吐提升，未给出完整单视频延迟和能耗。

证据整体仍以论文作者实测为主。StateCraft、PINT、LongForcing、Velox、SonoWorld 尚缺完整代码或独立复现；目前最容易实际验证的是 PhySimCode、CausalCascade 和 AVC-Reward。

## 3. 最值得关注的 10 个进展

### 1. StateCraft：显式状态负责事实，视频模型负责观察

- **类型 / 日期 / 主线：**论文、benchmark、demo；2026-10-14；世界模型、Coding × 互动作品。
- **官方链接：**[论文](https://arxiv.org/abs/2610.19795)、[项目页](https://insait-institute.github.io/StateCraft/)、[GitHub](https://github.com/insait-institute/StateCraft)。
- **相对上期的新变化：**首次收录；与上期 DAO/JING 的“权威状态＋生成观察”方向一致，但给出了抽象状态编辑、事件门控和最长 512 次动作回访实验。
- **核心贡献：**语言模型更新实体与视图组成的抽象状态图，视频扩散模型据此渲染当前观察。项目页报告回访一致性约 0.9 SSIM，直接编辑状态后视频有 81% 跟随率；事件门控可跳过 40.8% 的语言模型调用，代价为 0.57 dB PSNR。
- **Coding 接口：**抽象状态可以直接增删、重命名或修改不可见实体；适合映射为 JSON/图数据库、状态机和事件总线。
- **场景：**持久桌面、生成式 UI、互动叙事、包含隐藏状态的 NPC 世界。
- **成熟度 / 证据：**论文 demo；GitHub目前只有“Code coming soon”。作者实测，无第三方验证。
- **重要性 / 阅读：**高 / 必读。

### 2. Velox：用空间记忆限制长世界的注意力成本

- **类型 / 日期 / 主线：**论文、运行时方法；2026-10-15；世界模型、推理基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2610.22311)、[项目页](https://velox-world.com/velox/)。
- **相对上期：**首次收录；与上期 RAR 的物理时间控制互补，本项解决 rollout 越长、历史 KV 越昂贵的问题。
- **核心贡献：**把历史 token block 映射为带深度范围的相机视锥 slab，再以空间重叠和模型原生注意力共同选择历史块。固定块粒度能直接对应 FlashAttention tile。
- **关键结果：**作者在单张 H200、LingBot-Fast-Cam 上报告第 48 个 chunk 的注意力从 34.2 ms 降至 7.8 ms，整段去噪从 7.19 秒降至 2.96 秒；WBench API-free 平均分与 dense 版本相差 0.15 分。
- **Coding 接口：**适合作为 world-model server 的历史检索层，由相机姿态、深度和负载预算共同配置路由。
- **场景：**长时第一人称探索、生成式游戏、机器人视觉仿真。
- **成熟度 / 证据：**论文和对比 demo；代码、稀疏 kernel 与结果集仍标记为 planned。
- **重要性 / 阅读：**高 / 必读。

### 3. PhySimCode：从物理视频恢复可运行模拟器

- **类型 / 日期 / 主线：**benchmark、dataset、GitHub；2026-10-11；Coding × 世界模型。
- **官方链接：**[论文](https://arxiv.org/abs/2610.15722)、[代码](https://github.com/SourajaKundu/PhySimCode)、[MIT 数据集](https://huggingface.co/datasets/SourajaKundu123/PhySimCode)。
- **相对上期：**首次收录；将“视频理解物理”推进为可编译、可运行、可重新渲染的代码评测。
- **核心贡献：**完整语料含 160,614 个程序生成样本和 162 类物理现象；公开评测集含 2,430 段 SciPy/PyBullet 视频。输出必须包含物理规律、参数和 Python 程序，再按可运行性与重渲染视频相似度评分。
- **关键发现：**作者报告十个模型能复述物理规律，却很难从视频反演参数；最佳系统在 ±20% 容差下仅恢复 7.7% 的真实参数。
- **Coding 接口：**提供 JSONL 协议、可恢复运行的 evaluator、代码执行、DINOv2/VideoCLIP评分和三模型 judge。
- **场景：**数字孪生初始化、教育仿真、机器人场景重建、物理游戏原型。
- **成熟度 / 证据：**已开源评测代码和数据；不是生产级 video-to-simulator 工具。
- **重要性 / 阅读：**高 / 必读。

### 4. LongForcing：把监督范围扩展到模型自己的长时 rollout

- **类型 / 日期 / 主线：**论文、蒸馏方法；2026-10-13；世界模型、长视频基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2610.18289)、[GitHub占位仓库](https://github.com/Fantasy-AMAP/LongForcing)。
- **相对上期：**首次收录；不同于上期通过状态写回或重锚抑制漂移，本项直接解决训练监督窗口短于实际运行时间的问题。
- **核心贡献：**在分布匹配阶段使用长时双向教师监督学生自身的 extended rollout，不改变学生架构和推理成本。
- **关键结果：**作者报告 WorldRoamBench 60 秒动作分数在第一人称消融中提高 23.9 分，并展示最长 24 小时压力测试；“能生成 24 小时”不等于 24 小时状态和物理均正确。
- **Coding 接口：**可作为流式世界模型训练 recipe，配合状态检查点和自动长时回归测试。
- **成熟度 / 证据：**论文实测；GitHub仅 README、无许可证和实质代码。
- **重要性 / 阅读：**高 / 必读。

### 5. Temporal Specification Guidance：用时序逻辑编程视频事件

- **类型 / 日期 / 主线：**论文、控制方法；2026-10-14；Coding × 生成视频。
- **官方链接：**[论文](https://arxiv.org/abs/2610.20822)。
- **相对上期：**首次收录；将上期依赖 prompt skill 或脚本规划的时序控制升级为形式化、可评分的采样目标。
- **核心贡献：**把 Metric Temporal Logic 约束转为可微满足度，通过视频—文本注意力产生额外去噪方向，无需外部分类器或反向传播整个视频 Transformer。
- **关键结果：**作者在五个模型、220 个 prompt、11 类时序约束上报告相对 CFG 提高 9.5—20 个百分点。
- **Coding 接口：**程序可生成“事件 A 必须先于 B”“对象 C 在区间内持续存在”等规范，并将满足度用于生成、重试或验收。
- **场景：**互动电影、广告分镜、培训流程、带明确事件顺序的游戏过场。
- **成熟度 / 证据：**论文原型；未核验到公开代码。
- **重要性 / 阅读：**高 / 必读。

### 6. CausalCascade：画面合理不代表因果链正确

- **类型 / 日期 / 主线：**benchmark、dataset、GitHub；2026-10-11；世界模型评测。
- **官方链接：**[论文](https://arxiv.org/abs/2610.15562)、[MIT 代码](https://github.com/SJTU-DeepDeltaLab/CausalCascade)。
- **相对上期：**首次收录；比单帧物理合理性评测更强调触发事件如何传播至最终结果。
- **核心贡献：**50 个 Blender 场景、结构化事件图、诊断 VQA、三级未来事件描述和 2,832 个删除、移动、缩放或质量变化的反事实变体。
- **核心结论：**当前 I2V 模型较容易把运动放在正确区域，却常不能生成正确的时空演化；更详细的提示能提高事件召回，但没有解决物理实现。
- **Coding 接口：**支持自定义模型 adapter、运动评测、反事实响应和诊断 VQA，可直接接入生成模型 CI。
- **场景：**游戏物理回归、机器人数据生成验收、广告和影视特效自动质检。
- **成熟度 / 证据：**代码 MIT、数据 CC BY 4.0，已具备最小复现路径。
- **重要性 / 阅读：**高 / 必读。

### 7. PINT：以共享 Predictive Intent 协调语言、未来视频与动作

- **类型 / 日期 / 主线：**论文、机器人实机实验；2026-10-12；世界模型、机器人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.16355)、[项目页](https://zgca-hmi-lab.github.io/PINT/)。
- **相对上期：**首次收录；相较 WAVE-0、LeWAM 等把未来表示输入动作专家，本项用同一组 Intent Token 对齐 VLM、视频模型和动作专家。
- **核心贡献：**保留三个专家各自通路，Predictive Intent 负责 chunk 级共享意图；动作专家通过单向注意力读取视频生成器的中间表示。
- **关键结果：**作者报告 RoboTwin 2.0-Hard 15.5%、LIBERO-Plus 79.5%；五项真实双臂任务平均 ID/OOD 成功率为 68%/24%。
- **Coding 接口：**Intent 可作为规划器与动作服务之间的中间协议，但当前没有公开 API 或模型服务。
- **场景：**双臂操作、仓储、桌面机器人和可预览未来的机器人 UI。
- **成熟度 / 证据：**论文及实机视频；代码标记为 soon。
- **重要性 / 阅读：**高 / 必读。

### 8. SonoWorld：6-DoF 探头控制的临床超声生成环境

- **类型 / 日期 / 主线：**论文、医疗机器人 demo；2026-10-14；世界模型、工业仿真。
- **官方链接：**[论文](https://arxiv.org/abs/2610.19327)、[项目页](https://iclr2027anonymous.github.io/SonoWorld/)。
- **相对上期：**首次收录；把通用视觉世界模型扩展到高度专业、动作与观察强耦合的超声环境。
- **核心贡献：**先从约 690 万帧无标注临床视频学习潜动作，再用少量 EM 跟踪数据把潜动作对齐到 6-DoF 探头位姿，最后蒸馏为因果自回归模型。
- **关键结果：**五名有经验评估者对 55 个生成片段进行了评分；动作选择实验中，模型最高有 74.8% 的概率将朝目标的动作排在相反动作之前。论文未披露交互延迟。
- **Coding 接口：**输入是结构化 6-DoF 相对位姿序列；可包装成机器人策略的 `step(action) -> observation` 环境。
- **场景：**超声操作培训、机器人策略预评估、反事实扫描路径比较。
- **成熟度 / 证据：**研究原型；无公开代码和临床部署证据，不可用于诊断结论。
- **重要性 / 阅读：**中高 / 必读。

### 9. AVC-Reward：事件级音画一致性变成可调用服务

- **类型 / 日期 / 主线：**reward model、benchmark、GitHub、权重；2026-10-15；数字人支撑、音视频基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2610.22321)、[代码](https://github.com/Tsuki0512/AVC-Reward)、[32B 权重](https://huggingface.co/Tsuki0512/AVC-Reward)、[706 条 benchmark](https://huggingface.co/datasets/Tsuki0512/AVC-Benchmark)。
- **相对上期：**与 SyncReward 都评估音画关系，但本项新增多事件、分层声音和不对称跨模态关系，并已开放模型、benchmark及LTX-2 LoRA。
- **核心贡献：**分别输出全局叙事、事件起止同步和细粒度属性一致性，并保留失败解释。
- **关键结果：**作者在 AVC-Benchmark 上报告 Δ-Pairwise 0.728、PLCC 0.494；以 reward 优化 LTX-2 后，外部一致性指标亦有提升。
- **Coding 接口：**以 vLLM 启动本地 OpenAI 兼容端点，客户端读取 CSV/JSONL manifest；非常适合接入媒体生成 CI 和候选排序。
- **场景：**数字人演讲、虚拟主播、互动音画、直播素材预审。
- **成熟度 / 证据：**推理、benchmark、LoRA均已开放；32B BF16、研究用途许可证，训练代码未开放。
- **重要性 / 阅读：**中高 / 必读。

### 10. HeteroVDiff：手机 NPU 与 GPU 共享视频模型权重

- **类型 / 日期 / 主线：**论文、端侧运行时；2026-10-12；部署基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2610.16244)。
- **相对上期：**首次收录；从服务器端缓存和稀疏注意力扩展到移动 SoC 的异构调度。
- **核心贡献：**INT8 权重仅存一份，以 NPU 原生布局同时供 GPU 整数点积使用；将完整去噪轨迹展平后，在 block 边界把前后段分给 GPU/NPU并行流水。
- **关键结果：**作者在 Galaxy S25 上报告权重内存比双份方案降低 48%，连续生成吞吐为 NPU-only 的 1.35 倍，VBench 2.0 总分与 FP32相当。
- **Coding 接口：**切分点应根据双引擎并发实测速率配置，而非静态 FLOPs；可进入端侧编译器或 runtime scheduler。
- **场景：**离线短视频、隐私敏感的本地 avatar 素材、现场创作工具。
- **成熟度 / 证据：**论文系统原型；无 SDK、代码、功耗、绝对延迟或温升数据。
- **重要性 / 阅读：**中 / 可读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**本周期暂无 2026-10-11 之后发布、且具备高质量证据的新数字人生成模型。不能用窗口外的 portrait animation 论文填充本日增量。
- **3D/4D 表示：**暂无新的单图 avatar、NeRF、3DGS 或 mesh 数字人工作进入公开可复现阶段。
- **实时交互：**暂无完整覆盖双工语音、打断、表情、视线和全身动作的新增运行时。HeteroVDiff证明端侧异构推理可行，但并非实时数字人系统。
- **音视频与情感：**AVC-Reward能够检测多事件语音与画面在叙事、起止时间和属性上的一致性，可作为数字人视频发布门禁；它没有专门评测嘴形音素或对话情绪。
- **工程部署：**AVC-Reward已有 vLLM 服务协议，但32B BF16模型更适合离线质检，不适合每帧在线控制。
- **安全与身份治理：**本周期没有新的肖像授权、撤回、水印、C2PA、深伪检测或身份溯源机制。

结论：数字人生成能力本周期没有实质跳跃，新增价值主要来自音画质量工程化，而非形象表现或实时交互突破。

## 5. 世界模型进展

- **架构与训练：**StateCraft将抽象状态与视觉状态分离；PINT用共享意图连接语言、未来视频与动作；LongForcing把教师监督延伸到学生自己的长 rollout。
- **可控/可玩生成：**Temporal Specification Guidance提供事件级时间控制，SonoWorld提供连续 6-DoF动作控制。
- **长时与物理一致性：**Velox限制历史注意力成本，LongForcing处理监督窗口缺口；二者分别解决算力增长和模型漂移，但都不能单独保证因果正确。
- **空间表示：**Velox使用视锥 slab 和深度区间作为检索索引，说明空间几何正从生成结果的附属物转为运行时缓存结构。
- **机器人/仿真：**PINT有真实双臂实验；SonoWorld有专业用户研究；PhySimCode和CausalCascade则为合成数据与仿真验收提供工具。
- **实时部署：**Velox在长序列后段显著降本，但单 chunk 仍为秒级；SonoWorld未披露延迟；HeteroVDiff只有吞吐提升，没有实时证据。
- **评测：**评测正在从“视频像不像”转向状态回访、直接状态编辑、因果链、反事实响应、代码可执行性和参数恢复。

## 6. Coding × 新型互动作品

### 链路一：持久、可编辑的生成世界

**用户事件 → 状态机/实体图 → StateCraft 抽象状态更新 → 视频模型渲染 → 状态一致性检查**

代码负责对象 ID、库存、门锁、任务、权限和不可见状态；生成模型负责把当前状态渲染成自然画面；游戏服务器负责冲突裁决。已有论文 demo，但代码尚未开放。

### 链路二：程序化互动电影

**剧情 DSL → 时序逻辑规范 → TSG 采样引导 → 事件检测 → 不满足则重试**

创作者可以写“角色先进入、灯光随后熄灭、标志物持续出现三秒”等可执行规则。代码负责规范生成和验收，模型负责视觉表现，传统剪辑系统负责镜头拼接。当前属于论文方法，尚无现成创作插件。

### 链路三：视频到可执行数字孪生

**现场视频 → 多模态 coding agent → 物理规律/参数/Python → 沙箱执行 → 重渲染对账**

PhySimCode已为该链路提供协议和 evaluator。近期更现实的用途不是全自动重建工厂，而是对 coding agent 的物理反演能力做回归测试，并让工程师修正生成的模拟器。

### 链路四：带因果 CI 的生成式游戏资产

**关卡初态 → 视频模型生成未来 → CausalCascade 事件图/反事实评测 → 失败定位 → 模型或 prompt 更新**

传统引擎生成真实参考和反事实；模型生成视觉未来；代码计算事件发生、运动位置和选择性响应。已有开源 benchmark，可直接形成生成世界的持续集成门禁。

### 链路五：可预演未来的机器人控制台

**自然语言任务 → PINT Predictive Intent → 视频未来＋动作 chunk → 执行器 → 成功/失败记录**

共享意图让 UI 可以同时展示“机器人准备做什么”和“它认为会发生什么”。代码负责安全边界、轨迹限幅、回退和日志；模型负责语义、未来预测与候选动作。已有实机证据，代码未发布。

### 链路六：超声训练模拟器

**虚拟探头 6-DoF 输入 → SonoWorld 因果 rollout → 超声画面 → 学员/机器人下一动作**

代码负责探头设备接入、位姿坐标系、课程目标与评分；世界模型生成临床风格观察；真实机器人控制器不得直接依赖未经验证的生成结果。当前是研究和培训机会，不是临床部署。

### 链路七：数字人音画质量 CI

**数字人生成服务 → AVC-Reward 本地端点 → 三维分数和失败解释 → 重生成/人工审核**

模型生成表演，reward服务判断叙事、事件时间和属性关系，代码设置阈值并保存失败样例。该链路已有公开权重和接口；面部身份与肖像授权仍需独立系统处理。

## 9. 系统架构与技术趋势判断

- **明显升温：**显式状态、空间记忆、事件门控、长时 on-policy 监督、反事实评测和代码可执行性。
- **相对降温：**仅以 FID、VBench 或短视频观感宣称“世界模型”的路线；新评测正在证明视觉合理性与因果正确性差距很大。
- **趋于主流的架构：**  
  `权威状态/规则服务 → 结构化动作与约束 → 生成式观察或未来 → 自动评测 → 状态写回门禁`。  
  其中状态不应只存于视频 KV；需要图结构、几何索引或传统数据库。
- **代码的职责：**保存事实、生成时序规范、定义物理规则、调度缓存、执行生成代码、计算奖励和处理失败回退。
- **模型的职责：**补全视觉与声音、预测难以手写的未来、将高层意图映射为连续动作和感知结果。
- **传统引擎的职责：**物理、碰撞、权限、网络同步、硬实时控制和最终安全边界。
- **仍未解决：**端到端交互延迟、多人一致性、长时因果漂移、生成状态的可靠写回、失败恢复、商业许可证、身份授权和真实并发数据。
- **需要降级的宣传：**24小时 rollout 只能证明采样未崩溃，不能证明世界状态正确；“interactive”若没有动作到输出的延迟和连续闭环数据，应视为受控 demo；StateCraft、PINT、LongForcing和Velox的开源承诺尚未兑现。

## 10. 论文精读候选

1. [StateCraft](https://arxiv.org/abs/2610.19795)  
   值得读：最清晰地阐明显式状态与视觉状态分层。重点看方法中的状态图、事件门控，以及 state edit 和 512-action revisit 实验。与 DAO/JING 相比，它更强调状态编辑和可量化回访。风险是代码未开放，benchmark由作者自建。

2. [PhySimCode](https://arxiv.org/abs/2610.15722)  
   值得读：直接连接视频理解、coding agent和可执行仿真。重点看数据生成、代码沙箱、参数评分和 Table 5/9。与普通视频物理问答相比，它要求重建可运行程序。风险是合成域与真实视频差异较大。

3. [Velox](https://arxiv.org/abs/2610.22311)  
   值得读：空间几何第一次与 FlashAttention块级执行路径形成紧密结合。重点看 frustum slab、多重 warp、覆盖不足时的 safeguard route 和长序列延迟曲线。风险是只在特定模型和H200实现上验证。

4. [Temporal Specification Guidance](https://arxiv.org/abs/2610.20822)  
   值得读：提供可脚本化视频时间控制。重点看 Metric Temporal Logic 的可微语义、attention trace和无需主干反传的实现。风险是概念检测依赖模型自身注意力，复杂角色和细粒度动作可能不稳定。

5. [CausalCascade](https://arxiv.org/abs/2610.15562)  
   值得读：清晰区分“看起来合理”“事件发生”“因果过程正确”和“对干预选择性响应”。重点看事件图、三级 prompt和反事实指标。风险是50个Blender场景仍不足以代表开放世界。

## 11. 下周跟踪与可行动建议

### 持续跟踪

1. StateCraft是否真正开放状态格式、collector、benchmark、权重和推理代码。
2. Velox稀疏 kernel能否在非H200和其他视频模型上保持收益。
3. LongForcing的24小时样例是否提供分段身份、空间和动作一致性曲线，而不仅是展示视频。
4. PINT的代码能否复现实机 OOD 结果，以及 Predictive Intent 是否可供外部规划器读取。
5. SonoWorld是否披露动作到画面的延迟、训练数据治理和公开评测协议。
6. AVC-Reward对 talking head 嘴形、打断、视线与情感是否有效，还是主要覆盖通用音画事件。
7. HeteroVDiff的绝对生成时间、峰值内存、功耗、温升和持续负载降频情况。
8. 是否出现把 TSG 接入 ComfyUI、Diffusers、Unity时间线或影视剪辑工具的实现。

### 本周可做的小实验

#### 实验一：世界状态写回门禁

- **目标：**验证显式状态能否阻止生成画面错误污染长期世界。
- **组件：**JSON实体表、任意视频/I2V模型、VLM状态抽取器、简单diff规则。
- **难点：**把视觉描述稳定映射到对象 ID。
- **成功判据：**连续20次操作后，隐藏对象状态和回访画面均保持一致；非法状态写回能够被拒绝并重试。

#### 实验二：时序逻辑驱动的互动镜头

- **目标：**将自然语言剧情转成可执行事件约束。
- **组件：**小型 DSL、事件检测器、任意视频生成 API；暂不必完整复现 TSG。
- **难点：**事件检测误报以及生成重试成本。
- **成功判据：**在“进入→操作→离开”等三阶段任务上，自动验收通过率相对纯 prompt 提高至少20%。

#### 实验三：视频到模拟器 smoke test

- **目标：**建立 coding agent 反演简单物理的基线。
- **组件：**PhySimCode、一个多模态模型、SciPy子集、沙箱执行。
- **难点：**安全执行生成代码和单位归一化。
- **成功判据：**50个样例中，代码编译率超过80%、运行率超过60%，并报告参数误差而非只看视频相似度。

#### 实验四：数字人音画 CI

- **目标：**验证AVC-Reward能否发现数字人口播的错音、延迟和无关音效。
- **组件：**AVC-Reward、10—20段数字人视频、人工标注的延迟/错配变体。
- **难点：**32B模型资源需求及其对纯嘴形问题的敏感度。
- **成功判据：**人工严重错配样本的分数显著低于正常样本，并能在输出解释中定位具体事件。
