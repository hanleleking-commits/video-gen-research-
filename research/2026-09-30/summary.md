# 数字人、世界模型与互动作品研究日报：2026-09-30

检索窗口：2026-09-24 至 2026-09-30。  
信息截点：2026-09-30 09:16（Asia/Shanghai）。已与 9 月 23、24、28、29 日日报去重；论文日期按 arXiv 实际提交时间计算。

## 1. 本日摘要

本日最强新增是 EditWorld：视频世界不再只能被导航或触发事件，而可以在持续生成中接受新增、删除、替换、风格化及参考图注入，生成式世界开始接近“运行时可编辑场景”。

机器人世界模型出现两条互补路线：DTWM 将不可见的接触力纳入未来视频预测；LRC-JEPA 则把控制相关动力学与稳定外观上下文分开，使规划只传播紧凑状态而不反复处理无关视觉细节。

多主体一致性从通用多 agent 规划延伸到驾驶仿真：CoDrive 让多辆车从各自相机观察同一个共享世界，而不是独立生成互相矛盾的视频。

世界模型评测继续从画质转向状态可靠性。Beyond3D 显示当前最好模型在“物体被移动后离开视野”的问题上仅取得 42.2%，离可依赖的空间记忆仍很远。

更基础的实验还表明，普通 next-state 训练会拟合局部转移，却不一定学会把交换律、逆运算等规则传播到整个世界；这直接支持“代码或显式状态持有规则、生成模型负责观察与预测”的工程架构。

数字人方向没有新的通用实时 talking-head、原生音视频数字人或产业部署证据。新增主要是 MotionSpaceFlow 的逐关节、逐帧精确动作控制，以及 HOI-Retarget 的人物—物体接触重定向管线。

Coding × 互动作品的核心变化因此不是又多一个生成 API，而是控制面进一步结构化：每个视频 chunk 的编辑状态、共享世界坐标、触觉张量、关节约束、对象接触点都可以成为代码接口。

证据整体仍以论文和开源研究代码为主；除既有数字人服务外，本日没有新增客户部署、SLA 或规模化商业数据。

## 3. 最值得关注的 8 个进展

### 1. EditWorld：运行中的生成世界可以被精确修改

- **类型 / 日期 / 主线：**模型、论文、GitHub、权重、benchmark；2026-09-28；世界模型、Coding × 互动作品。
- **官方链接：**[论文](https://arxiv.org/abs/2609.34470)、[GitHub](https://github.com/leoisufa/EditWorld)、[权重](https://huggingface.co/leoisufa/EditWorld)。
- **相对上期：**新增；此前 GameDirector、CoDeR 解决规则和状态，本项解决视觉世界在运行中的内容修改。
- **核心贡献：**通过 Gated Causal Attention 接收随时间变化的编辑指令和参考图；Sparse Context 固定历史预算；WBench-Editing 含约 150 个、240—480 帧案例。作者报告总分 73.8、编辑分 80.0。[论文实验与方法](https://arxiv.org/html/2609.34470)
- **Coding 接口：**JSON 为每个 chunk 指定 `navigation`、`editing_N`、参考图片、相机内外参和场景描述；适合映射到事件系统或关卡脚本。
- **互动与工业场景：**观众实时改造互动电影场景、直播换装、品牌空间即时换陈设、设计评审中的持续场景修改。
- **成熟度 / 证据：**已开源多步推理和权重；few-step 模型与 WBench-Editing 尚未开放。示例脚本使用 8 GPU、70 步采样，不能视为实时产品。
- **重要性 / 阅读：**高 / 必读。

### 2. DTWM：让触觉决定未来视频如何演化

- **类型 / 日期 / 主线：**论文、世界模型、GitHub；2026-09-28；世界模型、机器人。
- **官方链接：**[论文](https://arxiv.org/abs/2609.34286)、[项目页](https://adonis-galaxy.github.io/dtwm-project-page/)、[代码](https://github.com/Adonis-galaxy/Dexterous-Tactile-World-Model)。
- **相对上期：**新增；此前 DexTacWAM 强调触觉世界状态，本项开放了完整训练、推理和评测路径。
- **核心贡献：**将双手压力、手指弯曲和手部位置作为零初始化残差注入视频 token。作者报告手部运动低估由 23% 降至 9%，手部区域感知误差下降 7.4%；越到预测后段，触觉收益越明显。
- **Coding 接口：**输入为 RGB、手部姿态、双手触觉张量和任务指令；仓库提供 LoRA 训练、30 步推理、vision-only 对照和逐指标评测脚本。
- **场景：**机器人抓取预演、触觉遥操作、手工技能训练、带力反馈的数字孪生。
- **成熟度 / 证据：**Apache-2.0 已开源研究原型；论文训练使用两张约 49GB GPU、约 5.5—6.5 小时。尚无闭环控制或实机策略收益。
- **重要性 / 阅读：**高 / 必读。

### 3. LRC-JEPA：把“动力学”与“外观上下文”拆开

- **类型 / 日期 / 主线：**论文、轻量世界模型；2026-09-28；世界模型、实时规划。
- **官方链接：**[论文](https://arxiv.org/abs/2609.34375)、[实验与实现细节](https://arxiv.org/html/2609.34375)。
- **相对上期：**新增；与 DeltaWAM 的像素增量互补，本项在 latent 层只传播可控动态。
- **核心贡献：**紧凑状态 `z` 负责动作条件动力学，残余上下文 `u` 保存缓慢变化的外观信息，但不进入规划循环。作者报告四个仿真环境平均规划成功率较参数相当基线提高 9 个百分点。
- **Coding 接口：**可作为 `encode → sample candidate actions → latent rollout → goal distance → execute` 的规划服务；训练期 decoder 不需随部署加载。
- **关键证据：**Bridge-v2 上活动编码器仅 5.5M 参数；作者在 RTX 5090 上报告完整规划时间 0.45 秒，V-JEPA2 对照为 0.83 秒、DINO-WM 为 57.56 秒。
- **成熟度 / 证据：**论文实测；真实数据仅做离线动作排序，没有实机闭环，未核验到公开代码。
- **重要性 / 阅读：**高 / 必读。

### 4. MotionSpaceFlow：动作生成变成逐关节、逐帧可约束接口

- **类型 / 日期 / 主线：**论文、动作生成 demo；2026-09-28；数字人。
- **官方链接：**[论文](https://arxiv.org/abs/2609.34190)、[项目页](https://yu1ut.com/MSFlow-HP/)。
- **相对上期：**新增；相较昨日的风格强度控制，本项提供空间位置硬约束。
- **核心贡献：**跳过动作 VAE，直接在完整动作空间进行 flow matching；global XYZ 版本可在推理时通过 projection sampling 精确约束任意关节和任意帧，无需额外控制训练。
- **Coding 接口：**代码可传入 `joint_id + frame_id + xyz target`，再将输出接入 SMPL、游戏骨骼、IK 或碰撞修正。
- **场景：**角色必须触碰具体按钮、站到舞台标记点、握住道具或避开障碍的互动表演。
- **成熟度 / 证据：**项目 demo 与论文实测；项目页的代码链接在截点时返回 404，暂无可复现训练栈。
- **重要性 / 阅读：**中高 / 必读。

### 5. CoDrive：多辆车必须看见同一个生成世界

- **类型 / 日期 / 主线：**论文、benchmark；2026-09-28；世界模型、驾驶仿真。
- **官方链接：**[论文](https://arxiv.org/abs/2609.34749)。
- **相对上期：**新增；从 RECAST 的单一 planner 闭环，推进到多个移动观察者共享动态世界。
- **核心贡献：**交替使用车内局部注意力与跨车全局注意力；所有相机轨迹进入统一世界坐标，并通过投影相对位置编码注入模型。CoDrive-Bench 分别评估轨迹服从、几何一致性和实例一致性。
- **Coding 接口：**仿真器维护车辆 ID、相机外参和轨迹；模型联合生成各车辆视图；一致性评测器检查同一车辆或行人在不同观察端的身份与位置。
- **场景：**车路协同、交叉路口反事实测试、多机器人共享感知。
- **成熟度 / 证据：**论文研究原型；未见代码、延迟、闭环 planner 或真实车辆部署。
- **重要性 / 阅读：**中高 / 必读。

### 6. Beyond3D：离开视野的物体仍是世界模型软肋

- **类型 / 日期 / 主线：**benchmark、dataset 方法；2026-09-28；世界模型评测、空间计算。
- **官方链接：**[论文](https://arxiv.org/abs/2609.34630)。
- **相对上期：**新增；WROP 测生成视频的对象永久性，本项测 VLM 能否回答被移动后离屏物体的状态。
- **核心贡献：**基于 HD-EPIC 构建 9,000 个问题、135 段视频、八类任务，覆盖可见性、最后出现时间、场景锚点与相对 3D 位置。
- **关键证据：**九个模型中最好结果仅 42.2%，随机水平为 29.7%，纯文本基线为 31.9%。
- **Coding 接口：**适合做持续世界或 AR agent 的回归集：事件日志更新对象状态，VLM 回答，再与 3D 真值比较。
- **成熟度 / 证据：**论文 benchmark；数据和代码入口尚未核验到。
- **重要性 / 阅读：**高 / 必读。

### 7. HOI-Retarget：从“像人的姿势”转向“保持接触的交互”

- **类型 / 日期 / 主线：**论文、GitHub、dataset；2026-09-28；数字人动作、机器人基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2609.34674)、[代码](https://github.com/shinben0327/hoi-retarget)、[数据集](https://huggingface.co/datasets/shinben0327/hoi-retarget)。
- **相对上期：**新增。
- **核心贡献：**以物体坐标系中的接触点为优化目标，在关节、足部支撑和平滑约束下把 SMPL-X 人物—物体动作重定向到 Unitree G1/H2。
- **Coding 接口：**提供 CLI、批处理、Pinocchio/CasADi 优化、MuJoCo 渲染和 Viser 接触点编辑器；可调整物体尺度并重新求解。
- **资源：**13,904 条机器人—动作轨迹、75 种物体；代码 BSD-3-Clause，数据为 CC BY-NC-SA 4.0，商业使用受限。
- **场景：**数字角色拿取道具、虚拟拍摄预演、人形机器人训练数据生成。
- **成熟度 / 证据：**代码与数据已开放；输出是运动参考，不等于实机可稳定执行。
- **重要性 / 阅读：**中高 / 必读。

### 8. 全局理解评测：next-state 正确不等于学会世界规则

- **类型 / 日期 / 主线：**论文、评测方法；2026-09-28；世界模型可靠性。
- **官方链接：**[论文](https://arxiv.org/abs/2609.34058)。
- **相对上期：**新增；为 OneWorld 的跨分支物理一致性补充更一般的规则传播视角。
- **核心贡献：**在由动作转移组成的 monoid worlds 中测试逆、交换、复合与周期约束。普通下一状态训练虽能拟合观测，却不能稳定传播未显式见过的规则；组合式训练在前三类约束上达到作者报告的 96%。
- **Coding 接口：**可把“证明深度”纳入生成世界 CI：固定规则后自动产生多步组合路径，检查远端状态是否仍满足不变量。
- **成熟度 / 证据：**形式化受控实验；离开放视频世界和产业系统尚远。
- **重要性 / 阅读：**中高 / 可读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**本周期没有新的脸部、嘴形或语音驱动突破。MSFlow 的价值是让动作不再只是整段不可编辑 clip，而可以指定某个时刻某个关节必须到达的位置。
- **3D/4D 表示：**无超过上期 PHOSA、ARS-Avatar 的新人物外观表示。HOI-Retarget 使用 SMPL-X 和显式机器人骨骼，重点在运动与接触，不在神经渲染。
- **实时交互：**两项新增均未披露满足实时数字人所需的首帧时间、持续帧率、打断恢复和多人并发。
- **音视频与情感：**本周期暂无高质量新增。MSFlow 也未联合语音韵律、嘴形、视线或面部表情。
- **工程部署：**较可信路径是离线生成或短时预取动作，由 Unity/Unreal/Godot 的 IK、碰撞和动画状态机修正，再与既有语音及面部系统合成。
- **安全与身份治理：**没有新的肖像授权、水印、溯源或深伪治理进展。

结论：数字人新增属于“可编程动作层”，不能解读为新的端到端数字人产品。

## 5. 世界模型进展

- **架构与训练：**EditWorld 采用 causal/bidirectional 联合训练和自生成历史；DTWM 注入触觉；LRC-JEPA 将动态状态与残余上下文分流。
- **可控 / 可玩：**编辑指令、参考图、相机姿态和 chunk 状态首次形成较完整的流式编辑条件；但公开版本仍是高成本多步推理。
- **长时与物理一致性：**Sparse Context 限制历史预算；Beyond3D 揭示离屏状态记忆不足；全局理解实验说明局部转移准确不保证规则能多步传播。
- **空间表示：**CoDrive 使用统一世界坐标连接多个移动观察者；这是多 agent 仿真比“分别生成多路视频”更关键的增量。
- **机器人 / 游戏 / 仿真：**机器人获得触觉预测与轻量 latent planning；驾驶获得跨车一致生成；游戏本日没有超过 GameDirector、CoDeR 的新系统。
- **实时部署：**没有新系统证明稳定实时。LRC-JEPA 的 0.45 秒规划是离线/仿真规划测量，EditWorld 的 8 GPU、70 步脚本明显仍偏研究。
- **评测：**对象离屏记忆、跨观察者一致性、编辑正确性和规则传播正在取代单纯 FVD/VBench，成为更接近工业价值的指标。

## 6. Coding × 新型互动作品

### 链路一：运行时可编辑的互动电影

**剧情事件或观众输入 → 状态机生成 chunk 编辑 JSON → EditWorld 注入指令/参考图 → 连续视频 → 播放缓冲**

代码负责编辑生效时间、权限、资产引用和撤销；模型负责视觉变化；传统引擎保存人物、库存和剧情真值。已有开源推理证据，但实时播放属于后续工程。

### 链路二：带道具约束的数字角色

**LLM 选择动作意图 → MSFlow 生成全身动作 → 代码添加手—物体目标 → IK/碰撞修正 → Avatar 渲染**

模型负责自然动作，代码规定手在第几帧触碰按钮或杯子，引擎负责碰撞与脚底约束。MSFlow 证明了逐关节约束；完整数字人链路属**本报告推断**。

### 链路三：人类视频到机器人技能数据

**SMPL-X/单目重建 → HOI-Retarget 接触优化 → MuJoCo 验证 → 策略训练 → 实机安全控制器**

相较只匹配姿势，代码显式保存接触段、物体尺度和关节限制。代码及数据可运行；实机成功率并未被本次发布证明。

### 链路四：触觉驱动的远程操作预演

**RGB + 手套压力 → DTWM 候选未来 → 失败/滑落评分器 → 操作者提示或动作筛选**

模型推测抓握是否会继续，代码负责多候选调度和安全阈值，机器人控制器执行最终命令。未来视频预测已有证据，闭环控制收益属**本报告推断**。

### 链路五：共享世界中的多车仿真

**场景服务器维护车辆姿态 → CoDrive 联合生成多车视图 → 各 planner 决策 → 服务器更新统一坐标**

代码和仿真器持有权威轨迹，生成模型补充传感器观察。论文证明跨车一致生成；planner-in-the-loop 尚未证明。

### 链路六：持续世界的记忆与规则双重 CI

**事件日志 → 离屏状态问题集/Beyond3D → 多步规则组合测试 → 回归门禁**

代码检查对象最后位置、所有权、守恒和规则闭包；VLM或视频模型提供感知与预测。这样可同时发现“物体忘了”和“规则只在近处有效”两类错误。

## 9. 系统架构与技术趋势判断

明显升温的是“结构化条件进入持续运行循环”：编辑状态、参考资产、触觉、共享坐标、关节和接触点都比纯文本 prompt 更适合代码验证、记录和回放。

世界模型正分成两层：低成本 latent 模型负责规划和动作筛选，高成本视频模型负责生成可观看的观察。LRC-JEPA 与 EditWorld 分别代表两端；要求一个模型同时承担规则、规划和渲染并不经济。

代码持有权威状态的路线继续得到支持。Beyond3D 和全局理解实验说明，单靠更长上下文或下一帧训练，既不能可靠记住离屏对象，也不能保证规则跨多步传播。

多主体系统正在从“多个 agent 共享文本记忆”升级为共享坐标、共享实体身份和联合生成。该架构可复用于多车、多机器人、多人 NPC 和协作数字人。

数字人研究则从外观画质暂时转向动作可控性和人与物体的关系。真正缺失的仍是把语音、脸部、视线、全身动作、碰撞和实时打断统一起来的开放运行时。

需要降级看待的宣传包括：只有定性 demo 而没有代码、延迟与失败率；把逐帧可控动作称为实时数字人；把多视图生成称为闭环驾驶部署；以及把视觉连贯直接等同于物理正确。

## 10. 论文精读候选

1. [EditWorld](https://arxiv.org/abs/2609.34470)：重点读 §3.1 数据合成、§3.2 Gated Causal Attention/Sparse Context、§4.1 WBench-Editing。它把编辑条件变成了真正的运行时输入；复现风险是 8 GPU、多模型数据管线和未开放 few-step 模型。
2. [LRC-JEPA](https://arxiv.org/abs/2609.34375)：重点读 representation routing、物理量 probe、Bridge-v2 排序实验和限制章节。与大视觉编码器路线的差异非常明确；风险是只有离线真实数据评估。
3. [Dexterous Tactile World Model](https://arxiv.org/abs/2609.34286)：重点读触觉空间注入、vision-only 对照和 horizon 分段结果。代码完整，适合验证触觉是否真的提供因果增益；风险是数据格式复杂且没有控制实验。
4. [Beyond3D](https://arxiv.org/abs/2609.34630)：重点读可见性轨迹构建、八类问题和 temporal grounding 失败分析。它适合转化为持续世界的 CI；风险是 benchmark 与生成模型之间仍有任务差距。
5. [Do World Models Learn Global Understanding?](https://arxiv.org/abs/2609.34058)：重点读 monoid world 构造、compositional training 和 proof depth。它解释了为何可执行规则不能轻易交给像素预测模型；风险是受控任务较抽象。

## 11. 下周跟踪与可行动建议

### 继续跟踪

1. EditWorld few-step 权重、WBench-Editing 和许可证何时开放。
2. EditWorld 的单 chunk 延迟、首帧时间、长时编辑漂移及参考图身份保持。
3. DTWM 的触觉收益能否转化为动作选择或机器人成功率，而非只改善视频指标。
4. LRC-JEPA 是否开放代码并提供真实机器人闭环结果。
5. Beyond3D 数据是否开放，以及视频世界模型在该基准上的表现。
6. CoDrive 是否发布 benchmark、代码和 planner-in-the-loop 测试。
7. MSFlow 代码链接何时恢复，约束采样的耗时和脚滑率如何。
8. 是否出现将动作约束、语音韵律、面部表情和引擎状态机统一的数字人运行时。

### 本周可动手实验

1. **chunk 级世界编辑控制器**
   - 目标：验证编辑事件能否成为稳定的软件接口。
   - 组件：EditWorld、简单 Web UI、JSON 时间线、参考图资产库。
   - 难点：事件切换的视觉突变和撤销语义。
   - 成功判据：同一 20—30 秒序列完成两次局部编辑和一次全局编辑，未编辑对象身份保持率达到团队预设阈值。

2. **数字角色触物约束**
   - 目标：验证“文本动作 + 手部目标点”是否优于生成后纯 IK。
   - 组件：开放 text-to-motion 基线、Unity/Three.js、IK、三种道具。
   - 难点：手部命中、脚滑和身体穿插。
   - 成功判据：至少 30 条动作中，接触成功率提高且动作自然度盲评无显著下降。

3. **离屏对象记忆 CI**
   - 目标：测量现有互动 agent 是否会忘记被移动后离屏的物体。
   - 组件：Unity/Godot 测试场景、对象事件日志、VLM、自动问答器。
   - 难点：区分感知失败、记忆失败与语言回答失败。
   - 成功判据：建立可重复的四阶段指标，并分别报告最后可见时间、最后放置位置、当前相对方向和最终检索成功率。

4. **触觉候选未来对照**
   - 目标：复现 DTWM 的触觉增益并检查其是否有决策价值。
   - 组件：DTWM、EgoTouch 子集、vision-only 开关、简单滑落/持续抓握分类器。
   - 难点：数据预处理和触觉—视频时间对齐。
   - 成功判据：除 LPIPS 外，触觉模型对“继续抓握或即将释放”的分类准确率稳定超过视觉基线。
