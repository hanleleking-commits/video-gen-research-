# 数字人、世界模型与互动作品研究日报：2026-08-04

检索窗口：2026-07-29 至 2026-08-04。  
日期说明：当前日期按 Asia/Shanghai 核验。arXiv 截至本次检索的最新公开批次仍为 8 月 3 日，尚无 8 月 4 日新批次；已与 7 月 29 日至 8 月 3 日日报去重。本期重点是上一期未覆盖、但处于窗口内且与三条主线直接相关的高质量条目。Meshy T2 的论文早于窗口一天，仅因 8 月 3 日出现开源状态更新而纳入。

## 1. 本日摘要

本周期数字人生成、口型驱动和实时对话侧没有未报道的高质量新增，不能用普通 3D 或人脸论文填补；新增主要位于可维护资产和身份安全两端。Meshy T2 把原生 mesh 生成压缩至作者报告的中位 6 秒，FocusGS 则为已经交付的 3DGS 资产增加局部修复和确定性编辑，这两项共同改善“生成资产进入代码化生产管线”的可行性，但都尚未形成可调用 SDK。世界模型的核心变化是从“把整个未来画出来”转向“只预测影响动作的状态”：ST-WAM 在训练时保留视觉未来监督、推理时跳过显式视频生成；Auto-JEPA更进一步，只预测连续驾驶意图并从轨迹库检索可执行方案。该趋势降低了运行时成本，也使世界模型更容易嵌入规划器、状态机和安全控制器，但失去了像素级未来所提供的可视化解释。RayViT和GO-PRE分别把相机射线与目标视域变成显式程序输入，说明空间智能正在形成比自由文本prompt更稳定的代码接口。安全侧，视频来源归因已有开源实现，但Rank-1仅20.5%，适合作为风险信号而非司法级结论；不确定性感知检测和人脸识别攻击仍只有论文证据。产业成熟度总体没有跃升：本期没有新的客户部署、SLA、并发成本或正式引擎插件，最强证据仍是作者实验和一个可运行取证仓库。

## 3. 最值得关注的 9 个进展

### 1. ST-WAM：训练时想象未来，运行时不生成未来画面

- **类型 / 时间 / 主线：** 论文；2026-07-31；世界模型、机器人运行时。
- **官方链接：** [论文](https://arxiv.org/abs/2607.28993)。
- **相对上期的新变化：** 首次纳入；8 月 3 日公开批次中的补充重点。
- **核心贡献：** 发现像素世界模型在视觉分布变化下会把当前环境“改画”回训练域。ST-WAM用DINOv3语义空间和VAE动态空间联合预测未来，并从近期DINO历史中检索当前任务证据；推理阶段不必显式生成未来视频。
- **Coding接口：** 适合封装为`observation + instruction + history → action`策略模块；历史缓存和检索窗口可由运行时管理，但尚无官方API或代码。
- **指标与限制：** 作者报告LIBERO 98.7%、RoboTwin 2.0 92.8%；相对Fast-WAM，LIBERO-Plus零样本提高21.3个百分点，真实视觉变化下成功率由25.8%升至61.5%。均为论文作者实验。
- **场景 / 成熟度 / 证据：** 机器人操作、视觉变化下的数字孪生控制；研究原型，论文实测；**高 / 必读**。

### 2. Auto-JEPA：只预测影响驾驶动作的连续意图

- **类型 / 时间 / 主线：** 论文、benchmark；2026-07-31；世界模型、自动驾驶。
- **官方链接：** [论文](https://arxiv.org/abs/2607.29031)。
- **相对上期的新变化：** 首次纳入。
- **核心贡献：** 不预测完整视频、occupancy或BEV未来，而将视觉、历史自车运动和导航命令映射为未来轨迹意图embedding，再从固定轨迹库检索并排序可执行轨迹。
- **Coding接口：** 轨迹库是明确的软件边界：传统规划器负责生成、版本化和验证轨迹，模型负责意图检索与场景排序，安全控制器拥有最终执行权。
- **指标与限制：** 作者报告NAVSIM v1 PDMS 91.3、v2 EPDMS 89.1；遮挡动态主体造成的意图变化为同面积随机遮挡的2.97倍。尚无代码或实车部署证据。
- **场景 / 成熟度 / 证据：** 自动驾驶规划、仿真候选轨迹筛选；研究原型，论文实测；**高 / 必读**。

### 3. Meshy T2：6秒级原生mesh生成，但开源仍未兑现

- **类型 / 时间 / 主线：** 论文、GitHub开源预告；论文2026-07-28，仓库状态更新2026-08-03；Coding × 3D资产基础设施。
- **官方链接：** [论文](https://arxiv.org/abs/2607.28675)、[GitHub](https://github.com/meshy-dev/meshy-t2)。
- **纳入原因 / 相对上期变化：** 论文早于窗口一天；8 月 3 日仓库新增“正在准备开源”的明确状态，因此首次纳入。仓库目前仍只有README和素材。
- **核心贡献：** vertex-set mesh VAE用每顶点连续token一次解码顶点、边连接及面绕序；体素flow与mesh flow组成粗到细级联，并通过顶点预算控制面数。
- **Coding接口：** 原生mesh、多部件连接和面数预算适合进入Blender、Unity、Unreal或WebGPU资产管线；当前尚无CLI、Python包、权重或导出示例。
- **指标与限制：** 作者报告图像到mesh中位耗时6秒，比自回归基线快一个数量级以上；硬件、材质、UV、rig和碰撞体生成成本未披露。
- **场景 / 成熟度 / 证据：** 游戏道具、虚拟展览、数字人服装与配件草模；论文demo＋开源预告，官方声称；**高 / 必读**。

### 4. FocusGS：为3DGS资产增加可验证的局部维护操作

- **类型 / 时间 / 主线：** 论文、demo；2026-07-30；数字人/空间资产基础设施。
- **官方链接：** [论文及附属demo](https://arxiv.org/abs/2607.28834)。
- **相对上期的新变化：** 首次纳入。
- **核心贡献：** 将局部修复表达为新增Gaussian基元，将确定性编辑表达为“擦除旧载体＋插入新内容”的空间delta层，避免重新训练整个资产或依赖不可复验的文本编辑。
- **Coding接口：** 可将编辑记录表示为`asset_version + ROI + erase_delta + insert_delta`，支持撤销、审核、差异渲染和CI回归测试。
- **指标与限制：** 作者报告修复区PSNR提高7.91 dB，83次确定性编辑全部改善目标ROI；无代码、标准3DGS格式或DCC插件。
- **场景 / 成熟度 / 证据：** 数字人局部外观修复、XR场景维护、产品数字孪生；论文与demo，论文实测；**高 / 必读**。

### 5. RayViT：用相机射线消除机器人策略的视角脆弱性

- **类型 / 时间 / 主线：** 论文；2026-07-31；世界模型支撑、机器人。
- **官方链接：** [论文](https://arxiv.org/abs/2607.29622)。
- **相对上期的新变化：** 首次纳入。
- **核心贡献：** 把相机内外参转换成Plücker ray map，通过位置embedding和门控cross-attention注入预训练ViT，使策略理解“这个像素来自哪条空间射线”。
- **Coding接口：** 机器人或仿真运行时可从相机标定直接生成ray map；相机位姿不再只是隐含训练条件，而成为可记录、测试和扰动的输入字段。
- **指标与限制：** 作者报告RoboCasa相机扰动下提高约13个百分点，实机多任务平均多完成1.78个阶段；无确认代码。
- **场景 / 成熟度 / 证据：** 可移动摄像头机器人、跨工位部署、XR遥操作；研究原型，论文实测；**中高 / 必读**。

### 6. GO-PRE：让代码指定“哪些视角必须重建好”

- **类型 / 时间 / 主线：** ICML 2026论文；2026-07-31；3D/4D采集、空间运行时。
- **官方链接：** [论文](https://arxiv.org/abs/2607.29037)、[ICML收录页](https://icml.cc/Downloads/2026)。
- **相对上期的新变化：** 首次纳入。
- **核心贡献：** 不再用参数不确定性或几何启发式选择下一视角，而是最大化用户指定目标视域中的预测渲染熵下降，并声称可实时计算信息增益。
- **Coding接口：** 扫描应用可把“正脸、手部、商品标签、机器人工作区”等目标定义成view manifold，规划器据此选择下一相机位姿。
- **限制：** 摘要未披露具体实时延迟，未发现代码、机器人接口或扫描SDK。
- **场景 / 成熟度 / 证据：** avatar定向采集、产品扫描、数字孪生、机器人主动感知；同行评审论文原型；**中高 / 必读**。

### 7. 训练-free生成视频来源归因：代码已开放，准确率仍不足

- **类型 / 时间 / 主线：** 论文、GitHub、benchmark；2026-07-31；身份安全与内容治理。
- **官方链接：** [论文](https://arxiv.org/abs/2607.28955)、[GitHub](https://github.com/renxi-seu/Video_Attribution)。
- **相对上期的新变化：** 首次纳入。
- **核心贡献：** 将生成源识别转成实例检索，结合正交颜色变换、多尺度量化残差与跨帧语义聚合，无需针对每个生成器训练分类器。
- **Coding接口：** 仓库提供帧提取后的gallery构建和`test.py`评测命令，可作为内容上传管线中的离线归因worker。
- **指标与限制：** 作者在GenVidBench报告Rank-1 20.5%、mAP 16.6%；只能形成弱风险信号，不能单独证明生成来源。仓库未见明确许可证。
- **场景 / 成熟度 / 证据：** 数字人视频审核、模型滥用调查、生成资产审计；已开源研究代码，论文实测；**中高 / 可读**。

### 8. 不确定性感知deepfake检测：重点从“给标签”转向“知道何时不可信”

- **类型 / 时间 / 主线：** 论文；2026-07-30；数字人安全。
- **官方链接：** [论文](https://arxiv.org/abs/2607.28769)。
- **相对上期的新变化：** 首次纳入。
- **核心贡献：** 联合CLIP视觉、面部属性语义约束和结构依赖三条证据流，用分支间分歧校准不确定性，面向训练集之外的新伪造方式。
- **Coding接口：** 产品侧最有价值的输出不是单一真假概率，而是`prediction + uncertainty + branch disagreement`，可驱动人工复核和拒绝决策。
- **限制：** 摘要未披露主要数值、代码、实时吞吐或压缩视频测试结果。
- **场景 / 成熟度 / 证据：** 视频开户、数字员工身份审核、UGC内容审核；研究原型，作者实验；**中 / 可读**。

### 9. DiffAttack：生成模型可直接优化人脸识别身份embedding

- **类型 / 时间 / 主线：** IJCB 2026论文；2026-07-31；数字人身份安全。
- **官方链接：** [论文](https://arxiv.org/abs/2607.28936)。
- **相对上期的新变化：** 首次纳入。
- **核心贡献：** 在latent diffusion空间中优化图像，使其接近目标人脸识别embedding，同时维持人眼可接受质量；攻击可跨人口属性和不同识别模型迁移。
- **指标与限制：** 作者报告跨多个人脸模型平均攻击成功率84.86%，迁移性超过噪声攻击15.28个百分点、语义攻击约5.21个百分点；尚无代码和真实摄像头链路验证。
- **Coding与场景：** 应用于数字人注册流程的红队测试，而非生产生成能力；身份系统需要活体、设备信号、挑战响应和人工审核共同防护。
- **成熟度 / 证据：** 安全研究原型，论文实测；**中 / 可读**。

## 4. 数字人 / 虚拟形象能力进展

**生成与驱动。** 本周期暂无新的高质量 talking head、speech-driven avatar、口型、视线、情感、可打断对话或原生音视频数字人增量。上一期的TaoMate、OmniMate、STEER等不因没有新信息而重复收录。

**3D/4D表示。** 新增集中在资产管线而非人物建模：Meshy T2生成标准mesh拓扑，FocusGS维护3DGS资产，GO-PRE优化目标视角采集。三者可分别承担“新建—维护—补采”，但尚未证明可共同处理表情rig、毛发、服装碰撞和长时4D动作。

**实时交互。** Meshy T2的6秒属于交互式资产创建，不是逐帧运行时；GO-PRE的“实时”仅指下一视角信息增益计算。没有新的数字人首帧响应、RTC延迟或并发数据。

**音视频与情感表达。** 本周期暂无高质量新增。

**工程部署。** 当前最有价值的接口是可版本化空间delta和可控制面数的mesh生成。真正进入Unity、Unreal或Web运行时仍需GLB/FBX/USD导出、材质、骨骼、LOD、碰撞体、确定性seed和失败回退。

**安全与身份治理。** 本期出现攻击、检测、归因三类互补信号，但都不能替代授权和溯源。生产系统仍应优先使用身份授权记录、C2PA类内容凭证和服务端生成日志；事后检测只作为补充。

## 5. 世界模型进展

**架构与训练。** ST-WAM采用“语义未来＋像素动态”双空间训练；Auto-JEPA只对齐未来轨迹意图。两者都表明世界模型不必在运行时生成可观看视频。

**可控/可玩生成。** 本期没有新的键鼠可玩视频世界。控制增量主要是机器人指令、导航命令、相机射线、候选轨迹和目标视域，均比自由prompt更适合软件测试。

**长时与物理一致性。** ST-WAM通过近期历史检索保持任务证据，但没有证明开放世界的长期对象持久性。Auto-JEPA的轨迹库保证候选轨迹可执行，却不等于模型掌握完整物理因果。

**空间表示。** RayViT的Plücker rays、GO-PRE的view manifold和Auto-JEPA的轨迹embedding形成三类紧凑空间协议：观察几何、采集目标和行动意图。

**机器人、游戏与仿真。** 新增全部偏机器人和驾驶；游戏侧只能借鉴其架构，不能将论文结果直接外推为生成式游戏证据。

**实时部署与评测。** ST-WAM不渲染未来理论上可降低延迟，GO-PRE声称实时选择视角，但两者均未披露端到端毫秒数、GPU预算或并发能力。

## 6. Coding × 新型互动作品

1. **视觉＋指令＋短期历史 → ST-WAM语义/动态预测 → 机器人动作 → 安全控制器**  
   代码负责历史缓存、权限、动作边界、超时和回滚；模型负责提取与任务相关的未来状态并生成动作；传统控制器负责碰撞和安全。已有作者实机研究证据，无公开运行栈。

2. **导航命令＋自车历史 → Auto-JEPA意图embedding → 轨迹库检索/排序 → 仿真或车辆执行**  
   代码维护经过验证的轨迹库并执行硬约束；模型只做场景相关选择。可用于自动驾驶仿真、训练体验和驾驶数字孪生；完整工业部署属于本报告推断。

3. **参考图＋顶点预算 → Meshy T2 → 原生多部件mesh → Blender/Unity/Unreal资产导入**  
   coding agent可从设计规格推导面数、部件清单和碰撞要求，模型生成几何，引擎负责材质、rig、LOD和物理。论文有6秒级证据，但代码和权重尚未交付。

4. **资产版本＋ROI变更 → FocusGS空间delta → 自动差异渲染 → 审核后合并**  
   代码像管理软件补丁一样管理3D资产delta；模型或优化器只修改局部外观。这可形成可审计的数字人修脸、场景维修和商品数字孪生工作流；目前仅论文demo。

5. **目标视域 → GO-PRE选择下一相机位姿 → 扫描设备采集 → 3D/4D资产更新**  
   创作者可指定“正脸和手部优先”，机器人或手机采集器执行下一视角，重建器更新资产。对avatar定向补采有明确机会，但端到端实现为本报告推断。

6. **生成视频上传 → 指纹提取/来源检索 → 不确定性检测 → 审核和授权日志**  
   代码负责任务队列、阈值、证据留存和人工升级；模型负责归因和异常评分。来源归因代码可运行，但准确率不足以自动执法或封禁。

## 8. 可复现资源与开发者入口

- [Video Attribution](https://github.com/renxi-seu/Video_Attribution)：目前唯一可确认有实质代码的新资源。提供特征提取、gallery构建和Rank-1/mAP评测流程；需先下载并逐帧展开GenVidBench。仓库未见明确许可证。最小验证路径是对两个已知生成器各抽取少量视频，构建10-shot gallery，再检查同模型视频的检索排名是否显著优于随机。
- [Meshy T2](https://github.com/meshy-dev/meshy-t2)：8 月 3 日声明正在准备开源，但当前只有README和素材，没有代码、权重或许可证；暂不值得配置环境。
- [FocusGS demo](https://arxiv.org/abs/2607.28834)：arXiv附属文件包含演示视频，可验证局部delta概念，但不能复现实验。
- ST-WAM、Auto-JEPA、RayViT、GO-PRE、DiffAttack及不确定性感知deepfake检测均未确认公开完整代码、权重或SDK，当前只适合论文级架构复现。
- 本周期未发现新增API、MCP、Unity/Unreal/Godot插件、可部署世界模型服务或数字人RTC示例。

## 9. 系统架构与技术趋势判断

明显升温的是“预测足够用于行动的状态”，而不是生成完整未来画面。正在形成的可复用架构为：

`传感器/用户输入 → 几何与权威状态 → 意图或语义未来 → 候选动作/资产delta → 规则与安全验证 → 引擎或设备执行`

代码负责相机标定、轨迹库、资产版本、对象状态、权限、约束、日志和回滚；生成或世界模型负责外观、语义状态、未来意图及候选排序；传统引擎负责物理、碰撞、渲染、网络同步和确定性规则。

3D资产侧也从一次性生成转向软件工程式生命周期：Meshy T2负责快速创建，GO-PRE决定补采位置，FocusGS用局部delta维护。若后续补齐标准格式和插件，这一组合比“每次重新生成整个资产”更适合工业生产。

仍未解决的问题包括：隐式意图是否遗漏安全相关细节；语义未来与真实物理结果的校准；无像素rollout时如何向人类解释决策；mesh生成后的UV、材质、rig和碰撞；3DGS delta跨渲染器兼容；视频归因的开放集泛化及法律证据效力。

需要降级看待的表述包括：Meshy T2的“代码和权重将开放”尚未兑现；GO-PRE的“实时”没有具体时延；ST-WAM和Auto-JEPA的高分均为作者实验；来源归因虽然超过基线，但20.5%的Rank-1不能支撑自动判责。本周期没有新的规模化产业落地证据。

## 10. 论文精读候选

1. [ST-WAM](https://arxiv.org/abs/2607.28993)：重点读Training-Distribution Hallucination诊断、DSFE和CAIR。与BWM类显式视频rollout的差异在于推理时不生成未来；复现风险是缺代码和真实视觉shift协议。
2. [Auto-JEPA](https://arxiv.org/abs/2607.29031)：重点读轨迹表示、意图对齐、trajectory memory和candidate selection。价值在于明确界定“规划需要的世界状态”；风险是固定轨迹库限制长尾机动。
3. [Meshy T2](https://arxiv.org/abs/2607.28675)：重点读vertex-set VAE、连接性解码、face winding和两级flow。与自回归mesh token的关键区别是并行生成；复现风险是代码、权重和训练数据未开放。
4. [FocusGS](https://arxiv.org/abs/2607.28834)：重点读空间delta表示、erase-insert factorization和评测协议。价值在于将3DGS编辑变成可验证维护操作；风险是仅有demo。
5. [RayViT](https://arxiv.org/abs/2607.29622)：重点读Plücker ray编码、门控cross-attention和相机扰动实验。可迁移到世界模型及XR输入；风险是对标定误差和动态相机的鲁棒性未知。

## 11. 下周跟踪与可行动建议

继续跟踪：

1. Meshy T2是否真正开放代码、权重、许可证、显存和导出格式。
2. ST-WAM是否公布推理延迟，以及不生成未来视频带来的实际加速。
3. Auto-JEPA能否处理轨迹库之外的紧急动作和多主体博弈。
4. RayViT是否开放相机标定到Plücker ray map的实现。
5. GO-PRE是否发布实时规划代码、具体毫秒数及移动采集demo。
6. FocusGS能否支持动态4DGS、人物表情区域及跨版本delta合并。
7. 视频来源归因能否覆盖新模型、转码、裁剪、水印和开放集未知来源。
8. deepfake不确定性是否能在直播压缩、遮挡和低清晰度条件下保持校准。

本周可做的小实验：

1. **世界模型“渲染未来是否必要”对照实验**  
   目标：比较像素未来特征与纯语义未来特征对动作分类的贡献。组件：现有机器人视频、DINO特征、轻量时序预测器。难点：保证训练预算和历史长度一致。成功判据：语义模型在视觉背景替换后保持更高动作准确率，同时显著降低推理时间。

2. **3D资产delta版本协议**  
   目标：为3DGS定义`base_asset/ROI/erase/insert/author/version`清单。组件：任意3DGS查看器、Git LFS或对象存储、差异渲染脚本。难点：Gaussian索引和空间范围稳定性。成功判据：局部修改可撤销、可合并，并能自动证明非目标区域变化低于阈值。

3. **生成视频归因压力测试**  
   目标：验证开源归因方法在转码和编辑后的退化。组件：Video Attribution仓库、少量GenVidBench视频、FFmpeg。难点：数据准备成本。成功判据：得到H.264码率、裁剪、缩放、加字幕四类扰动下的Rank-1曲线，并确定不可自动判责的阈值。

4. **相机几何接口原型**  
   目标：把Unity或机器人相机内外参转换为统一ray-map张量。组件：Unity/Isaac Sim或真实相机、Plücker射线生成脚本、ViT特征对比。难点：坐标系和畸变约定。成功判据：相机移动后，同一3D目标的几何条件特征比纯RGB特征更稳定。
