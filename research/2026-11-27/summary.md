# 数字人、世界模型与互动作品研究日报：2026-11-27

检索窗口：2026-11-21 至 2026-11-27。日期以官方页面或 arXiv 首次提交时间为准；检索截至 2026-11-27（北京时间）。

## 1. 本日摘要

本周期的主要突破来自世界模型运行时，而非基础视频画质：ShowNow 不只达到 16 FPS，还通过预生成八种候选未来，将按键到画面响应的中位延迟从 620 ms 降至 208 ms，首次较完整地公开了权重、数据、浏览器交互服务及延迟测试工具。[论文](https://arxiv.org/abs/2611.34693)｜[代码](https://github.com/showlab/ShowNow)

WorldInteract 把材质行为学习与碰撞响应分开，用统一的速度增量接口连接因果视频生成器和物理控制器；SimPWM 则让规则模拟器维护对象真值、视频模型负责写实渲染。两者共同说明，近期世界模型正在从“端到端猜测一切”转向“传统模拟或代码保存可验证状态，生成模型补足视觉表现”。[WorldInteract](https://arxiv.org/abs/2611.34730)｜[SimPWM](https://arxiv.org/abs/2611.32786)

Coding 的角色进一步上升。CodeWAM 直接把可执行车辆动力学代码纳入世界表示；PSC-Gen 用 VLM agent 生成、验证物理关键帧；AvatarAnyone 用 agent 根据服装类别和层级动态组装每个角色的优化流程。代码不再只是调用模型，而开始定义状态、候选未来、物理约束和资产管线。

数字人方向没有新的 talking-head、实时语音头像或音视频一体基座。高质量增量集中在可编辑资产：AvatarAnyone 输出可进入 Blender、Unreal 和 MuJoCo 的分层人体与服装 mesh；Head Anything 提升少图多表情头部 mesh 的跨帧一致性；MemHand 为遮挡和出画手部维护事件与尺度记忆。

相对 11 月 24 日日报，增量从 NoPeWorld 的“生成后安全过滤”推进到 ShowNow 的“输入前推测候选未来”、SimPWM 的“显式模拟状态”及 CodeWAM 的“代码即世界状态”。但除 ShowNow、Residual Guidance、SimPWM 外，多数项目仍只有论文或项目页；本周期没有新的客户部署或规模化商业案例。

## 3. 最值得关注的 12 个进展

### 1. ShowNow：提前生成候选未来，降低真实交互延迟

- **类型 / 日期 / 主线：**模型、GitHub、权重、dataset、demo；2026-11-25；世界模型、Coding × 互动作品。
- **官方链接：**[论文](https://arxiv.org/abs/2611.34693)、[GitHub](https://github.com/showlab/ShowNow)。
- **相对上期：**11 月 24 日后新增。
- **核心贡献：**共享历史树一次准备最多八种动作未来，每 0.25 秒提交一个 latent；5B 模型在单张 H100 上以 480p、16 FPS 运行。论文实测 ViZDoom 中位输入—显示延迟由 620 ms 降至 208 ms。
- **Coding 接口：**提供键盘事件、MJPEG 浏览器服务、CUDA Graph/FA3 运行时、延迟回放工具及训练脚本。
- **作品 / 场景：**可玩视频、生成式第一人称空间、互动电影镜头和低延迟仿真前端。
- **成熟度 / 证据：**已开源可运行；Apache-2.0；论文实测。仍仅支持八个离散动作和 ViZDoom，长时一致性会下降。**重要性：高；必读。**

### 2. WorldInteract：用统一冲量接口连接视频模型与物理控制器

- **类型 / 日期 / 主线：**论文、demo；2026-11-25；世界模型、物理基础设施。
- **链接：**[arXiv](https://arxiv.org/abs/2611.34730)。
- **相对上期：**新增。
- **核心贡献：**将材质自身运动和接触响应解耦；外部推力、碰撞冲量统一表示为速度增量。生成器在 30,000 个无接触模拟视频、22 类材质上学习行为，物理控制器计算接触响应。
- **Coding 接口：**理论接口可抽象为 `material_state + impulse -> next_video_chunk`，适合由物理引擎或节点图注入控制；代码尚未确认。
- **场景：**软体、液体、布料互动装置，材质教学，机器人操作预演。
- **成熟度 / 证据：**论文原型；作者评测；无工业部署。**高；必读。**

### 3. SimPWM：模拟器保存对象真值，视频模型负责写实渲染

- **类型 / 日期 / 主线：**论文、GitHub、权重、demo；2026-11-24；世界模型、机器人仿真。
- **链接：**[论文](https://arxiv.org/abs/2611.32786)、[MIT 代码](https://github.com/TingtingLiao/SimPWM)。
- **相对上期：**新增，直接延续上期“代码/规则保存真值”的判断。
- **核心贡献：**从首帧构建机器人模型和可接触对象点云，规则模拟器按动作更新显式状态，再由视频模型渲染。加入对象代理后，漏掉抓取的比例由 54% 降至 38%；冻结对象还能测试视频是否真正服从状态。
- **Coding 接口：**Python 包、JSON 状态、MuJoCo 模型、训练/评测脚本；自带 bottle、rope、shirt 示例。
- **场景：**机器人数据生成、反事实测试、数字孪生、操作任务可视化。
- **成熟度 / 证据：**已开源研究原型；论文实测。代理生成约需单 GPU 3 分钟，完整 H3 渲染路径需 4×80 GB GPU。**高；必读。**

### 4. CodeWAM：把可执行动力学代码纳入自动驾驶世界表示

- **类型 / 日期 / 主线：**论文；2026-11-24；世界模型、Coding × 工业控制。
- **链接：**[arXiv](https://arxiv.org/abs/2611.32483)。
- **相对上期：**新增；比 Code World Model 2.0 更进一步进入决策回路。
- **核心贡献：**代码执行候选轨迹下的车辆状态演化，学习模型预测场景后果，两者共同评价计划。论文报告 NAVSIM v1 PDMS 93.6、v2 EPDMS 92.1、NAVHARD EPDMS 50.6。
- **Coding 接口：**核心产物就是可执行 ego dynamics；但官方仓库及许可证尚未可靠确认。
- **场景：**自动驾驶候选计划审核、可解释轨迹比较、仿真回归测试。
- **成熟度 / 证据：**benchmark 研究原型；作者实测。**高；必读。**

### 5. AvatarAnyone：agent 规划分层 mesh 数字人重建

- **类型 / 日期 / 主线：**论文、项目页、demo；2026-11-23；数字人、Coding × 资产管线。
- **链接：**[论文](https://arxiv.org/abs/2611.30777)、[项目页](https://miraymen.github.io/avataranyone/)。
- **相对上期：**新增。
- **核心贡献：**agent 识别服装类别、衣型和层级，为每个人选择不同初始化和优化阶段；身体、服装、鞋与长发保持独立 mesh，可换装、布料模拟及接触计算。
- **Coding 接口：**项目展示直接导入 Blender、Unreal Engine、MuJoCo；代码仓库目前只有 README，计划 2027-01-15 发布。
- **场景：**游戏玩家分身、虚拟试衣、影视群演、机器人与人体交互模拟。
- **成熟度 / 证据：**可运行 demo、代码待发布；论文实测约 150 段 YouTube 视频。**高；必读。**

### 6. Residual Guidance：流式视频中途换提示词不再被旧上下文拖回

- **类型 / 日期 / 主线：**论文、GitHub、benchmark；2026-11-24；世界模型运行时。
- **链接：**[论文](https://arxiv.org/abs/2611.32820)、[MIT 代码](https://github.com/nahyeonkaty/residual-guidance)。
- **相对上期：**新增。
- **核心贡献：**不修改 KV cache，而是在新提示词下重新噪化上一片段，计算校正 residual 并注入下一片段前两个去噪步骤；无需训练或修改权重。
- **Coding 接口：**统一脚本适配 Self Forcing、Causal Forcing、LongLive 和 Infinity-RoPE；提供 5 秒切换、10 秒故事及 60 秒交互测试集。
- **场景：**实时虚拟布景、互动电影、直播场景和由事件系统驱动的生成世界。
- **成熟度 / 证据：**已开源研究组件；每个被引导片段增加一次前向计算。**高；必读。**

### 7. iWAM：不生成未来画面，也能保留世界模型的行动信息

- **类型 / 日期 / 主线：**论文；2026-11-24；世界模型、机器人运行时。
- **链接：**[arXiv](https://arxiv.org/abs/2611.33141)。
- **相对上期：**新增；与 SOAR 的“减少 rollout token”形成互补。
- **核心贡献：**利用双向 flow map，让一次视频骨干前向产生足够区分候选行动的特征；控制策略无需等待完整未来帧生成。
- **Coding 接口：**适合作为低延迟 `state -> latent effect -> action` 服务；公开代码及精确延迟尚未确认。
- **场景：**机器人闭环控制、NPC 决策和高并发仿真。
- **成熟度 / 证据：**论文原型；作者报告覆盖模拟和真实机器人。**高；必读。**

### 8. Interactive Neural Computers：把桌面界面本身变成世界模型

- **类型 / 日期 / 主线：**论文、demo；2026-11-24；Coding × 互动界面。
- **链接：**[arXiv](https://arxiv.org/abs/2611.32811)。
- **相对上期：**新增。
- **核心贡献：**从屏幕历史和键鼠动作直接预测下一屏；用显式 slot memory 保存离屏文件、VLM query bridge 处理推理、residual renderer 只生成变化区域。长闭环中离屏文件召回率达 64.2%，终端 OCR 由 1.3% 提高到 50.1%。
- **Coding 接口：**键鼠事件即 action API，显式记忆可在测试时替换；作者承诺发布语料、代码和权重。
- **场景：**个性化操作系统、无障碍界面、软件培训模拟、GUI agent 测试环境。
- **成熟度 / 证据：**研究原型；代码待发布。精确文本仍远未达到传统 UI 标准。**中高；必读。**

### 9. Head Anything：少图、多表情下联合生成一致的 3D 头部

- **类型 / 日期 / 主线：**论文、项目页；2026-11-23；数字人、3D 表示。
- **链接：**[arXiv](https://arxiv.org/abs/2611.31143)。
- **相对上期：**新增。
- **核心贡献：**在预训练单图 3D 生成器中加入对应点注意力，使不同视角和表情共同补全不可见区域。作者报告头部 Chamfer distance 降低 32%，跨帧不一致降低 47%。
- **Coding 接口：**输出 pixel-aligned mesh，可进入面部跟踪、绑定和 DCC 管线；代码与模型尚未发布。
- **场景：**游戏角色、远程会议头像、影视数字替身。
- **成熟度 / 证据：**论文与 demo；作者实测。**中高；可读。**

### 10. MemHand：为遮挡和出画的手建立事件记忆

- **类型 / 日期 / 主线：**论文、项目页；2026-11-24；数字人、空间交互。
- **链接：**[论文](https://arxiv.org/abs/2611.32876)、[项目页](https://irmvlab.github.io/memhand.github.io/)。
- **相对上期：**新增。
- **核心贡献：**短期事件记忆保存遮挡前后证据，长期尺度记忆保存可靠的度量锚点；相对 StableHand，W-MPJPE 在 ARCTIC、HOT3D 分别降低 57% 和 70%。
- **Coding 接口：**可向 XR 或动作重定向系统持续输出世界坐标手部轨迹；代码显示为 coming soon。
- **场景：**AR 手势、第一视角动作采集、人到机器人策略迁移。
- **成熟度 / 证据：**论文原型；作者实测。**中；可读。**

### 11. PSC-Gen：VLM agent 规划并验收物理关键帧

### 12. ActRosetta：检查世界模型训练与推理的 action 接口是否一致

- **类型 / 日期 / 主线：**论文、评测工具设计；2026-11-25；世界模型工程可靠性。
- **链接：**[arXiv](https://arxiv.org/abs/2611.34739)。
- **相对上期：**新增。
- **核心贡献：**发现 Navigation World Models 的训练和 rollout 代码存在三类相互作用的 action 编码差异；统一修复后 DreamSim 预测误差平均下降 42%，并改变部分 checkpoint 排名。
- **Coding 接口：**ActRosetta 检查归一化、编码和训练—推理契约，在信息足够时修复输入。
- **场景：**世界模型 CI、benchmark 审计、引擎插件版本升级验收。
- **成熟度 / 证据：**论文实测；控制成功率提升尚未证明。**高；必读。**

## 4. 数字人 / 虚拟形象能力进展

**生成与驱动：**本周期没有新的语音驱动头像、lip-sync 或全双工视频数字人。AvatarAnyone、Head Anything 的重点是把网络视频和少量照片变成后续可编辑的资产，而非直接生成最终表演。

**3D/4D 表示：**AvatarAnyone 的分层 mesh 比融合表面或纯 3DGS 更适合换装、碰撞和布料模拟；Head Anything 改善头部在多表情、多视角输入间的一致性。它们都更贴近传统 DCC 管线，但尚无公开生产级导出插件。

**实时交互：**MemHand 的有界事件记忆适合持续手势追踪，但论文没有证明端侧帧率。ShowNow 的低延迟生成能力可用作数字人的环境或镜头层，不能替代实时人脸表演。

**音视频与情感表达：**本周期暂无高质量新增。没有新的情绪准确性、多语言、打断对话或原生音视频数字人评测。

**工程部署：**当前最有价值的组合是“agent 生成资产规划 → mesh 优化 → Unreal/Blender/MuJoCo → 传统绑定与物理模拟”。AvatarAnyone 已展示引擎导入，但代码仍待发布；Head Anything、MemHand 同样不应标为已开源。

**安全与身份治理：**AvatarAnyone 使用公开人物视频，其补充材料讨论滥用风险，但未提供授权、撤销、水印或身份溯源机制。本周期没有新的肖像治理技术，商业使用仍必须单独获取人物、服装和视频素材授权。

## 5. 世界模型进展

- **架构与训练：**世界模型正在分层：ShowNow 负责多未来生成，SimPWM/CodeWAM 维护显式动力学，iWAM/Effect 表示降低“必须先生成完整视频”的成本。
- **可控与可玩：**ShowNow 把可玩性的指标从 FPS 推进到输入—显示延迟；Residual Guidance 解决运行中提示词变化被旧上下文压制的问题。
- **长时与物理一致性：**WorldInteract处理材质与接触，SimPWM处理对象状态，PSC-Gen处理物理事件顺序。它们仍分别覆盖局部问题，不能证明开放世界长时物理已解决。
- **空间表示：**MemHand维护手的世界尺度；SimPWM用点云和相机标定维护对象与机器人状态。显式空间状态正在成为视频生成器的外部真值层。
- **机器人、游戏与仿真：**ShowNow提供游戏运行时；SimPWM和iWAM面向机器人；CodeWAM面向驾驶。世界模型正从同一种架构分化为针对具体 action interface 的系统。
- **实时部署：**ShowNow已有单 H100 16 FPS 证据；iWAM试图用一次前向替代视频 rollout。除 ShowNow 外，大多数项目未披露端到端 P50/P95。
- **评测：**ActRosetta提醒，action 编码错误足以扭曲模型排名。今后的 benchmark 应同时发布 action schema、归一化参数、回放代码和版本哈希。

## 6. Coding × 新型互动作品

### 链路一：低延迟可玩视频

**玩家键盘/手柄 → ShowNow 提前生成八种候选未来 → 事件循环在 0.25 秒粒度提交分支 → 浏览器持续播放 → 生成式第一人称游戏。**

代码负责输入采样、候选分支、权威任务状态和网络同步；模型负责生成视觉未来；传统游戏逻辑负责生命值、库存和胜负。已有 ViZDoom 可运行证据，但任意游戏和组合动作仍未验证。

### 链路二：显式物理状态驱动的写实机器人世界

**机器人动作 → SimPWM/MuJoCo 更新对象点云与抓取状态 → 视频模型写实渲染 → 状态—画面一致性检查 → 训练或测试机器人策略。**

这条链路避免让视频模型同时承担物理真值和视觉表现。SimPWM 已开源，但完整写实渲染成本较高，软体物体仍受简化模拟限制。

### 链路三：材质互动装置

**触摸、拖拽或力传感器 → 代码转成速度增量/冲量 → WorldInteract 因果生成器执行材质行为 → WebGPU/LED/沉浸式屏幕显示。**

传统物理层负责接触与质量、恢复系数；生成模型负责布料、液体、软体的视觉响应。这是基于论文接口的本报告推断，尚无 SDK。

### 链路四：agent 驱动的数字人资产工厂

**用户视频 → agent 识别服装结构并生成优化计划 → AvatarAnyone 输出分层 mesh → Blender/Unreal 脚本绑定、换装和布料模拟 → 玩家分身或虚拟试衣。**

agent 负责因人而异的管线配置，优化器负责几何，传统引擎负责实时动画与碰撞。目前只有 demo，需等待代码和许可证。

### 链路五：代码与模型共同评估驾驶计划

**规划器提出候选轨迹 → 可执行代码计算车辆状态演化 → 学习模型预测交通场景后果 → 评分器选择计划 → 下一周期继承执行上下文。**

CodeWAM 表明 coding 不仅是工具调用，也可以成为世界表示本身。现有证据来自 NAVSIM benchmark，不能直接外推到量产车辆。

### 链路六：运行中可改写的互动叙事

**剧情状态机触发新事件 → Residual Guidance 抵消旧提示词惯性 → 流式视频保持镜头连续 → 用户继续选择分支。**

代码负责事件顺序、角色状态和审核；模型负责视觉过渡；传统音频、字幕和 UI 层负责同步。Residual Guidance 已有代码，完整互动电影属于组合推断。

## 9. 系统架构与技术趋势判断

明显升温的是“显式状态＋生成渲染”的混合架构，以及将输入延迟、action schema 和候选未来调度视为一等运行时问题。单纯报告 FPS 已不足以说明可交互性；ShowNow 的主要贡献正是把吞吐、按键到画面延迟和候选准备成本分别测量。

正在形成的复用架构是：

**权威状态/可执行代码 → 动作候选与物理模拟 → 世界模型生成或预测 → 运行时提交分支 → 一致性审计 → 用户或设备反馈。**

数字人侧则呈现：

**agent 解析人物结构 → 生成因人而异的资产计划 → 分层 mesh 优化 → DCC/引擎绑定 → 传统物理和动画系统实时执行。**

生成模型负责开放式视觉、材质和外观补全；代码负责实体 ID、物理参数、事件顺序、权限、候选分支和失败恢复；传统引擎负责权威碰撞、网络同步、确定性规则与安全边界。

仍未解决的问题包括多用户一致状态、组合动作爆炸、分钟级视觉漂移、软体接触真值、世界模型的不确定性校准、低成本多租户 serving、数字人授权与撤销，以及 benchmark 的 action 编码复现。

需要降级处理的说法包括：把 ShowNow 的 ViZDoom 八动作写成通用游戏引擎；把 SimPWM 的规则对象代理写成通用物理模拟；把 AvatarAnyone 项目页写成已开源生产工具；把 PSC-Gen 的 VLM 自检写成物理正确性证明；把 NAVSIM 成绩写成道路规模部署证据。

## 10. 论文精读候选

1. [ShowNow](https://arxiv.org/abs/2611.34693)：重点读 speculative multi-future、shared-history tree、single-latent commitment、E1 延迟 protocol 和 E3 长时质量。复现风险是 H100/FA3 依赖及只支持 ViZDoom 离散动作。
2. [SimPWM](https://arxiv.org/abs/2611.32786)：重点读显式对象状态、freeze-object 反事实测试及不同底模对代理的服从差异。复现风险是完整视频模型路径成本高、软体物体模拟过于简化。
3. [WorldInteract](https://arxiv.org/abs/2611.34730)：重点读速度增量接口、材质行为/接触响应解耦和 Material-Aware RL。与纯 action-conditioned 视频的差异是把可验证物理计算放到生成器外部；风险是代码未公开。
4. [CodeWAM](https://arxiv.org/abs/2611.32483)：重点读 executable ego dynamics、候选执行上下文及跨 benchmark 迁移。风险是代码可执行性、闭环频率和真车结果尚不透明。
5. [AvatarAnyone](https://arxiv.org/abs/2611.30777)：重点读 agent questionnaire、layer plan、初始化门禁和联合优化。与融合 mesh/3DGS 的差异是服装层可独立模拟；风险是代码延期、人物授权和复杂服饰拓扑。

## 11. 下周跟踪与可行动建议

需要持续追踪：

1. ShowNow 能否扩展到连续鼠标、手柄轴和组合动作，而不造成候选数量指数增长。
2. ShowNow 在 5–10 分钟连续游玩中的状态、场景与角色一致性曲线。
3. WorldInteract 是否发布代码、权重，以及与 Unity/Unreal 物理冲量接口的映射。
4. SimPWM 在透明、形变、液体和多物体接触上的状态—视频一致性。
5. AvatarAnyone、Head Anything、MemHand 的代码、许可证和商业使用范围。
6. iWAM 的真实端到端控制延迟及相对生成式 WAM 的算力下降比例。
7. ActRosetta 能否扩展为通用 action-schema CI 工具，并覆盖游戏、驾驶和机器人接口。
8. Residual Guidance 在多人角色、对象增删及镜头切换时是否出现身份或背景断裂。

本周建议小实验：

1. **可玩视频延迟审计。**目标：区分生成 FPS 与真实操作延迟。组件：ShowNow、浏览器 demo、键盘事件时间戳和 240 FPS 摄像。难点：GPU预热与显示刷新同步。成功判据：获得 P50/P95/P99 按键—像素变化曲线，并复现约 208 ms 中位水平。
2. **显式状态服从测试。**目标：验证视频是否真的遵循模拟器，而非仅根据机械臂姿态猜测。组件：SimPWM bottle/rope 示例、freeze-object 修改和帧级对象跟踪。难点：对齐模拟状态与生成帧。成功判据：冻结对象后，至少能量化三种底模的错误移动率。
3. **流式剧情切换实验。**目标：验证 Residual Guidance 对互动叙事的价值。组件：LongLive 或 Causal Forcing、三段事件脚本、RG。难点：同时评价新指令服从和旧角色连续性。成功判据：切换服从率显著提升，人物相似度和镜头连续性不明显下降。
4. **分层数字人资产契约设计。**目标：在 AvatarAnyone 代码发布前定义可落地的引擎接口。组件：SMPL-X、服装 mesh 样例、Blender、Unreal、JSON schema。难点：层间碰撞、材质和骨骼映射。成功判据：同一角色可脚本化替换两套服装并完成动作、布料和碰撞回归测试。
