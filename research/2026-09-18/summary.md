# 数字人、世界模型与互动作品研究日报：2026-09-18

检索窗口：2026-09-12 至 2026-09-18。发布日期以 arXiv 提交记录、官方 GitHub、产品技术博客为准；已与 9 月 14、16、17 日日报去重。

## 1. 本日摘要

本周期最强信号不是视频画质再次提升，而是世界模型开始补齐“持续运行的软件系统”所需的执行、恢复和服务层。StrucPhysVideo 从数据标注端显式描述接触、材质、形变与状态转换，再把模型扩展为接受机器人末端动作的四步增量视频世界模型，说明物理监督正从宽泛 caption 转向代码可构造的事件结构。

WAVE-Go 和 FaRe 分别处理两种在线失效：前者根据风险动态缩短或取消尚未执行的动作前缀，后者在失败污染自回归历史后，重建 KV cache 的可靠前缀并比较“继续、回退、重置”三种未来。两者都表明工业系统不能把模型一次生成的长动作序列视为不可撤销计划。

vLLM-Omni 新的世界模型实时推理路线图，则把长连接会话、session-owned state、流式 VAE、实时交互和多会话压测提升为通用 serving 契约；但当前单 H200 约 5 FPS，距离其定义的约 12 FPS 交互门槛仍有明显差距。

数字人生成本体本日没有新的高质量 talking-head、3D/4D avatar 或身份保持论文。新增主要在支撑层：GrainSpeech 将声学模型压到 26.48 万参数并在 MCU 上实现 17.9 倍实时 Mel 生成；Runway 则公开了流式视频的同步审核结构，平均审核延迟低于 0.5 秒，并承认仍可能出现短暂违规画面暴露。

DecoGS 的静态—动态分区更新和 vidax 的 TPU/JAX 视频生成运行时，分别补齐持续空间重建与非 CUDA 推理路径。总体趋势是：代码负责权威状态、风险预算、缓存生命周期和验收；生成模型负责预测与表现；传统引擎、控制器和审核器负责硬约束。新增证据仍以论文作者实测和官方技术主张为主，尚无新的大规模客户 SLA、长期在线成本或第三方复核。

## 3. 最值得关注的 9 个进展

### 1. vLLM-Omni 世界模型实时推理路线图

- **类型 / 日期 / 主线：**GitHub RFC、运行时；截至 2026-09-18 持续更新；世界模型、Coding、实时基础设施。
- **官方链接：**[实时推理 RFC](https://github.com/vllm-project/vllm-omni/issues/7074)、[Apache-2.0 仓库](https://github.com/vllm-project/vllm-omni)。
- **相对上期：**新增。此前日报报道具体模型，本次新增是跨 LingBot World、MiniMax H3、ABot、Echo-WM 的统一 serving 契约。
- **核心贡献：**将世界模型改造成“一次请求即一个长会话”：运行时拥有 session、调度、chunk 时序与流式输出，模型只管理条件转换和自回归状态；支持中途 prompt/camera interaction、session-affinity、流式 VAE 和多会话压测。
- **工程现状：**stepwise execution、通用交互框架、session-owned streaming VAE、文本编码复用等已合并；camera interaction、会话亲和路由和多会话 load harness 尚未完成。
- **关键指标：**RFC 报告 LingBot 当前单 H200 约 5 FPS，目标是最多四张 H200 达到至少 12 FPS，并稳定 rollout 约两分钟；这些是维护者测量与发布门槛，不是最终 SLA。
- **互动场景：**可玩视频、生成式展馆、实时背景、持续数字人场景、互动电影。
- **成熟度 / 证据：**开源运行时、部分功能已合并；维护者工程测量。重要性高，必读。

### 2. StrucPhysVideo：从“描述画面”转向“标注物理事件并接受动作”

- **类型 / 日期 / 主线：**论文、项目 demo；2026-09-16；世界模型。
- **官方链接：**[论文](https://arxiv.org/abs/2609.18430)、[项目页](https://westlakedi-awomo.github.io/StrucPhysVideo-Page/)。
- **相对上期：**新增。
- **核心贡献：**数据流水线分离相机运动与物体行为，并结构化描述物体、材料、接触、形变和状态转换；TI2V 使用稀疏 MoE 和物理课程训练，IA2V 再加入机器人末端动作、因果自回归生成和四步蒸馏。
- **关键结果：**作者报告 Physics-IQ Verified 得分 45.5%，比其复现的 Cosmos3-Super-Image2Video 高 2.8 个百分点。
- **Coding 接口：**机器人末端命令可成为显式 action condition；物理 caption schema 可由仿真器、日志解析器或 coding agent 自动生成。
- **互动场景：**机械臂后果预览、实验教学、物理互动沙盒、合成机器人训练数据。
- **成熟度 / 证据：**论文和项目 demo；未核验到开放代码、权重或端到端延迟。作者实测，重要性高，必读。

### 3. WAVE-Go：世界模型计划必须能被中断

- **类型 / 日期 / 主线：**论文、GitHub、实机/仿真研究；2026-09-16；世界模型、机器人运行时。
- **官方链接：**[论文](https://arxiv.org/abs/2609.18193)、[代码与运行记录](https://github.com/vigorlee/wave-go)。
- **相对上期：**新增。
- **核心贡献：**将世界—动作预测与命令执行分开。执行器在风险预算下选择动作前缀，新观测证明计划失效时取消待执行命令；轮式、腿式和姿态切换还需通过净空、稳定性和任务证据门。
- **关键结果：**作者报告 ID/OOD 成功率为 74.1%/63.3%，比最强基线高 4.7/7.7 个百分点；碰撞由每百米 4.4 次降至 2.9 次。固定四命令对照下，成功率提高 4.0 个百分点、重规划频率下降 51.2%。
- **Coding 接口：**适合实现为 `world-action proposal → risk-bounded prefix → interruptible queue → Nav2/controller`。
- **互动场景：**轮足机器人导览、仓储巡检、可打断自动驾驶或舞台机器人。
- **成熟度 / 证据：**公开仓库含配置、控制桥、测试和证据文件，但未见明确许可证；作者实验，尚非认证产品。重要性高，必读。

### 4. FaRe：失败后重写世界模型的因果历史

- **类型 / 日期 / 主线：**论文、恢复框架；2026-09-16；世界模型、运行时可靠性。
- **官方链接：**[论文](https://arxiv.org/abs/2609.18016)。
- **相对上期：**新增。
- **核心贡献：**发现自回归 WAM 的错误不仅影响当前动作，还会污染持续 KV cache。FaRe 用进度模型检测持续停滞，检索与当前物理状态相容的历史锚点，重放可靠前缀，再比较完整历史、恢复前缀和完全重置三种 continuation。
- **Coding 接口：**KV cache 不再是黑盒优化，而成为可检查、可分支、可回滚的运行时状态；verifier 依据任务进度、视觉连续性和动作有效性选择分支。
- **互动场景：**机器人失败恢复；也可迁移到生成式 NPC 卡死、互动电影剧情漂移和长期数字人会话恢复。
- **成熟度 / 证据：**RoboTwin 2.0 和双臂 SO-101 研究实验；无公开代码入口，论文未在摘要中给出完整增益数字。作者实测，重要性高，必读。

### 5. Runway 实时视频审核：流式输出需要同步安全层

- **类型 / 日期 / 主线：**官方安全技术博客、生产运行时；2026-09-16；数字人安全、互动生成。
- **官方链接：**[Moderation in Real Time](https://runway.com/news/safety/moderation-in-real-time)。
- **相对上期：**新增；不是新生成模型，而是实时模型发布前的安全架构披露。
- **核心贡献：**输入先审；生成时持续抽取视频帧同步审核，发现违规即停止流；分享或下载前再根据完整上下文终审；输出携带 C2PA provenance。
- **关键指标：**Runway 称使用基于 Gemma-4-26B-A4B-it 的 CoPE-B LoRA 后，平均审核时间低于 0.5 秒。公司同时承认边界案例仍可能在阻断前短暂显示违规内容。
- **Coding 接口：**可实现为 WebRTC/media stream 的旁路分类器和 kill switch，配合事件日志、账号处罚与最终资产门禁。
- **成熟度 / 证据：**官方生产设计与内部测试主张；缺少公开 benchmark、误报率和第三方审计。重要性高，必读。

### 6. DecoGS：只更新真正变化的 3D Gaussian 区域

- **类型 / 日期 / 主线：**论文；2026-09-15；3D/4D 表示、空间运行时。
- **官方链接：**[论文](https://arxiv.org/abs/2609.17230)。
- **相对上期：**窗口内漏项补录。
- **核心贡献：**流式视频进入时，不再逐帧更新全部 Gaussian，而是通过梯度门控和可见性过滤，集中优化发生运动或光度变化的时空区域；静态区保持稳定，减少闪烁与漂移。
- **关键结果：**作者报告 N3DV/MeetRoom 为 34.55/31.60 dB PSNR，渲染 261 FPS，相对最佳既有方法时间闪烁降低约 70 倍。
- **Coding 接口：**适合接相机流、SLAM pose 和动态区域 mask，作为 Unity/Unreal/WebXR 的自由视角背景或数字孪生场景层。
- **成熟度 / 证据：**论文实测；未核验到代码，261 FPS 是渲染速度，不代表在线训练、采集到显示的完整延迟。重要性中高，可读。

### 7. vidax：为视频生成补上 TPU/JAX 执行路径

- **类型 / 日期 / 主线：**论文、推理框架；2026-09-16；支撑基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2609.18077)。
- **相对上期：**新增。
- **核心贡献：**提供 JAX/Flax 视频推理引擎和 PyTorch→JAX 权重翻译，覆盖 DiT、omnimodal mixture-of-transformers、3D VAE、文本编码器和 sampler；在单一 JAX mesh 上组合 tensor parallel 与 Ulysses sequence parallel，并支持逐层权重卸载。
- **Coding 接口：**目标是让现有视频或世界模型 checkpoint 在 TPU pod 上部署，无需在执行路径保留 PyTorch。
- **场景：**长序列视频、世界模型批量 serving、跨 CUDA/TPU 的容量调度。
- **成熟度 / 证据：**论文声称开源并报告 TPU v4-8 编译、延迟和显存实验，但截至检索时 arXiv 未给出代码仓库链接；应视为“代码待核验”，而非已可复现。重要性中高，可读。

### 8. GrainSpeech：MCU 级声学模型为端侧角色发声降本

- **类型 / 日期 / 主线：**论文、GitHub、checkpoint、demo；2026-09-16；数字人音频基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2609.18856)、[Apache-2.0 代码](https://github.com/lab-emi/GrainSpeech)。
- **相对上期：**新增。
- **核心贡献：**固定感受野卷积编码器将上下文限制在有效的音素范围；Mel 专用的局部梯度—方差损失缓解小模型过度平滑。
- **关键结果：**26.48 万参数，在 STM32H747XI MCU 上达到 17.9 倍实时 Mel 生成；作者称 UTMOS 与大得多的模型相当。
- **Coding 接口：**提供 CPU/GPU CLI、训练脚本、checkpoint、HiFi-GAN 和浏览器试听；普通英文文本可经 G2P 转为音素。
- **互动场景：**离线导览角色、玩具、车载助手、隐私敏感数字员工的本地语音前端。
- **成熟度 / 证据：**已开源可运行；17.9 倍实时只对应 Mel 声学模型，不等于完整文本处理、vocoder、avatar 渲染的端到端延迟。重要性中，可读。

- **官方链接：**[论文](https://arxiv.org/abs/2609.16074)、[MIT 许可资源库](https://github.com/RCL-Robotics/Awesome-World-Action-Models)。

- **Coding 接口：**仓库提供机器可读论文目录、研究地图、分类审查和阅读报告，可转化为内部选型表与 benchmark 清单。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**本日没有新的高质量 talking-head、lip-sync、单图身份建模或全身数字人模型。搜索结果曾将 HeyGen Avatar V 标为 9 月 17 日更新，但[官方页面实际显示 2026-05-04](https://www-heygen.com/blog/announcing-avatar-v)，因此未纳入本周期新增。
- **3D/4D 表示：**没有数字人专用新增。DecoGS 可用于持续场景与多人自由视角采集，但没有人体骨骼、表情或身份控制，不能直接当作 avatar 方法。
- **实时交互：**新增集中在旁路系统：流式审核、会话状态、语音声学模型与断流控制。它们提升生产可用性，但不代表人物动作或表情质量升级。
- **音视频与情感：**GrainSpeech 证明低算力设备可生成声学特征；其数据仅为 LJSpeech 单说话人英语，没有多语言、情感强度、声音克隆或 turn-taking 证据。
- **工程部署：**现阶段更现实的架构仍是 `VAD/RTC → 对话 agent → 流式或端侧 TTS → avatar renderer → 同步审核 → WebRTC`。世界模型适合承担环境和后果预测，不宜直接保存业务权威状态。
- **安全与身份治理：**Runway 给出实时内容审核和 C2PA 设计，但未解决肖像授权、声音授权和身份撤回。生成平台仍需独立的授权账本、人物白名单、水印及人工复核。

结论：数字人主线本日是“配套运行时变强”，而不是“人物生成能力跃迁”。

## 5. 世界模型进展

- **架构与训练：**StrucPhysVideo 说明物理能力不能只依赖通用视频规模，接触、材料、形变和状态变化应进入数据 schema 与课程训练。
- **可控 / 可玩生成：**动作条件正在从模糊文本变为机器人末端命令、相机事件和结构化 interaction message；但 StrucPhysVideo 尚无可调用 SDK。
- **长时与物理一致性：**FaRe 不假设历史永远正确，而是把 history cache 变成可回退状态；这是比单纯扩大 context window 更接近事务式运行时的方案。
- **空间表示：**DecoGS 通过静态—动态区域分离降低持续重建的闪烁；它适合环境记忆层，不是完整物理状态数据库。
- **机器人 / 仿真：**WAVE-Go 表明动作 chunk 必须可取消，且高层世界预测不能取代 Nav2、步态控制和姿态安全检查。
- **实时部署：**vLLM-Omni 已开始定义统一长会话和流式解码接口，但当前 5 FPS 与目标 12 FPS 仍有距离；“支持实时模型”不等于“达到互动服务门槛”。
- **评测：**视频物理 benchmark、导航成功率、碰撞率、恢复率和 serving FPS 正在汇合；仍缺统一的端到端 p95、每会话 GPU 成本、连续运行故障率和多用户隔离指标。

## 6. Coding × 新型互动作品

### 链路一：玩家事件 → 权威状态机 → 长连接世界模型 → 流式画面

Unity、Unreal、Godot 或 Web 服务维护玩家位置、库存、碰撞和剧情；事件转换为 prompt、相机或结构化 interaction；vLLM-Omni 长会话持有自回归 KV 与解码状态，再经 WebSocket 输出视频。

代码负责权威状态、session、重试和回滚；模型负责画面、音频与环境反应；传统引擎负责确定性规则。vLLM-Omni 已有部分运行时代码，但 camera interaction、12 FPS 目标和多会话压测尚未完成。

### 链路二：机器人动作 → 物理世界 rollout → 风险前缀 → 可中断执行

StrucPhysVideo 根据末端动作生成候选未来；WAVE-Go 根据累计失败预算只提交安全长度的动作前缀；新观测使计划失效时，执行器取消剩余命令并重新规划。

这能形成机器人训练模拟器、工业操作预演和可解释导航界面。论文已有实验依据；把 StrucPhysVideo 与 WAVE-Go 直接组合属于**本报告推断**。

### 链路三：失败检测 → KV 历史分支 → verifier → 恢复运行

进度模型检测角色、机器人或生成世界持续无进展；运行时构造 `continue/prefix-reset/full-reset` 三个历史分支；verifier 比较任务进度、视觉连续性和动作有效性，只提交最优分支。

代码负责 checkpoint、cache replay 和分支选择；生成模型负责重新想象未来。FaRe 已在机器人研究中验证；迁移到生成 NPC 卡死恢复属于**本报告推断**。

### 链路四：相机流 → 动态区域检测 → 增量 3DGS → 自由视角互动空间

摄像头、SLAM 和事件系统提供 pose；DecoGS 只更新发生运动或光度变化的 Gaussian；WebXR/Unity 根据用户视角渲染。可构建实时展厅数字孪生、体育自由视角回放和远程协作空间。

已有论文速度与质量证据，但尚无公开 SDK，也未披露完整采集—优化—显示延迟。

### 链路五：端侧文本 → GrainSpeech → 本地音频 → 数字人表演

业务 agent 输出短句和情绪标签；GrainSpeech 在端侧生成 Mel，HiFi-GAN 生成语音；avatar renderer 读取音频或音素驱动嘴形；云端只处理高层推理。

代码负责文本队列、打断、缓存和设备降级；语音模型负责声学输出；avatar 模型负责表演。GrainSpeech 可复现，但多语言、声音克隆和音画端到端同步仍需另建。

### 链路六：实时生成 → 低延迟旁路审核 → 断流与最终发布门

流媒体同时进入显示通道和审核通道；分类器触发 kill switch；完整视频在下载或分享前再次审核并写入 C2PA。适用于实时数字人、直播电商、互动电影和生成式品牌活动。

Runway 提供了生产设计证据，也明确暴露窗口不能完全归零。因此产品还需缓冲帧、年龄分级、申诉与人工升级流程。

## 9. 系统架构与技术趋势判断

**明显升温：**

1. **失败恢复成为一级能力。**世界模型不再只展示成功 rollout，而开始处理动作失效、历史污染和重新规划。
2. **运行时拥有状态。**session、KV、VAE decode、交互队列与回滚逐步从应用侧脚本进入 serving engine。
3. **动作 chunk 可撤销。**机器人和互动系统都需要短前缀、反馈检查和取消语义。
4. **结构化物理监督。**对象、材料、接触、形变和状态转换比通用视频 caption 更适合训练可行动世界模型。
5. **实时安全旁路。**流生成无法等待成片审核，必须支持同步分类、断流、最终复核和 provenance。

**降温或被重新审视：**

- 单纯扩大上下文不能解决被错误执行历史污染的问题；
- “生成速度接近视频时长”不足以证明可交互，仍需首帧、输入到显示 p95 和取消响应时间；
- 高渲染 FPS 不等于在线重建或多人服务吞吐；
- 世界模型输出视觉未来，不等于拥有权威物理状态；
- 产品博客中的“实时”和“身份一致”若无日期、benchmark 或 SDK 更新，不应当作研究新增。

**逐渐稳定的复用架构：**

`用户/传感器事件 → 权威状态与动作协议 → 世界模型生成候选 → 风险前缀或历史分支 → verifier/审核器 → 引擎或控制器执行 → 新观测 → 状态提交、取消或回滚`

数字人可以作为该架构的角色表现层，3DGS 作为空间观察层，语音模型作为端侧输出层；三者不应替代业务数据库、物理引擎或安全控制器。

**仍未解决：**

- 长会话世界模型的多用户隔离、显存碎片和 session 迁移；
- 失败恢复 verifier 自身误判时如何安全降级；
- 物理 benchmark 提升能否转化为真实控制成功率；
- 端到端音视频打断与恢复是否能稳定低于人类可感知阈值；
- 数字人肖像、声音授权、撤回与跨平台 provenance；
- 生产系统的单位会话成本、p95/p99、连续运行时间和人工接管率。

## 10. 论文精读候选

1. [StrucPhysVideo](https://arxiv.org/abs/2609.18430)：重点读数据清洗与结构化 caption、物理课程训练、TI2V→IA2V 的 action conditioning 和四步蒸馏。差异在于把物理数据工程与可执行动作统一起来；风险是代码与真实控制结果缺失。
2. [FaRe](https://arxiv.org/abs/2609.18016)：重点读 recovery trigger、历史锚点检索、KV cache 重建和三假设 verifier。差异在于把“过去”也纳入 test-time scaling；风险是额外推理成本和进度模型误差。
3. [WAVE-Go](https://arxiv.org/abs/2609.18193)：重点读条件风险预算、动作前缀选择、姿态/模式切换证据门和 cancellation ablation。差异在于执行层可中断，而不是只优化预测模型；风险是平台特定组件较多。
4. [DecoGS](https://arxiv.org/abs/2609.17230)：重点读动态区域判定、gradient gating、Gaussian 管理和 temporal flicker 指标。差异在于减少静态区域的无效更新；风险是缺少公共实现和完整在线延迟。
5. [vidax](https://arxiv.org/abs/2609.18077)：重点读 PyTorch→JAX 权重映射、TP/Ulysses mesh、flash attention、offload 和数值错误案例。差异在于 TPU 原生视频推理；风险是仓库入口尚未核验。

## 11. 下周跟踪与可行动建议

### 继续跟踪

1. vLLM-Omni camera interaction、session-affinity 和多会话 load harness 是否合并。
2. LingBot 从单 H200 约 5 FPS 到 12 FPS 的优化是否给出可复现 profile。
3. StrucPhysVideo 是否发布数据 schema、训练代码、IA2V 权重及动作延迟。
4. FaRe 是否开放代码，以及 recovery 触发的额外计算量和误触发率。
5. WAVE-Go 仓库是否补充许可证、论文对应实现和完整实机日志。
6. DecoGS 是否开放在线训练代码，并披露优化更新频率而不只是渲染 FPS。
7. vidax 是否发布仓库、支持模型清单和 TPU 成本对照。
8. Runway 实时审核是否公开按类别的召回率、误报率、p95 延迟和未成年人场景测试。

### 本周可动手的小实验

1. **可取消动作队列。**  
   目标：验证世界模型或 agent 输出的长计划能否安全中断。组件：仿真机器人、动作 chunk、观测差异检测器、取消队列。难点：避免取消后旧命令继续下发。成功判据：动态障碍出现后在一个控制周期内停止旧计划，且碰撞率低于固定 chunk。

2. **生成世界历史回滚。**  
   目标：把 FaRe 思路迁移到互动场景。组件：任一自回归视频/世界模型、KV checkpoint、三分支生成、简单视觉与状态 verifier。难点：重放历史时的位置编码和 cache 一致性。成功判据：人为注入错误事件后，prefix recovery 比继续生成和完全重置更好地保持身份与任务状态。

3. **数字人端侧语音延迟拆解。**  
   目标：判断 GrainSpeech 是否能减少真实交互等待。组件：GrainSpeech、HiFi-GAN、现有 avatar renderer、VAD。难点：论文速度只覆盖 Mel。成功判据：分别记录 G2P、声学模型、vocoder、嘴形驱动和首帧时间，端到端 p95 较现有方案降低至少 20%，且主观音质可接受。

4. **实时审核暴露窗口测试。**  
   目标：量化流式数字人的安全延迟。组件：WebRTC 测试流、帧级分类器、100—300 ms 可配置缓冲、kill switch、审计日志。难点：降低暴露时间会增加交互延迟。成功判据：高风险测试流在播放前或 300 ms 内被阻断，正常内容误断率可接受，并能完整记录触发帧与规则版本。
