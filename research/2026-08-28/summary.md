# 数字人、世界模型与互动作品研究日报：2026-08-28

检索窗口：2026-08-22 至 2026-08-28。

## 1. 本日摘要

本周期最重要的变化不是更大的视频模型，而是“代码持有世界状态、生成模型负责视觉实现”开始成为明确架构。Code World Model 让 coding agent 生成可执行状态更新，再编译为时空代理视频驱动 MiniMax-H3 渲染，直接回应了纯像素世界模型难以维护规则和永久后果的问题。数字人方向没有新的高质量人像生成主模型，但 TaoLive v3 披露了已经接入淘宝直播数字人服务的 Harness-Aware Agent：Skills、Hooks、工具 schema 和策略提示可以独立于模型更新，并有在线 A/B 商业指标信号。VoiceMem 则把信息记忆、情绪归因和人格记忆放入语音交互的并行流式链路，作者报告检索耗时 134 ms，为陪伴角色和数字员工补齐长期关系层。机器人世界模型继续从“生成未来视频”转向更紧凑的任务接口：Zero-WAM用人类示范视频临时指定未见任务，LAWA用 latent intention保留未来想象而省去视频解码。VBVR-Pro和FIRM-Video分别把确定性规则验证、逐项视频检查引入训练和评测，说明生成世界的测试正在从整体VLM打分转向可诊断断言。工业证据强弱分化明显：TaoLive有生产部署和A/B信号，但效果量未披露；其余项目主要仍是论文实测、开源组件或待发布代码。整体趋势是代码、状态机、工具系统和验证器成为权威层，视频模型逐步退回其更擅长的外观、动作和感知渲染层。

## 3. 最值得关注的 8 个进展

### 1. Code World Model：Coding Agent成为可执行“世界大脑”

- **类型 / 主线：** 论文、GitHub、LoRA、示例；世界模型 × Coding。
- **官方链接：** [论文](https://arxiv.org/abs/2608.25927)、[项目页](https://buaacyw.github.io/cwm/)、[Apache-2.0仓库](https://github.com/buaacyw/code-world-model)。
- **发布或更新时间：** 论文 2026-08-26；代码、LoRA和40个紧凑示例随项目开放。
- **相对上期的新变化：** 首次收录，是昨日之后最直接回应 Coding × 世界模型主题的新发布。
- **核心贡献：** coding agent把用户事件转为可执行代码，更新实体、布局和规则状态；代码再生成逐帧语义区域、人物 primitive和对象框等proxy，编译为proxy video并驱动微调后的MiniMax-H3完成视觉实现。游戏数据可直接读取运行时标注，真实视频则通过3D重建和对象标注构造配对数据。[项目说明](https://buaacyw.github.io/cwm/)
- **Coding接口：** JSON配置、NPZ条件、`validate/prepare/generate`命令和可修改proxy通道；代码可通过局部程序修改增删约束。
- **互动作品 / 工业场景：** 有持久库存和剧情后果的生成式游戏、互动电影、品牌世界、仿真可视化。
- **成熟度 / 证据：** 已开源研究原型；论文实测＋官方代码。仓库可复现视觉生成，但通用coding agent、多人服务器和生产状态存储仍需开发。
- **重要性 / 阅读：** 高 / 必读。

### 2. TaoLive HAT v3：数字人从固定Prompt转向可演进Harness

- **类型 / 主线：** 技术报告、生产部署；数字人 × Coding × 产业案例。
- **官方链接：** [arXiv v3](https://arxiv.org/abs/2608.15763)。
- **更新日期：** v1为8月16日，v2为8月22日，v3于2026-08-26提交；本次因窗口内重大修订和完整部署证据纳入。
- **相对上期的新变化：** 最近日报未收录；首次覆盖其Harness、延迟与线上A/B结果。
- **核心贡献：** Harness-Aware Training对Skill名称与内容、工具schema、prompt结构和Hook函数做保持任务不变的扰动，使小模型在运行时工具经常变化时仍能稳定调用。训练由HSA-SFT、通用on-policy蒸馏和HSA-RL组成。
- **Coding接口：** Skills、Hooks、工具调用schema和策略prompt可以独立于模型权重升级；适合接商品检索、优惠策略、评论互动和风控工具。
- **互动作品 / 工业场景：** 实时数字人主播、销售Agent、企业数字员工。作者报告单张H20上P50/P95为3.4/8.1秒，并称已部署于淘宝直播数字人服务、GMV和商品页访问在线A/B为正，但未披露提升幅度。[论文摘要与版本记录](https://arxiv.org/abs/2608.15763)
- **成熟度 / 证据：** 生产部署；官方声称，尚无独立复核。P95 8.1秒对自由对话仍偏慢。
- **重要性 / 阅读：** 高 / 必读。

### 3. Zero-WAM：用人类视频给机器人“临时编程”

- **类型 / 主线：** 论文、项目页、GitHub占位；世界模型 × 机器人。
- **官方链接：** [论文v2](https://arxiv.org/abs/2608.26103)、[项目页](https://robbyant-research.github.io/Zero-WAM/)、[仓库](https://github.com/robbyant-research/Zero-WAM)。
- **发布或更新时间：** v1为8月26日，v2为2026-08-27。
- **相对上期的新变化：** 首次收录。
- **核心贡献：** 单个因果video-action policy同时接受语言或人类示范视频，把演示视为in-context任务规格。HumanGen由机器人轨迹自动生成74.2K个人类—机器人配对，覆盖8.6K任务；IFP目标迫使模型读取演示中的长期状态变化。
- **Coding接口：** 部署端可把检索到或现场录制的人类视频作为任务参数；项目的数据流水线使用VLM解析、首帧编辑、视频生成和语义/物理过滤。
- **互动作品 / 工业场景：** 示范即编程的机器人培训、工人录制一次后由机器人复现、视觉化具身NPC技能教学。
- **成熟度 / 证据：** 论文原型。作者报告RoboTwin七项未见任务平均成功率46.95%，较最强视频动作基线高29.50个百分点；代码、模型和数据计划在9月15日前发布，当前仓库主要是说明材料。
- **重要性 / 阅读：** 高 / 必读。

### 4. VoiceMem：流式信息、情绪与人格记忆

- **类型 / 主线：** 论文、GitHub、模型、dataset；数字人支撑基础设施。
- **官方链接：** [论文](https://arxiv.org/abs/2608.26005)、[Apache-2.0代码](https://github.com/xzf-thu/VoiceMem)、[模型](https://huggingface.co/zhifeixie/VoiceMem_MF_Qwen3_6_35B_A3B_Qlora)、[ChatMem-400K](https://huggingface.co/datasets/zhifeixie/VoiceMem-ChatMem400k)。
- **发布或更新时间：** 论文8月26日；代码v0.0.1于2026-08-27发布。
- **相对上期的新变化：** 首次收录。
- **核心贡献：** “左脑”维护事实信息，“右脑”维护短长期情绪归因和persona节点；记忆I/O与语音流并行执行，后端可替换。作者报告检索134 ms、三项persona benchmark综合提升4.29点。
- **Coding接口：** `pip install voicemem`，内置ASR、声纹、情绪、embedding和可替换memory backend；另提供微调与评测目录。
- **互动作品 / 工业场景：** 有长期关系的虚拟陪伴、能记住客户偏好和情绪的数字员工、连续剧情角色。
- **成熟度 / 证据：** 已开源、作者称有真实部署；尚缺独立延迟和隐私审计。
- **重要性 / 阅读：** 高 / 必读。

### 5. LAWA：用latent intention代替未来视频解码

- **类型 / 主线：** 论文、项目页；世界动作模型。
- **官方链接：** [论文](https://arxiv.org/abs/2608.24882)、[项目页](https://getterupper.github.io/LAWA/)。
- **发布日期：** 2026-08-25。
- **相对上期的新变化：** 首次收录；补齐近期“保留世界想象还是完全删除视频分支”的关键分支。
- **核心贡献：** 离散tokenizer学习操作相关意图码，连续latent state与可执行action chunk联合去噪；推理时保留未来意图但不生成未来RGB。作者报告相对匹配的Joint-WAM降低42.9%推理时延，同时在RoboCasa少样本和全数据设置达到65.6%与80.8%成功率。
- **Coding接口：** latent intention可作为策略服务内部状态，经安全控制器转为动作块；当前代码和模型仍标记为待发布。
- **互动作品 / 工业场景：** 后台物理角色决策、机器人控制、无需向用户展示“想象视频”的实时Agent。
- **成熟度 / 证据：** 论文实测、研究原型。
- **重要性 / 阅读：** 中高 / 必读。

### 6. VBVR-Pro：给视觉世界模型加入确定性验证器

- **类型 / 主线：** benchmark、dataset、训练代码、reward scorer；世界模型评测。
- **官方链接：** [论文](https://arxiv.org/abs/2608.26105)、[训练代码](https://github.com/Video-Reason/VBVR-Pro)、[评测代码](https://github.com/Video-Reason/VBVR-Pro-Bench)。
- **发布日期：** 2026-08-26。
- **相对上期的新变化：** 首次收录。
- **核心贡献：** 300个程序生成任务和任务特定确定性scorer，把视觉生成当作推理轨迹；对30余种图像、视频和交错式生成器进行控制实验。作者发现视频更适合持久时空状态，交错生成成本更低。
- **Coding接口：** 程序生成任务、规则型reward、训练与评测仓库，可作为世界模型RL和CI的断言层。
- **互动作品 / 工业场景：** 自动验证拼图、空间操作、机器人视觉推演和游戏状态变化。
- **成熟度 / 证据：** 全资源开放的研究测试床；不能直接证明开放世界物理正确。
- **重要性 / 阅读：** 中高 / 必读。

### 7. FIRM-Video：先逐项核验，再给生成视频打分

- **类型 / 主线：** reward model、benchmark、dataset；支撑基础设施。
- **官方链接：** [论文](https://arxiv.org/abs/2608.21839)、[项目页](https://firm-reward.github.io/)。
- **发布日期：** 2026-08-22；8月27日进入公开论文社区。
- **相对上期的新变化：** 首次收录。
- **核心贡献：** 把prompt拆成原子要求，为世界一致性生成对象和动作相关检查项，并只聚合已找到时间证据的判断。FIRM-Video-90K含88,044条维度样本，Bench含250个视频、750个人工点级标注。
- **Coding接口：** 适合把“人物是否仍在场、门是否保持打开、动作是否按顺序发生”转换为测试清单；可接Best-of-N选择、回归测试和RL reward。
- **互动作品 / 工业场景：** 数字人动作验收、多分支互动视频筛选、世界模型持续集成。
- **成熟度 / 证据：** 论文实测；当前公开入口未明确给出完整代码许可证。
- **重要性 / 阅读：** 中 / 可读。

### 8. MemUse：长期记忆应测“自然使用”，而非只测问答召回

- **类型 / 主线：** benchmark、dataset、真实部署研究；数字人 × 陪伴交互。
- **官方链接：** [论文](https://arxiv.org/abs/2608.24189)、[数据与评测](https://github.com/RuiSumida/MemUse)。
- **发布日期：** 2026-08-25。
- **相对上期的新变化：** 首次收录。
- **核心贡献：** 四个月、40名用户、1,872次会话的部署研究显示，Direct QA分数变化与满意度没有同步关系；一个Direct QA为78.8%的系统，在自然对话中只主动使用7.9%的相关记忆。
- **Coding接口：** 从真实对话提取“应当自然调用记忆”的时刻，作为角色Agent的离线评测和A/B分层指标。
- **互动作品 / 工业场景：** 长期陪伴角色、私人导师、客户关系数字员工。
- **成熟度 / 证据：** 数据与评测已开放；真实用户研究，但样本量有限。
- **重要性 / 阅读：** 中 / 可读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：** 本周期暂无高质量新增的talking-head、单图身份建模、唇同步或全身生成主模型。不可把TaoLive的Agent进展误写成数字人视觉质量突破。
- **3D/4D表示：** 暂无新增人体NeRF、3D/4D Gaussian Splatting或生产级mesh数字人方案。
- **实时交互：** TaoLive证明工具化角色大脑已经进入正式直播服务，但P95 8.1秒说明复杂策略回复仍可能影响轮次节奏。VoiceMem的134 ms仅是记忆检索，不是端到端语音或视频延迟。
- **音视频与情感：** VoiceMem把情绪与persona作为可寻址记忆节点，比只在prompt中描述人格更适合长期角色；但没有新增表情、视线、口型与情绪记忆联动的视觉评测。
- **工程部署：** Skills、Hooks和工具schema独立更新是本期最重要工程信号。数字人产品可以更换销售策略或检索工具，而不必重新训练视觉模型。
- **安全与身份治理：** 本周期未发现新的高质量肖像授权、水印或溯源发布。VoiceMem引入声纹、情绪和长期个人信息后，数据最小化、删除权、租户隔离和敏感属性访问日志成为更突出风险。

结论：本期数字人的增量主要发生在“大脑、工具、记忆和业务运行时”，不是脸部或身体生成器。

## 5. 世界模型进展

- **架构与训练：** Code World Model将状态演化与视觉实现分离；Zero-WAM将人类视频变成任务上下文；LAWA把未来想象压缩成latent intention。
- **可控/可玩生成：** CWM的proxy提供逐帧实体位置与语义约束，比只输入WASD或文本更接近结构化导演接口。
- **长时与物理一致性：** CWM让代码维护永久状态，解决“物品离开画面后是否仍存在”的规则问题；但最终视频仍可能不遵守proxy，因此必须保留反馈与验收。
- **空间表示：** CWM有意使用coding agent容易构造的区域、primitive和对象框，而未采用难以持续维护的复杂骨骼和完整3D模型。这提升可编程性，但降低精细碰撞和身体控制能力。
- **机器人/游戏/仿真：** Zero-WAM适合“示范定义任务”，LAWA适合“紧凑后台想象”，CWM适合“代码维护规则、视频实现外观”，三者对应不同运行层。
- **实时部署与评测：** VBVR-Pro和FIRM-Video共同表明，VLM整体打分不足以作为生产验收；应加入确定性状态断言、动作分解和可见证据定位。

## 6. Coding × 新型互动作品

### 链路一：代码持有永久状态的生成式游戏

**玩家输入 → coding agent生成状态更新代码 → 权威对象/ECS状态 → proxy compiler → MiniMax-H3视觉渲染 → FIRM/VBVR式验证 → 玩家看到持续变化的世界。**

代码负责库存、对象身份、规则、事件和回滚；视频模型负责外观和动态；传统引擎负责碰撞与多人同步。CWM已有可运行生成代码，完整游戏服务器属于后续工程。

### 链路二：可热更新策略的数字人直播间

**评论与商品事件 → TaoLive Harness → Skill/Hook/工具调用 → 销售或问答决策 → TTS与数字人表演 → 指标与审核日志。**

代码负责商品检索、优惠资格、策略版本和风控；Agent负责选择话术和工具；数字人生成器负责声音、口型和表演。已有生产部署与A/B信号，但提升幅度和并发成本未披露。

### 链路三：有长期关系的虚拟陪伴角色

**流式语音 → VAD窗口内并行VoiceMem检索 → 事实记忆＋情绪/persona节点 → 对话模型 → 语音/数字人输出 → MemUse自然整合评测。**

代码负责隐私策略、记忆TTL、删除、检索和可观测性；模型负责相关性判断与自然表达。VoiceMem代码可运行，视觉数字人整合属于本报告推断。

### 链路四：人类演示即机器人技能API

**现场拍摄/检索人类演示 → Zero-WAM视频上下文 → 未来观察与action chunk → 安全控制器 → 机器人执行。**

生成视频在这里不是作品输出，而是任务编程语言。代码负责视频检索、相机与机器人坐标适配、限位、急停和失败恢复。已有仿真与实体作者实验，核心代码尚未开放。

### 链路五：无需渲染想象视频的实时具身角色

**当前观察 → LAWA latent intention → action chunk → ECS/机器人控制器 → 传统渲染或实体执行。**

模型负责紧凑未来意图，代码负责确定性规则与执行。适合后台NPC和机器人；当前只有论文证据，尚不能据此声称已达到生产实时性。

### 链路六：互动视频的自动测试流水线

**剧情/动作规格 → 生成多个候选rollout → FIRM逐项检查＋VBVR确定性规则 → 阈值和回归报告 → 发布或回炉。**

代码负责测试用例、版本、种子、失败重放和发布门禁；生成模型负责候选视觉；规则验证器负责可审计判断。评测组件已有开放证据，通用开放世界测试仍需自建schema。

## 9. 系统架构与技术趋势判断

明显升温的是“显式状态＋生成渲染”路线。过去一周的CWM、NeoWorld-Pro、LeFlow、GlanceWAM和LAWA虽然表示不同，但都在减少让大视频模型独自承担规则、物理、规划和外观的做法。

正在形成的可复用架构是：

`用户事件 → Agent/Harness → 可执行状态或latent计划 → ECS/物理/权限层 → proxy或条件编译 → 视频/数字人渲染 → 规则验证＋视频检查 → 日志与反馈`

数字人侧的对应结构是：

`RTC输入 → 记忆与知识检索 → 工具化角色大脑 → 策略/情绪状态 → TTS与数字人表演 → 审核和业务指标`

代码适合维护可查询、可回滚和可测试的事实；世界模型适合提供开放域视觉先验和局部未来；传统引擎适合碰撞、经济系统、多人同步与安全；数字人模型适合表情、声音和身体表演。纯端到端视频方案仍难以支持实体查询、确定性规则、版本迁移和事故追溯。

未解决问题包括proxy到RGB的严格服从、复杂人体骨骼表达、端到端首帧和P95延迟、多人权威状态、长期记忆隐私、真实机器人安全、生产并发和版权。CWM虽然方向正确，但目前世界仍较简单；Zero-WAM和LAWA尚未开放核心实现；VBVR-Pro的程序任务不能替代真实开放世界评测。TaoLive是最强产业信号，但因没有A/B效果量、流量规模和故障指标，不能判定为规模化成熟方案。

## 10. 论文精读候选

1. [Code World Model](https://arxiv.org/abs/2608.25927)：重点读proxy表示、代码生成状态更新、游戏/真实数据配对和长期风格切换。区别是把coding agent放在世界动力学核心。风险是端到端Agent能力和复杂交互评测不足。
2. [TaoLive HAT](https://arxiv.org/abs/2608.15763)：重点读Harness-State Augmentation、on-policy蒸馏、HSA-RL和线上实验。区别是把工具系统变化纳入训练分布。风险是商业指标、样本量和事故率未披露。
3. [Zero-WAM](https://arxiv.org/abs/2608.26103)：重点读HumanGen流水线、IFP目标和任务级hold-out。区别是用人类视频而非文本定义新任务。风险是生成演示的物理伪影和代码待发。
4. [VoiceMem](https://arxiv.org/abs/2608.26005)：重点读双脑节点结构、流式预取、backend解耦和隐私边界。区别是将信息与情绪记忆并行维护。风险是作者部署数据和情感指标需独立验证。
5. [LAWA](https://arxiv.org/abs/2608.24882)：重点读action-free tokenizer、latent intention和匹配基线。区别是保留未来想象而不解码RGB。风险是绝对延迟、显存和代码均未开放。

## 11. 下周跟踪与可行动建议

### 持续跟踪

1. Code World Model是否开放完整coding-agent状态生成、proxy compiler训练数据和实时交互前端。
2. CWM在对象离开画面、被销毁、重建和多人同时修改时能否保持状态一致。
3. TaoLive v3相对v2的具体修订内容，以及A/B的GMV提升幅度、流量、显著性与故障率。
4. VoiceMem在敏感信息删除、错误记忆纠正、跨用户隔离和恶意记忆注入下的表现。
5. Zero-WAM能否按计划在9月15日前发布模型、HumanGen和可运行RoboTwin脚本。
6. LAWA是否公布绝对推理延迟、显存、控制频率和真实机器人复现代码。
7. FIRM-Video与VBVR-Pro能否检测人物身份交换、物体永久性和跨镜头状态冲突。
8. 数字人视觉层是否出现新的流式、可打断、带身份授权与水印的端到端系统。

### 本周可动手实验

1. **代码状态—视频渲染一致性测试**
   - 目标：验证CWM中代码状态是否真的约束最终视频。
   - 组件：CWM示例、proxy编辑器、对象检测/跟踪器。
   - 难点：proxy正确但RGB漏画或错画。
   - 成功判据：对对象出现、移动、消失和回归四类事件达到至少90%的自动检查通过率。

2. **数字人Harness热更新实验**
   - 目标：验证工具schema或Skill名称变化时Agent是否无需重训。
   - 组件：小型LLM、三个商品工具、Hook事件和模拟直播评论。
   - 难点：旧工具幻觉、尾延迟和策略冲突。
   - 成功判据：三次schema重命名后工具调用准确率下降不超过3个百分点，P95延迟不增加20%以上。

3. **VoiceMem＋MemUse长期角色实验**
   - 目标：评估角色是否在合适时机自然使用记忆，而非机械复述。
   - 组件：VoiceMem、语音Agent、MemUse式评分、20段多轮对话。
   - 难点：区分“有用引用”和侵犯边界的主动提及。
   - 成功判据：自然整合率明显高于无记忆基线，同时错误引用和敏感越界率均低于2%。

4. **视频示范即任务规格的轻量验证**
   - 目标：在Zero-WAM代码发布前验证视觉任务接口价值。
   - 组件：RoboTwin/PyBullet、示范视频encoder、规则策略或小型VLA。
   - 难点：跨视角、动作时序和对象对应。
   - 成功判据：对语言歧义任务，加入演示视频后对象选择或动作顺序成功率提高至少15个百分点。
