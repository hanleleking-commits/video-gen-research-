# 数字人、世界模型与互动作品研究日报：2026-11-20

检索窗口：2026-11-14 至 2026-11-20。  
日期口径：以论文首次提交时间、官方发布日期或仓库实际更新为准；检索截至 2026-11-20 09:40（Asia/Shanghai）。

## 1. 本日摘要

过去 7 天最明显的变化，不是生成画质再次跃升，而是“显式状态／规则／几何由代码维护，生成模型负责视觉实现”的系统路线迅速集中。Code World Model 2.0 已把结构代理、WebSocket 会话服务、浏览器客户端和八卡部署文档组合成可运行栈，并展示连续 30 分钟代理驱动生成；这比单纯的可玩视频 demo 更接近开发者运行时。WorldRuler进一步把用户规则、依赖关系和离屏对象状态放进可保存、可恢复的 3D 规则图，说明生成式游戏正在从“响应控制”转向“执行游戏规则”。

机器人世界模型出现两条并行路线：Z-sight在 VLM 原生视觉 token 空间预测未来，以 110 ms/chunk 避免像素重建；Phoenix则保留几何、语义和外观多种 latent，以更高计算成本换取跨场景、跨本体泛化。Doppel提供了第三种工程接口：代码或控制器先渲染未来机器人姿态，视频模型只预测环境如何响应，从而统一不同机器人的动作空间。

数字人新增相对较弱，但仍有两个有价值的结构性进展：ARG-Avatar利用传统蒙皮、投影和渲染几何，把可动画 3D 人体重建压缩到 68M 可训练参数；Gaspard不再采用“先生成语音、再驱动动作”的串联管线，而是联合生成语音与手势。前者有明确的引擎资产意义，后者更适合实时角色表演，但二者目前都仍是论文原型。

HandWorldBench显示，手部姿态更可控并不代表物体状态变化更正确；因此世界模型的产品验收不能继续依赖视频美观度。整体产业成熟度仍呈两极分化：结构代理渲染已经出现开源运行时，机器人和规则世界主要仍是研究验证；数字人商业 API 已经可用，但本周期没有新的独立安全、水印或肖像授权机制。

## 3. 最值得关注的 9 个进展

### 1. Code World Model 2.0 / Invoker-Render：结构代理成为生成世界的运行时协议

- **类型／主线：** 模型、GitHub、运行时；世界模型／Coding × 互动作品。
- **官方链接：** [论文](https://arxiv.org/abs/2611.22925)、[GitHub](https://github.com/inclusionAI/CodeWorldModel)。
- **时间：** 论文首次提交 2026-11-17；仓库和发布材料于 11 月 18–19 日进入公开检索。
- **相对上期的新变化：** 上期未收录；这是本日最重要的新增。
- **核心贡献：** Invoker-Render用结构代理视频、外观参考图和文本作为统一条件；因果流式模型每个 chunk 采用四步生成，并用 Progressive Forcing处理蒸馏和自生成历史累积误差。官方展示包含连续 30 分钟赛车生成，但预览帧率不等同于推理吞吐。
- **Coding 接口：** 仓库提供命令行、WebSocket `/v1/session`、文件客户端、浏览器客户端以及基于 SGLang 的服务端；代理可来自语义图、3D box、人物 mask、shaded geometry或骨骼框。
- **作品／场景：** 游戏控制器驱动低模世界、生成式赛车、虚拟摄影棚、实时风格化数字场景。
- **成熟度：** 已开源代码和权重、可运行 demo；默认生产配置为单机八 GPU。
- **证据／重要性／阅读：** 论文实测＋官方开源；**高／必读**。代码为 Apache-2.0，但部分依赖和权重含非商业条款，商用需逐项审查。

### 2. WorldRuler：把游戏规则与状态做成可执行 3D 图

- **类型／主线：** 论文、dataset；世界模型／Coding × 互动作品。
- **官方链接：** [arXiv](https://arxiv.org/abs/2611.24869)。
- **时间：** 2026-11-18。
- **相对上期的新变化：** 新增；比此前“代码保存状态、模型负责表现”的推断更进一步，论文直接实现了规则—状态—视觉闭环。
- **核心贡献：** 可执行 3D 规则图保存规则定义、依赖和对象状态；动态对象绑定把规则实体映射到视觉实例；即使对象暂时不可见，也能在首次出现时应用已累积状态。RuleVerse由 GTA-V 和 Habitat 自动采集并带状态、事件标注。
- **Coding 接口：** 规则图本质上是可序列化状态机，可由关卡脚本、agent或自然语言编译器生成；论文尚未披露稳定 SDK。
- **作品／场景：** 可保存的生成式游戏、用户自定义物理规则、互动叙事、AI 关卡编辑器。
- **成熟度：** 研究原型；未确认公开代码。
- **证据／重要性／阅读：** 论文实测；**高／必读**。

### 3. Z-sight：在 VLM token 空间联合生成未来与动作

- **类型／主线：** 论文、模型；世界模型／机器人。
- **官方链接：** [论文](https://arxiv.org/abs/2611.24940)、[项目页](https://junjieye.com/Z-sight/)。
- **时间：** 2026-11-18。
- **核心贡献：** 未来预测直接发生在 VLM 用于感知当前画面的视觉 token 空间，不重建像素，也不依赖额外冻结编码器。论文报告 SIMPLE 成功率 81.9%、六项 Unitree G1 任务平均 73.3%，推理为 110 ms/chunk。
- **Coding 接口：** 上层任务规划器输入语言目标，模型联合输出未来 latent 和连续动作；适合封装成机器人 policy service，而非图像生成 API。
- **作品／场景：** 实时机器人角色、实体展演、带预演能力的远程操作界面。
- **成熟度：** 研究原型；未见可下载权重。
- **证据／重要性／阅读：** 作者论文实测，尚无第三方复核；**高／必读**。

### 4. Phoenix：为 WAM 显式保留场景结构

- **类型／主线：** 模型、项目页；世界模型／机器人。
- **官方链接：** [论文](https://arxiv.org/abs/2611.24938)、[项目页](https://openphoenix-team.github.io/Phoenix-pages/)。
- **时间：** 2026-11-18。
- **核心贡献：** Phoenix Encoder从几何与时序教师蒸馏知识，CS-VAE做因果压缩，再联合预测结构 latent、外观 latent和动作。官方报告使用约 3.93 万小时有效数据，LIBERO-Plus 达到 94.8%，RoboTwin 2.0 C2R 达到 72.4%。
- **Coding 接口：** 输入多视角 RGB、机器人状态、语言和 embodiment ID；支持异步执行和 action chunking，适合部署为闭环策略服务。
- **作品／场景：** 柔性制造、接触丰富的机器人训练、数字孪生中的策略验证。
- **成熟度：** 可运行项目演示；代码、数据和模型入口由项目页提供，许可证需在下载时复核。
- **证据／重要性／阅读：** 论文实测＋官方 demo；**高／必读**。

### 5. Doppel：先渲染机器人，再生成环境响应

- **类型／主线：** 论文、demo；世界模型／支撑基础设施。
- **官方链接：** [论文](https://arxiv.org/abs/2611.24925)、[项目页](https://doppelwm.github.io/)。
- **时间：** 2026-11-18。
- **核心贡献：** 将未来身体构型渲染到相机视角，与数值动作一起作为条件；视频模型不再重复学习机器人运动学，而专注于物体和环境变化。一个模型覆盖八种机器人和人体本体、约 600 小时视频。
- **Coding 接口：** URDF／骨架、运动规划器或控制程序可直接生成未来姿态渲染；这种“rendered action API”比跨机器人统一数值动作更容易工程化。
- **作品／场景：** 跨机器人预演、人体遥操作、动作迁移、具身角色和物理场景合成。
- **成熟度：** 研究 demo；未确认公开权重。
- **证据／重要性／阅读：** 论文实测；**高／必读**。

### 6. HandWorldBench：手可控，不等于物体状态正确

- **类型／主线：** benchmark、dataset；世界模型评测。
- **官方链接：** [arXiv](https://arxiv.org/abs/2611.24731)。
- **时间：** 2026-11-18。
- **核心贡献：** 从 600 多小时素材筛出 20,500 个片段，再人工选择 500 个样本，覆盖人手、仿真灵巧手和真实机器人手；评测视觉、手部保真、外观一致性、指令遵循、物理一致性和时间一致性。11 个模型的结果显示，手姿态控制更强未必带来正确、持久的物体状态变化。
- **Coding 接口：** 可作为 world-model CI：程序读取动作和目标对象状态，分别验收手部轨迹与对象状态转移。
- **作品／场景：** 机器人数据生成、第一视角训练、虚拟装配和手势交互。
- **成熟度：** benchmark 论文；资源许可证尚待核验。
- **证据／重要性／阅读：** 论文实测；**高／必读**。

### 7. ARG-Avatar：用动画与渲染几何降低 3D 数字人重建成本

- **类型／主线：** 论文；数字人／3D avatar。
- **官方链接：** [arXiv](https://arxiv.org/abs/2611.22207)。
- **时间：** 2026-11-17。
- **核心贡献：** FACRoPE利用人体模板、线性蒙皮、相机投影和渲染建立 avatar token 与图像 patch 的对应；Intermediate Token Rendering进一步提供中间几何监督。模型仅 68M 可训练参数，论文称相较 LHM++ 快 6 倍、训练计算少 14 倍，并在 NeuMan OOD 上提高 2.7 dB PSNR。
- **Coding 接口：** 输出是可驱动的 canonical avatar及姿态相关形变，比纯视频数字人更适合接入 Unity、Unreal或离线 DCC；具体导出格式未披露。
- **作品／场景：** 玩家分身、虚拟试衣、远程呈现、低成本数字演员。
- **成熟度：** 研究原型；未发现官方代码或权重。
- **证据／重要性／阅读：** 论文实测；**中高／必读**。

### 8. Gaspard：语音与手势从串联生成改为联合生成

- **类型／主线：** 论文、模型方法；数字人。
- **官方链接：** [arXiv](https://arxiv.org/abs/2611.24862)。
- **时间：** 2026-11-18。
- **核心贡献：** 使用连续自回归 flow matching，分别设置语音和手势预测头，并通过解耦 classifier-free guidance在推理时独立调节两种模态。短参考前缀可提供声音和手势风格。
- **Coding 接口：** 最自然的工程接口是文本／角色状态输入，同时返回音频流与动作 latent；再由 TTS 播放器、骨骼 retargeter和面部系统消费。
- **作品／场景：** 生成式 NPC、虚拟主播、互动讲师、具身语音助手。
- **成熟度：** 研究原型，暂无实时延迟和公开 SDK 证据。
- **证据／重要性／阅读：** 论文实测；**中高／可读**。

### 9. UltraTex：从“看起来像”推进到可重光照的 PBR 材质

- **类型／主线：** 论文、3D 资产工具；支撑基础设施。
- **官方链接：** [论文](https://arxiv.org/abs/2611.24941)、[项目页](https://ultratex.vercel.app/)。
- **时间：** 2026-11-18。
- **核心贡献：** 两阶段多视角扩散先生成 albedo和世界空间 shading normal，再结合 VLM 材质语义及受控光照特征预测 metallic/roughness。目标不是复刻参考图中的光照，而是产生可在引擎中重新打光的材质。
- **Coding 接口：** 输入 mesh和单张参考图，输出 PBR 通道，可进入 Blender、Unity或 Unreal 的资产导入脚本。
- **作品／场景：** 生成式游戏资产、数字人服装和道具、虚拟制片快速预览。
- **成熟度：** 论文＋项目 demo；代码运行于 Meshy 内部框架，尚未开源。
- **证据／重要性／阅读：** 论文实测＋官方产品关联说明；**中／可读**。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：** Gaspard把语音和身体手势放进同一生成过程，解决串联管线中“语音先定死、动作只能被动追随”的问题。不过论文未给出可打断对话、turn-taking或端到端实时延迟，暂不能视为实时数字人产品。
- **3D/4D 表示：** ARG-Avatar是本周期最明确的新增。其价值不只是模型更小，而是证明蒙皮、相机和渲染这些传统图形知识可以替代部分数据与参数规模。它产生可动画 3D 表示，工程价值高于只输出视频。
- **实时交互：** 本周期没有新的数字人模型提供可信的实时流式指标。上期已报道的 Avatar 6 API 和 LongCat-Video-Avatar 1.6仍是更直接的产品／开源入口。
- **音视频与情感：** Gaspard支持语音—手势风格联合，但没有完整面部、视线或情绪状态机证据；尚不能单独组成高保真虚拟员工。
- **工程部署：** ARG-Avatar论文称推理为秒级，但未发布引擎插件、标准骨架或资产导出工具，真正接入游戏管线仍需 retargeting、LOD、碰撞体和材质处理。
- **安全与身份治理：** 本周期暂无高质量新增。未发现与上述模型同步发布的肖像授权、可验证水印、C2PA或深伪检测机制；涉及真人参考图和声音克隆时仍需外部治理。

## 5. 世界模型进展

- **架构与训练：** Z-sight代表“只预测任务相关 latent”的低延迟路线；Phoenix代表“结构、语义、外观与动作共同建模”的高容量路线；两者不能仅凭成功率横比，因为后训练数据和评测设置不同。
- **可控／可玩生成：** Code World Model 2.0用连续结构代理控制镜头、对象和人物；WorldRuler进一步把规则执行加入闭环。共同趋势是将生成模型降级为“视觉执行器”，而不是世界状态的唯一所有者。
- **长时与物理一致性：** 30 分钟外观稳定是 Code World Model 2.0的重要证据，但不等于 30 分钟语义或物理正确。HandWorldBench证明局部动作外观正确也可能伴随错误的对象状态。
- **空间表示：** WorldRuler使用 3D 规则图；Doppel使用相机对齐的人体／机器人渲染；Phoenix使用结构 latent。空间中间表示正在成为代码和生成模型之间的接口层。
- **机器人／游戏／仿真：** 游戏侧更强调规则持久化；机器人侧更强调未来预测是否改善真实动作。此前日报已经指出“预测更准不必然使策略更好”，今天的 Z-sight和 Phoenix仍需独立真实机器人复核。
- **实时部署与评测：** Z-sight的 110 ms/chunk接近交互控制，但 chunk长度、硬件和控制频率决定实际体验；Invoker-Render已提供服务端，但官方明确提醒 demo 播放 FPS 不是推理吞吐。

## 6. Coding × 新型互动作品

### 链路一：代码世界上的实时生成式游戏

**规则脚本／ECS → WorldRuler 3D 规则图 → 结构代理 → Invoker-Render WebSocket → 可保存的生成式游戏**

代码维护生命值、库存、对象存在性、离屏状态和存档；传统引擎计算碰撞、相机和低模代理；视频模型负责材质、光照、局部动作和最终画面。WorldRuler与 Invoker-Render分别验证了规则层和渲染层，但尚未有公开项目将二者完整拼接，属于**有组件证据的本报告推断**。

### 链路二：可编程互动电影与虚拟摄影棚

**剧情 agent → 镜头／角色轨迹 → shaded geometry或骨骼代理 → 流式生成 → 导演实时改镜头**

代码负责剧情状态、镜头列表和角色 blocking；传统 3D 引擎提供可编辑空间；生成模型把粗代理渲染成高质量风格画面。Invoker-Render已提供相机路线和浏览器交互 demo，属于**可运行证据**，但八卡默认部署使其更适合工作室预演，而非消费端。

### 链路三：低成本玩家分身

**手机多图／单目视频 → ARG-Avatar → 骨架 retargeting → Unity/Unreal → 玩家控制的个性化角色**

ARG-Avatar承担身份和可动画几何恢复；代码负责标准骨架、LOD、网络同步和物理；引擎负责确定性互动。本周期只有论文证据，尚无标准资产格式和引擎插件，属于**研究原型**。

### 链路四：语音、动作和角色大脑的协同

**对话 agent／状态机 → 文本与情绪参数 → Gaspard 音频＋手势 latent → TTS 播放／骨骼驱动 → NPC 表演**

角色 agent决定说什么、是否打断及调用何种工具；Gaspard负责同步的声音和身体动作；引擎负责注视、导航、碰撞和剧情事件。联合生成可减少“先出语音、后补动作”的僵硬感，但实时推理和可打断性尚未验证，属于**本报告推断**。

### 链路五：跨机器人世界预演

**运动规划器 → 未来 robot pose rendering → Doppel → 环境响应视频 → verifier／reward model → 执行动作**

数值动作空间不同不再阻碍共享模型，因为渲染图成为统一接口。代码负责 URDF、正向运动学、候选动作采样和风险阈值；模型预测物体移动；验证器选择动作。Doppel已验证跨本体预测，闭环工业部署仍缺失。

### 链路六：世界模型 CI

**任务脚本 → 生成 rollout → HandWorldBench 六维指标＋对象状态断言 → 回归报告**

视频质量、手姿态和对象状态必须分别验收。适合机器人数据工厂、虚拟装配和生成式游戏的自动回归；这是从“人工看 demo”转向软件工程测试的重要变化。

## 9. 系统架构与技术趋势判断

明显升温的是“**显式可执行世界＋生成式观察器**”：代码维护事实，传统引擎计算确定性状态，视频模型生成可感知画面，视觉模型再把结果反馈给状态系统。这一架构同时出现在 WorldRuler、Invoker-Render和 Doppel中，已不再是单一项目偶然选择。

第二个趋势是**视觉代理成为跨系统协议**。3D box、mask、骨骼、机器人渲染和 shaded geometry都能由现有代码生成，又比供应商私有 latent更可调试、更容易录制回放。它们可能成为生成式运行时的“中间表示”。

第三个趋势是机器人世界模型开始分层：低延迟控制使用 Z-sight式 latent foresight；高保真训练或分析使用 Phoenix、Doppel式结构与视频预测。工业系统可能并存一个快速策略模型和一个较慢的审计／预演模型。

仍未解决的问题包括：生成画面的真实 FPS、端到端输入延迟、多用户并发、长时语义正确性、对象拓扑变化、失败检测、确定性回放、引擎资产格式、真人身份授权及训练数据版权。论文成功率通常依赖各自后训练和 benchmark，不能直接推导生产可靠性。

营销风险最高的是把“30 分钟没有明显视觉跳变”解释成“世界状态正确运行 30 分钟”，或把机器人 benchmark提升解释为已经规模化部署。UltraTex与 ARG-Avatar都具有明确工程价值，但目前缺少公开代码；对外宣称可直接进入量产管线仍过早。

## 10. 论文精读候选

1. [Code World Model 2.0](https://arxiv.org/abs/2611.22925)  
   值得读：最完整地连接结构代理、四步流式模型和 serving。重点读 Progressive Forcing、代理粒度实验、30 分钟 rollout及服务流水线。与上期 FastFrames的差异是：FastFrames强调逐帧延迟，本作强调上游引擎—生成渲染器分工。复现风险是八卡配置、依赖许可证和缺少统一吞吐指标。

2. [WorldRuler](https://arxiv.org/abs/2611.24869)  
   值得读：把“可编程世界”从口号落实为规则图、对象绑定、存档恢复。重点读规则图数据结构、离屏状态约束和反事实重建训练。复现风险是 RuleVerse和完整代码尚未确认公开。

3. [Z-sight](https://arxiv.org/abs/2611.24940)  
   值得读：理解为何世界模型不一定要重建像素。重点读 foresight expert、action expert、EMA teacher和梯度隔离。与视频 WAM相比速度更优，但可解释视觉 rollout较弱。复现风险是数据规模和机器人后训练细节。

4. [Phoenix](https://arxiv.org/abs/2611.24938)  
   值得读：比较结构 latent、外观 latent和动作联合生成如何改善泛化。重点读双教师蒸馏、CS-VAE、MoT及少样本适配。复现风险是约 3.93 万小时有效数据和多阶段训练成本。

5. [HandWorldBench](https://arxiv.org/abs/2611.24731)  
   值得读：它直接暴露“控制看起来对、对象状态却错”的评测盲点。重点读六维指标、跨本体协议和失败案例。复现风险是部分维度可能依赖 VLM或人工评价，需要检查一致性。

## 11. 下周跟踪与可行动建议

### 继续跟踪

1. Invoker-Render能否公布真实硬件上的首帧延迟、稳定 FPS、显存和并发曲线。
2. WorldRuler是否开放 RuleVerse、规则图 schema和生成闭环代码。
3. Z-sight的 110 ms/chunk对应多少动作步，以及在异步控制下的端到端频率。
4. Phoenix开放资源的许可证、权重规模和单卡／多卡推理要求。
5. Doppel是否能用生成结果稳定排序候选策略，而不只是提高 PSNR。
6. ARG-Avatar是否提供标准骨架、Gaussian／mesh导出和 Unity／Unreal示例。
7. Gaspard能否支持流式输出、打断和对话 turn-taking。
8. HandWorldBench是否发布可自动化运行的对象状态指标与 leaderboard。

### 本周可动手实验

**实验一：结构代理驱动的互动赛车**

- 目标：验证“传统引擎负责状态，视频模型负责画面”的最小闭环。
- 组件：简单 Three.js／Godot赛道、键盘输入、低模代理录制、Invoker-Render。
- 难点：八卡资源、代理帧节奏与生成 chunk同步。
- 成功判据：连续 3 分钟内转向与镜头变化都被正确表现，车辆身份和赛道结构无明显跳变。

**实验二：可保存的规则世界**

- 目标：实现 WorldRuler思想的简化版，不等待官方代码。
- 组件：JSON规则图、ECS或轻量状态机、三个对象、存档／读档、普通 3D 引擎。
- 难点：离屏事件、规则依赖和重新入镜时的状态一致性。
- 成功判据：对象在离屏期间发生状态变化，读档后首次入镜仍呈现正确属性。

**实验三：数字人语音—动作接口契约**

- 目标：先定义角色大脑与联合表演模型之间的稳定 API。
- 组件：对话 agent、情绪／意图标签、音频 chunk、骨骼动作序列、Unity或 WebGL角色。
- 难点：音频和动作时钟对齐、打断后的缓冲清理。
- 成功判据：五轮可打断对话中，声音与关键手势误差低于 200 ms，打断后不继续播放旧动作。

**实验四：手—物体因果回归测试**

- 目标：避免只用视觉质量评估世界模型。
- 组件：20段抓取／放置视频、对象检测或分割、动作前后状态标签、自动报告。
- 难点：遮挡、左右手切换和容器内外关系识别。
- 成功判据：测试同时报告手部轨迹、目标对象状态和时间持久性，并能抓出“手动了但物体没动”的失败样本。
