# 数字人、世界模型与互动作品研究日报：2026-07-28

检索窗口：2026-07-22 至 2026-07-28。  
检索截止：2026-07-28 09:03（UTC+8）。

## 1. 本日摘要

本周期最明显的增量来自世界模型与可执行 3D agent，而不是传统 talking-head 数字人。ViTacWorld 把触觉加入动作条件世界模型，用生成 rollout 同时训练和预评估机器人策略；Robot-Factored World Models 则把控制器、运动学和 URDF 渲染放到模型外部，显示“代码与机器人系统负责动作实现，模型只学习环境响应”正在成为清晰架构。面向生成式游戏，Closing the Loop 利用引擎已有的相机位姿和深度建立回环记忆，在不重新训练模型的情况下缓解“离开后再返回，场景被重新画了一遍”的问题。

Coding × 互动作品方面，SceneActBench 首次以统一 Blender MCP 循环评测 agent 是否能真正摆放、重建和动画化完整 3D 场景；11 组模型最高总分仅 50.2，说明“能看懂截图”距离“能可靠构建运行场景”仍很远。AgentHOI 则给出另一条链路：四个 VLM agent 把文本和人物/物体参考图转成逐秒动作计划，再驱动 Wan 2.1 视频模型生成人物—物体交互，但单卡仍需约 80GB 显存，属于离线内容生成而非实时角色。

数字人主线没有新的高质量实时口型、情感、全身流式驱动或端侧部署突破；新增主要是人物交互视频、动态脸部脑信号重建和安全评测。安全侧出现两个相反信号：潜空间角度水印试图提升生成内容溯源，而 ISPCloak 证明模拟真实相机 ISP 特征即可显著削弱一批深伪检测器。总体看，近期系统正从“端到端生成一切”转向“代码保存权威状态和几何约束，生成模型预测外观与未来，agent负责编排与验收”；最接近工业使用的是评测、数据生成和离线内容管线，实时生成世界仍缺乏稳定延迟、长时状态正确性和规模化部署证据。

## 3. 最值得关注的 10 个进展

### 1. ViTacWorld：视觉—触觉世界模型进入策略训练和预评估

- **类型 / 时间 / 主线：** 论文、项目demo；2026-07-24；世界模型、机器人。
- **官方链接：** [论文](https://arxiv.org/abs/2607.22530)、[项目页](https://vitacworld.github.io/)。
- **相对上期的新变化：** 全新条目。
- **核心贡献：** 输入机器人动作，同步预测主视角、腕部视角和触觉信号；以真实触觉数据、任务对齐仿真和真实策略rollout分阶段训练。
- **Coding接口：** 动作序列是运行时输入，生成rollout可进入ACT或π类策略的数据管线及离线策略评估器。
- **场景：** 插接、剥皮、精细装配、接触丰富的机器人训练与上线前测试。
- **成熟度 / 证据：** 研究原型；GitHub仍标注“Coming Soon”。作者报告加入两轮dream rollout后，四项实机任务平均成功率从42.5%升至80.0%；世界模型评估为57.5%，实机为67.5%。
- **重要性 / 阅读优先级：** 高 / 必读。

### 2. Robot-Factored World Models：把控制器和URDF从世界模型中拆出

- **类型 / 时间 / 主线：** 论文、项目demo；2026-07-24；世界模型、机器人运行时。
- **官方链接：** [论文](https://arxiv.org/abs/2607.22535)、[项目页](https://bjkim95.github.io/rofacto/)、[GitHub](https://github.com/bjkim95/rofacto)。
- **相对上期的新变化：** 全新条目。
- **核心贡献：** 控制命令先经真实控制器和运动学得到名义轨迹，再以URDF渲染机器人RGB、末端深度和场景深度；模型只预测接触后的场景响应，避免直接学习不同机器人的动作实现，也避免使用未来真实状态造成标签泄漏。
- **Coding接口：** 控制器、运动学求解器、URDF渲染器和相机标定构成明确预处理API；可编辑名义轨迹并批量比较预测结果。
- **场景：** 跨机器人本体预测、双臂组合、由人类示范合成机器人交互视频。
- **成熟度 / 证据：** 作者demo；代码仓库目前只有README并标注“coming soon”。
- **重要性 / 阅读优先级：** 高 / 必读。

### 3. Closing the Loop：为生成式游戏渲染加入回环记忆

- **类型 / 时间 / 主线：** 论文、游戏引擎demo；2026-07-23；世界模型、Coding × 生成式游戏。
- **官方链接：** [论文](https://arxiv.org/abs/2607.21848)、[项目页](https://wenchao-m.github.io/ClosetheLoop.github.io/)。
- **相对上期的新变化：** 全新条目。
- **核心贡献：** 按相机位姿检索已被KV cache淘汰的历史latent，并用深度重投影为注意力增加空间对应先验；基座为冻结的深度条件Causal Wan-VACE，无需后训练。
- **Coding接口：** 游戏引擎持续输出相机位姿和metric depth；外部记忆服务保存历史latent及其姿态。
- **场景：** 玩家绕行后返回仍保持建筑、材质和地标一致的生成式探索游戏、虚拟制片和数字孪生。
- **成熟度 / 证据：** Roblox与宾州州立作者demo，已接入内部游戏引擎；未确认公开代码、实时帧率或显存。
- **重要性 / 阅读优先级：** 高 / 必读。

### 4. SceneActBench：用Blender MCP评测agent能否真正操作3D世界

- **类型 / 时间 / 主线：** benchmark、GitHub、dataset、MCP harness；2026-07-24；Coding × 互动作品。
- **官方链接：** [论文](https://arxiv.org/abs/2607.22393)、[GitHub](https://github.com/Feinaldo2/SceneActBench)、[数据集](https://huggingface.co/datasets/FEInaldo/SceneActBench)。
- **相对上期的新变化：** 全新条目。
- **核心贡献：** 520个案例覆盖布局、相机恢复、铰接动画、场景重建和动态动画；最终交付JSON或GLB，并对隐藏3D真值计算几何指标。
- **Coding接口：** 模型通过Blender MCP在headless环境中写脚本、渲染、观察、修改；harness记录每次工具调用和中间checkpoint。
- **关键结果：** 11组模型总分38.6–50.2；最强重建分仅12.3，且没有模型在五项任务上全面领先。
- **成熟度 / 证据：** MIT评测代码、162GB数据集和leaderboard已公开；论文作者评测。
- **重要性 / 阅读优先级：** 高 / 必读。

### 5. AgentHOI：四个VLM agent规划人物—物体交互视频

- **类型 / 时间 / 主线：** 论文、GitHub、权重；2026-07-24；数字人、Coding × 视频创作。
- **官方链接：** [论文](https://arxiv.org/abs/2607.22241)、[GitHub](https://github.com/bone-11/agenthoi)。
- **相对上期的新变化：** 全新条目。
- **核心贡献：** 多个感知、交互和动作规划agent先生成逐秒时间线，再由Wan2.1-I2V-14B生成穿戴、骑乘、拿取等HOI视频；训练阶段以文本到动作教师做关系蒸馏，推理时不再需要显式动作输入。
- **Coding接口：** JSON包含人物图、物体图和caption；中间动作时间线会保存到磁盘，可被人工或剧情代码编辑后跳过agent重跑。
- **场景：** 虚拟模特、商品演示、角色预演、教育动作素材；不适合实时NPC。
- **成熟度 / 证据：** 训练和推理代码、checkpoint已公开；默认demo需InternVL3.5-38B、Wan 14B和约80GB单卡显存；未发现明确仓库许可证。

### 10. Talking-face生理信号检测与ISPCloak：检测与规避同步升级

- **官方链接：** [生理信号检测](https://arxiv.org/abs/2607.21776)、[ISPCloak](https://arxiv.org/abs/2607.21897)。

- **核心贡献：** 前者从视频提取rPPG波形，在Celeb-DF++ talking-face子集上达到AUC 0.806，但不同生成器AUC从0.690到0.985，泛化仍不稳。后者把生成图像逆变换到RAW域，注入真实传感器噪声并重新执行ISP，使内容更像相机拍摄，从而规避依赖数字生成伪影的检测器。
- **Coding接口 / 场景：** rPPG可作为审核服务的一路信号；ISP攻击说明生产审核必须组合内容凭证、模型水印、身份授权和多模态检测。

## 4. 数字人 / 虚拟形象能力进展

**生成与驱动。** 本周期没有新的高质量实时talking-head、lip-sync或流式全身驱动模型。AgentHOI解决的是离线人物—物体动作逻辑，并非对话数字人；约80GB显存需求也排除了多数实时前端。

**3D/4D表示。** SM4RT输出结构化运动基，DETRIS改善非凸表面表达，均可为可编辑虚拟角色或动态资产提供底层表示，但尚无标准骨骼、blendshape、FBX/GLB动画导出证据。

**实时交互。** 无新数字人模型给出低于一秒的端到端ASR—LLM—TTS—表演闭环。当前可产品化方案仍应使用传统rig、动画状态机和流式语音，把生成视频作为可选表现层。

**音视频与情感表达。** 没有情感TTS、视线、active listening或turn-taking新增。AgentHOI的逐秒时间线可控制动作顺序，但不支持用户中途打断。

**工程部署。** 可进入制作管线的是AgentHOI的JSON时间线、人物/物体参考绑定和离线批量生成；fMRI2Face仍是研究数据和神经解码实验。

**安全与身份治理。** 单一视觉检测不足。较稳妥的生产架构应同时记录人物授权、参考资产哈希、生成模型版本、潜空间水印、C2PA类凭证和审核结果；rPPG只能作为辅助信号。

## 5. 世界模型进展

**架构与训练。** ViTacWorld把视觉和触觉编码为对齐latent并由view-aware DiT预测；Robot-Factored把控制器、运动学和机器人外观显式外置；两者都减少了模型需要隐式学习的内容。

**可控/可玩生成。** Closing the Loop使用相机位姿和深度作为引擎—模型协议，比纯键盘token更有几何意义。控制仍以相机和机器人轨迹为主，通用对象增删、库存和任务状态API尚未形成标准。

**长时与物理一致性。** 回环检索解决“重访外观”，不保证对象内部状态、任务或碰撞长期正确。权威状态仍应由引擎或机器人控制栈保存。

**空间表示。** SE(3)运动基、URDF渲染、深度重投影和可变形三角基元共同表明：结构化几何中间层正在成为代码与视频模型之间的主要接口。

**机器人/仿真。** ViTacWorld已把生成rollout用于真实策略训练，并给出成功率变化；Robot-Factored展示了跨本体泛化，但两者都不能替代真实碰撞检测、安全控制器和实机验收。

**实时部署与评测。** 本批新增论文普遍未披露端到端延迟、GPU、并发或长时运行成本。Closing the Loop虽接入内部引擎，也没有足以证明商业实时游戏可用的性能数据。

## 6. Coding × 新型互动作品

1. **引擎相机与深度 → 回环检索服务 → 冻结视频生成器 → 可重访的生成式探索世界**  
   代码负责相机、几何、位姿索引和历史latent管理；模型负责持续视觉风格化；引擎负责碰撞和任务。已有内部引擎demo，公开实时部署证据不足。

2. **控制命令 → 机器人控制器/运动学 → URDF渲染 → 世界模型预测接触结果 → 策略评分**  
   传统机器人栈生成不泄漏未来结果的名义轨迹；模型预测物体响应；评分器选择安全候选。项目demo已运行，代码待发布。

3. **策略动作 → ViTacWorld视觉/触觉rollout → dream dataset → 策略再训练 → 接触任务实机执行**  
   代码负责动作采样、rollout筛选、数据版本和训练循环；模型生成难以廉价采集的接触结果。已有作者实机成功率证据，不是纯概念。

4. **图片/视频帧 → VLM agent → Blender MCP工具调用 → GLB/JSON → 隐藏几何评分**  
   agent负责观察、写Blender Python、渲染复查；Blender负责几何、动画和确定性执行；harness负责轨迹、checkpoint与评分。SceneActBench代码和数据已开放。

5. **人物图＋物体图＋文本 → 四个VLM agent → 逐秒动作JSON → Wan视频生成 → 商品或角色片段**  
   剧情代码可直接编辑中间时间线，复用同一人物和商品资产。已有完整推理路径，但时延和80GB显存使其更适合预生成内容。

6. **单目视频 → SM4RT结构化运动 → 对象级轨迹/SE(3) → 仿真资产初始化**  
   可将动态视频从像素流转换为较紧凑的对象运动描述，再交给Unity、Unreal、Blender或机器人仿真器；标准引擎适配属于本报告推断。

## 8. 可复现资源与开发者入口

- [SceneActBench](https://github.com/Feinaldo2/SceneActBench)：harness为MIT；数据新增标注采用CC BY-NC 4.0，底层资产另受原始许可证约束。最小验证是下载一个任务子集，启动headless Blender MCP，以单一模型执行Layout任务并检查`steps.json`、GLB和ADD-S。
- [AgentHOI](https://github.com/bone-11/agenthoi)：已提供训练、推理、权重下载和示例JSON；单张80GB GPU可配合CPU offload运行。最小路径是先使用内置refined timeline并设置`SKIP_AGENT=1`，验证视频阶段后再加入四agent规划。
- [SM4RT](https://github.com/wzzheng/SM4RT)：2026-07-26发布训练和推理代码，需Python 3.11；checkpoint和评测代码尚未确认发布，许可证不明确。建议等待权重后验证单段视频的运动基数量和同物体轨迹一致性。
- [Robot-Factored World Models](https://github.com/bjkim95/rofacto)：只有README，代码未发布；目前只能评估论文和项目demo。
- [ViTacWorld](https://vitacworld.github.io/)：项目页明确标注GitHub即将发布；触觉数据格式、传感器标定和checkpoint均待公开。
- [DETRIS](https://github.com/orioljim1/detris)：项目页交互demo可用，但CUDA栅格器和预训练场景尚未发布。
- Closing the Loop项目页中的“Code”当前指向论文而非独立仓库，不应视为已开源。
- LAW、ISPCloak、fMRI2Face和talking-face rPPG检测均未确认公开代码；现阶段不建议作为生产依赖。

## 9. 系统架构与技术趋势判断

明显升温的是“显式中间接口”：相机位姿、深度、URDF渲染、SE(3)运动、触觉latent、GLB/JSON和MCP工具调用正在取代只依赖文本prompt的端到端控制。

逐渐形成的复用架构是：

`用户/agent意图 → 结构化计划或动作 → 权威引擎/控制器 → 几何与传感器中间表示 → 世界模型生成观察或未来 → 评分、审核与回滚`

代码负责权限、确定性状态、物理、时间线、网络同步和可观测性；生成模型负责视觉表现、不可见未来和难采集数据；coding agent负责把视觉证据转成可执行脚本，并通过渲染或实机结果迭代。

数字人方向短期更可能复用AgentHOI式“动作计划＋传统资产＋离线生成”，而不是把实时神经视频直接放进核心交互循环。世界模型在机器人领域的商业路径也更清楚：先用于数据扩增、策略排序和上线前评估，而非直接控制低层执行器。

仍未解决的问题包括：生成画面如何反写为可靠对象状态；触觉模型如何跨传感器迁移；回环记忆能否扩展到大世界和多玩家；Blender/Unity/Unreal agent如何事务回滚；实时数字人的脸、身体、语音和打断如何统一；水印在转码、截图、ISP处理及恶意攻击下的实际召回率。

需要降级看待的是“代码链接存在即已开源”的表述：ViTacWorld、Robot-Factored和DETRIS尚未发布实现，Closing the Loop也没有独立代码仓库。SceneActBench证明当前agent即使能反复使用Blender工具，也远未达到稳定自动制作完整3D场景的水平。

## 10. 论文精读候选

1. [Robot-Factored World Models](https://arxiv.org/abs/2607.22535)：重点读action realization、nominal trajectory和depth conditioning；与Masked Visual Actions相比，它更明确地区分可部署控制信号与泄漏未来结果的logged state。复现风险是代码未发布。
2. [ViTacWorld](https://arxiv.org/abs/2607.22530)：重点读视觉/触觉token化、仿真预训练、真实rollout微调及dream-data循环；价值在于把世界模型与策略收益直接关联。风险是触觉硬件和数据格式尚未开放。
3. [Closing the Loop](https://arxiv.org/abs/2607.21848)：重点读pose retrieval门限、深度重投影、遮挡判断和KV预算；与AlayaWorld的固定空间memory相比，它是无需训练的引擎辅助回环。风险是无公开代码和性能数据。
4. [SceneActBench](https://arxiv.org/abs/2607.22393)：重点读统一agent loop、五类几何指标和case-level失败分析；它为Unity CLI、Blender MCP和未来3D coding agent提供可迁移的验收方法。风险是162GB数据和商业模型API成本。
5. [AgentHOI](https://arxiv.org/abs/2607.22241)：重点读四agent职责、时间线表示和token-relation distillation；与显式骨骼/姿态控制不同，它在推理时只需文本和参考图。风险是80GB显存、训练数据未公开及许可证不明确。

2. Robot-Factored是否开放URDF渲染、名义轨迹生成及跨本体评测脚本。

6. SM4RT checkpoint和评测代码是否按计划发布，输出能否稳定转换为对象级轨迹。
7. 潜空间水印在视频转码、裁剪、屏摄和ISP攻击下的联合表现。
8. 是否出现新的流式脸—身体—语音统一数字人以及真实并发成本报告。

本周可执行实验：

1. **Blender MCP最小执行式评测。** 目标：验证coding agent从参考图到可评分场景的闭环。组件：SceneActBench、Blender、一个API模型。难点：工具调用错误和相机坐标。成功判据：完成10个Layout任务，全部输出有效GLB，且中间步骤可重放。
2. **引擎回环记忆原型。** 目标：测试生成渲染重访一致性。组件：Godot/Unity场景、深度与相机导出、任一视频生成后端、向量检索。难点：latent与相机时间对齐。成功判据：绕行60秒后返回，地标外观相似度显著高于滑动窗口基线，权威对象状态零错误。
3. **AgentHOI可编辑时间线。** 目标：验证“agent计划可人工接管”。组件：公开代码、80GB GPU或多GPU、两组人物/商品参考。难点：手—物接触和显存。成功判据：只修改JSON中的动作顺序即可改变视频行为，同时人物和商品身份保持可辨识。
4. **机器人渲染动作接口。** 目标：复现Robot-Factored思想而不等待代码。组件：PyBullet/MuJoCo、URDF、相机深度、简单未来预测模型。难点：名义轨迹与接触后的真实轨迹分离。成功判据：同一预测器可接受两种机器人本体，且对接触物体位移的误差低于直接使用原始动作向量的基线。
