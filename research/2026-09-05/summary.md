# 数字人、世界模型与互动作品研究日报：2026-09-05

检索窗口：2026-08-30 至 2026-09-05。

## 1. 本日摘要

本周期最强信号来自 Runway GWM Worlds 2：世界模型首次把实时 720p/24fps 视频、48kHz 音频、角色语言动作、连续相机控制、多人角色和 agent 控制统一到同一自回归运行时，WorldPrompt 则把世界拆成持久设定与时间戳事件流，使其开始像一种可编排的软件后端，而不只是视频生成器。  
但该系统仍是研究预览，没有开放 API、SDK、权重、成本或独立评测；官方也承认高速转向会破坏几何，长时记忆仍不可靠，因此不能等同于可生产部署的游戏引擎。  
开源侧的主要增量是 Puffin-World：RGB、深度、重力/纬度等“原生世界状态”被同一模型联合生成，并可直接重建为点云，使生成画面更容易接入导航、空间编辑和机器人系统。  
WorldReward 与 Principia 分别补上了“动作是否执行正确”和“物理是否成立”的自动化测试层；后者显示六种视频生成器在常规视觉指标约 0.8 时，物理一致性最高仍不超过 0.42，说明“看起来真实”与“可作为仿真器”仍明显分离。  
数字人视觉生成本周期暂无新的高质量核心模型；增量主要发生在角色运行时的语音和交互层：Text-Audiobox 联合建模双向对话、重叠语音、反馈语和情感，ERICA/Teleco 系统则给出了嘈杂公共空间中的真实运行证据。  
Compile by Training 展示了另一条重要工程路径：把自然语言角色规则编译成可版本化的小型本地神经函数，再由确定性 DSL 和浏览器运行时校验、执行，降低持续调用大模型的延迟与成本。  
GIFT 的结果进一步说明，世界模型用于机器人时，不能只追求像素预测；几何、affordance 和目标区域等结构必须进入训练目标，才能成为可控制的行动表示。  
总体趋势是：代码正在从“生成一次内容”转向维护持久状态、事件协议、验证器、安全边界和实时分发；生成模型负责外观与开放式行为，传统软件继续掌握真值状态、权限、物理约束和失败恢复。  
相较 9 月 4 日日报，本日新增重点不是又一套长时视频骨干，而是 GWM Worlds 2 的端到端实时产品信号，以及 Puffin-World、WorldReward、Principia 形成的“状态—生成—评测”开源闭环。

## 3. 最值得关注的 11 个进展

### 1. GWM Worlds 2：实时原生音视频世界成为可编排运行时

- **类型 / 日期 / 主线：**模型、产品研究预览、demo；2026-09-03；世界模型、Coding × 互动作品、数字角色。
- **官方链接：**[Runway 研究发布](https://runway.com/research/introducing-gwm-worlds-2)。
- **相对上期：**首次收录；9 月 4 日日报未覆盖。
- **核心贡献：**自回归扩散模型连续生成 720p、24fps 视频和 48kHz 音频。WorldPrompt 将输入划分为 genesis prompt、首帧与时间戳事件流；事件可包含角色动作、对白、声音和逐帧相机位姿。滑动 KV cache 和因果音视频解码器承担实时生成。
- **Coding 接口：**官方 demo 将键鼠输入映射为预制文本动作；允许 LLM 生成世界设定和键位；多人 demo 用 LiveKit 分发音视频并按 player/director 角色路由控制；agent 可同时控制角色与环境。
- **作品 / 工业场景：**生成式 NPC、多人互动电影、可玩视频、实时预演、机器人视觉仿真。
- **成熟度 / 证据：**研究预览、内部可运行 demo；**官方声称**。未开放 SDK、权重、价格或第三方评测。
- **判断：**重要性高，必读。最大突破是控制协议和运行时完整度，不是已经解决物理或长时状态。

### 2. Puffin-World：在同一模型中生成外观、深度和物理朝向

- **类型 / 日期 / 主线：**论文、模型、GitHub、权重、dataset；论文 2026-09-03 提交、仓库记录 09-04 发布；世界模型、空间基础设施。
- **官方链接：**[项目页](https://kangliao929.github.io/projects/puffin-world/)、[代码](https://github.com/KangLiao929/Puffin)、[模型卡](https://huggingface.co/ACERobotics/Puffin-World)。
- **相对上期：**首次报道；权重和训练代码实际在 8 月下旬开放，本周期的纳入原因是完整论文于 9 月 4 日发布。
- **核心贡献：**统一建模 appearance、dense depth、gravity/latitude；9 通道 Omni-Camera 条件同时表达绝对重力方向、内参和相对射线几何。Puffin-16M 含 1500 万视觉—语言—相机三元组和 100 万轨迹。
- **Coding 接口：**提供 Python 脚本完成单图相机理解、文本加相机条件生成、多视角 RGB-D 生成、点云重建和自校准探索。
- **场景：**空间设计预览、数字孪生初始化、机器人导航界面、可遍历背景资产。
- **成熟度 / 证据：**已开源、可运行研究原型；**论文实测**。目前主要面向静态场景，物理状态基本限于重力和纬度。
- **许可 / 优先级：**S-Lab License 1.0，仅允许非商业使用；重要性高，必读。

### 3. WorldReward：把相机动作执行和视觉质量变成可服务化奖励

- **类型 / 日期 / 主线：**论文、reward model、benchmark、GitHub；2026-09-03；世界模型评测、Coding。
- **官方链接：**[论文](https://arxiv.org/abs/2609.03952)、[代码](https://github.com/CodeGoat24/WorldReward)、[9B 权重](https://huggingface.co/CodeGoat24/WorldReward-qwen35-9b)、[WorldReward-Bench](https://huggingface.co/datasets/CodeGoat24/WorldReward-Bench)。
- **相对上期：**首次收录。
- **核心贡献：**按动作切分长视频，将每段转为结构化视觉证据，再分别投票判断动作、外观和运动质量，避免短暂动作被长上下文稀释。760 对、9 类世界模型的人类标注 benchmark 上，9B 模型三项一致率为 77.63%、81.32%、73.03%。
- **Coding 接口：**提供 Python API、批处理 JSONL、vLLM 服务及基于 HunyuanVideo-1.5/HY-WorldPlay 的 RL post-training 代码。
- **场景：**生成世界 CI、模型回归测试、候选采样排序、RL 奖励服务。
- **成熟度 / 证据：**已开源、Apache-2.0；**论文实测**，尚无独立复核。
- **判断：**重要性高，必读；它是目前最接近“生成世界单元测试”的可接入组件。

### 4. Principia：证明视觉逼真不能替代物理验收

- **类型 / 日期 / 主线：**论文、benchmark、synthetic pipeline；2026-09-03；世界模型评测。
- **官方链接：**[论文与完整实验](https://arxiv.org/html/2609.04200)。
- **核心贡献：**用同一物理规律下两个对象之间的相对关系消除尺度、帧率和相机标定依赖，覆盖重力、摩擦、动量、恢复系数、转动惯量、抛体、摆和弹簧。包含 500 余个真实场景及 Isaac Sim 反事实生成管线。
- **关键结果：**六种生成器的 Principia 得分为 0.14–0.42，而 VBench 均约 0.8；最佳 VLM 对物理违例的识别准确率也仅 67%。
- **Coding 接口 / 场景：**可将关系不变量写成物理验收规则，用于仿真数据过滤、world-model CI 和安全关键训练集筛选。
- **成熟度 / 证据：**benchmark 研究原型；**论文实测**。项目页可访问，但本次未确认独立代码仓库及数据许可证。
- **判断：**重要性高，必读。

### 5. Compile by Training：把自然语言角色规则编译成本地神经函数

- **类型 / 日期 / 主线：**论文、编译服务、SDK、demo；2026-09-03；Coding × 互动作品、数字角色。
- **官方链接：**[论文](https://arxiv.org/html/2609.04199)、[在线服务](https://programasweights.com/)。
- **核心贡献：**教师模型在构建阶段生成样本，训练共享 0.6B interpreter 的小型 adapter；产物可缓存、版本化和组合，运行时无需再次调用教师模型。FuzzyBench-Hard 语义准确率由快速编译器的 22.4% 提升到 83.6%。
- **Coding 接口：**`Compile(spec) → program`、`Run(program,input)`；Avatar Director 把自然语言转换为支持顺序、时长、重复和并行动作的 DSL，浏览器先验证再驱动 3D 角色，44 个指令中 43 个结构正确。
- **工程指标：**冷编译约 50.9 秒/B300、68.2 秒/H200、99.2 秒/RTX；适合构建阶段，不适合逐帧在线学习。
- **场景：**本地 NPC 意图路由、内容审核、手势编排、低成本高并发互动装置。
- **成熟度 / 证据：**公开服务和 demo；**论文实测**。通用编译器完整开源状态仍需核验。
- **判断：**重要性高，必读。

### 6. Text-Audiobox：全双工、情感与配音进入统一音频生成框架

- **类型 / 日期 / 主线：**论文、音频模型；2026-09-03；数字人、支撑基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2609.03992)。
- **核心贡献：**3B flow-matching DiT 以 DAC-VAE 将 48kHz 音频压缩至 25Hz latent；用 cross-attention 学习文本—语音对齐，取消强制对齐和显式时长预测。支持双通道重叠语音、turn-taking、backchannel、情感条件和跨语言配音。
- **Coding 接口：**论文给出多扩散长音频方案，但未发布 API、代码或权重。
- **场景：**互动角色对话音轨、多人播客、影视配音、可插话数字员工。
- **成熟度 / 证据：**研究原型；**论文实测**。30 秒 chunk、20 秒 overlap 说明它更接近离线长对话合成，不能直接视作低延迟语音 runtime。
- **判断：**重要性高，必读。

### 7. ERICA / Teleco：数字化身在嘈杂公共空间完成多人交互 PoC

- **类型 / 日期 / 主线：**论文、真实场地 PoC；2026-09-01；数字人、产业案例。
- **官方链接：**[论文与系统细节](https://arxiv.org/html/2609.00648)。
- **核心贡献：**四通道 ReSpeaker 同时承担多人语音增强、增量 ASR 和远程操作者空间音频；Teleco 结合 SLAM、YOLO、人机位置跟踪、WebRTC、口型同步和 GPT-4.1 对话支持。
- **实测：**实验室 CER 为手持麦克风 7.87%、静止/运动 Teleco 6.71%、噪声环境 7.18%；大阪世博会场运行六天，ERICA 记录 513 次互动，但因隐私约束没有正式主观评测。
- **Coding 接口：**事件按钮控制辅助 agent 的 ask/suggest/back-me-up 行为，VAP 模型控制轮次和反馈语，传统状态机控制队形与安全移动。
- **成熟度 / 证据：**现场 PoC；**论文实测 + 作者现场报告**，尚非规模化部署。
- **判断：**重要性中高，必读。

### 8. GIFT：让世界模型的中间表示真正服务于机器人动作

- **类型 / 日期 / 主线：**论文、机器人实验；2026-09-03；世界模型、工业应用。
- **官方链接：**[论文](https://arxiv.org/html/2609.04193)。
- **核心贡献：**用几何、对象—末端执行器 affordance 和目标区域监督训练 VLA/WAM 中间特征；默认不把辅助预测注入动作头，部署时不增加几何教师成本。
- **结果：**在 LIBERO-Plus 上三种配置相对匹配基线提升 4.6、12.6、5.2 个百分点；RoboCasa 提升 12.6、9.0、8.4 个百分点，并有 xArm7、ARX X5 实机实验。
- **Coding 接口 / 场景：**作为训练损失插件接入直接动作扩散、快速 WAM 或逆动力学 WAM；用于高精度装配和铰接物操作。
- **成熟度 / 证据：**研究原型；**论文实测**。项目页存在，未确认代码/权重开放。
- **判断：**重要性高，必读。

### 9. SPAR3S：把稀疏视角场景补全改写成稀疏体素 token 预测

- **类型 / 日期 / 主线：**论文；2026-09-03；世界模型、3D 基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2609.03931)。
- **核心贡献：**只为占据体素保存 latent，以 masked autoregressive transformer 同时预测空间占据和内容；训练依靠可微 3DGS 的图像监督，不需要真实 3D 标注。
- **Coding 接口 / 场景：**适合作为扫描不完整空间到可遍历资产的离线构建节点，后接 3DGS/mesh 导出和引擎碰撞重建。
- **成熟度 / 证据：**论文原型，代码与许可证未确认；**论文实测**。
- **判断：**重要性中，可读。

### 10. 实时 3DGS 调色：神经资产开始具备 DCC 式局部编辑

- **类型 / 日期 / 主线：**论文、交互编辑算法；2026-09-03；3D/4D 基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2609.03897)。
- **核心贡献：**重参数化预训练 3DGS 的球谐系数，支持调色板、独立亮度曲线和像素级约束；编辑在数十毫秒完成，并可烘焙回标准 3DGS。
- **Coding 接口 / 场景：**可包装为引擎编辑器滑杆、剧情状态驱动的灯光/材质事件或虚拟制作调色节点。
- **成熟度 / 证据：**研究原型；**论文实测**，未确认代码开放。
- **判断：**重要性中，可读。

### 11. Editable Visual Design：生成模型负责视觉先验，coding agent 交付可编辑结构

- **类型 / 日期 / 主线：**论文、GitHub、Codex Skill；2026-09-03；Coding × 创作工具。
- **官方链接：**[论文](https://arxiv.org/abs/2609.04034)、[Apache-2.0 仓库](https://github.com/yejy53/Editable-Design)。

- **与本报告主线的关系：**虽然当前案例是海报而非世界模型，但其“生成先验—结构化代码—确定性验收—可继续编辑”范式可直接迁移到互动网页、HUD、数字展陈和角色控制台。
- **成熟度 / 证据：**已开源、可运行工具；论文结果主要为作者验证。
- **判断：**重要性中，可读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**本周期没有新的高质量 talking-head、单图 3D/4D avatar 或 streaming portrait 核心模型。GWM Worlds 2 的角色支持自然语言动作、对白、语调、语言和自动口型，但角色身份跨长时段稳定性没有量化。
- **3D/4D 表示：**无直接数字人新增。Puffin-World、SPAR3S 和实时 3DGS 编辑提供的是场景级空间底座，可承担数字人的环境、自由视点背景和资产后处理。
- **实时交互：**最实质进展来自运行时。GWM Worlds 2 将角色、场景与相机动作统一为事件流；ERICA/Teleco 则证明麦克风阵列、VAP、ASR、LLM、WebRTC、SLAM 和传统安全控制必须协同，单个数字人模型不足以形成公共空间产品。
- **音视频与情感：**Text-Audiobox 把 turn-taking、重叠语音、backchannel 和情感轨迹纳入联合生成；但它没有证明流式低首包延迟。GWM Worlds 2 更接近实时音画一体，证据仍只有官方 demo。
- **工程部署：**公共场所应用当前更成熟的路线依然是组件化栈：独立 ASR/VAP/LLM/TTS/口型/机器人控制，而非端到端生成视频。
- **安全与身份治理：**本周期没有新水印或肖像授权基础设施。新发布的[音乐元宇宙威胁分析](https://arxiv.org/abs/2609.03659)将 avatar impersonation、表达/神经生理数据泄漏和实时流中断列为重要风险，并建议实时媒体路径使用 SRTP/DTLS、边缘处理和数据最小化；证据来自 13 个组织、14 名利益相关者，规模较小，应视为设计建议。

## 5. 世界模型进展

- **架构与训练：**GWM Worlds 2 代表“离线双向扩散模型经后训练转为因果自回归模型”；Puffin-World 则代表将 RGB、深度和物理朝向作为联合状态，而不是全隐含在像素 latent 中。
- **可控 / 可玩：**WorldPrompt 已支持角色寻址、并行动作、对白和连续相机流，明显强于只有 WASD 或相机轨迹的控制接口。
- **长时与物理一致性：**“无限生成”只是无固定时长，不等于无限一致。Runway 明确承认滑动窗口遗忘；Principia 进一步量化了视觉质量与物理正确性脱钩。
- **空间表示：**Puffin-World 的 RGB-D 与重力坐标、SPAR3S 的稀疏体素 latent，显示显式空间状态重新成为主流补充，而非完全依赖视频上下文。
- **机器人 / 游戏 / 仿真：**GIFT 说明像素预测需要结构监督才能转化为动作；GWM Worlds 2 展示 agent 控制，但只有简单到达旗帜任务，不能据此判断复杂规划能力。
- **部署与评测：**WorldReward 已能作为 Python/vLLM 奖励服务；Principia 更适合作为离线物理回归集。两者共同说明未来 world-model serving 需要与测试、回滚和规则引擎一起部署。

## 6. Coding × 新型互动作品

### 链路一：持久世界设定 → WorldPrompt 事件流 → 实时音视频 → 多人互动电影

LLM 或创作工具生成 genesis prompt、角色表和键位动作；游戏服务器维护角色权限和剧情状态；GWM Worlds 2 生成画面、声音与表演；LiveKit 向多个参与者广播。由此可构建玩家、演员、导演共同操控的互动电影。当前有官方多人 demo，但没有公开 API 和成本数据，属于可运行研究预览。

### 链路二：NPC 语言意图 → 本地神经函数 → 已验证动作 DSL → 3D 角色

Compile by Training 在构建阶段把“角色如何理解自然语言”编译为 adapter；运行时仅输出受限 DSL，浏览器验证序列、时长和并行动作后驱动角色。模糊语义由模型完成，安全动作集合、碰撞和权限由代码掌握。适用于展馆 NPC、儿童教育角色和端侧游戏；已有网页 demo。

### 链路三：生成候选世界 → WorldReward 服务 → CI/RL → 更可控的版本

测试程序读取首帧、动作序列和两个候选视频，WorldReward 输出动作、外观、运动三轴偏好；CI 阻断明显回退，训练任务将结果用作 NFT/RL 奖励。互动作品因此可以像软件一样做 nightly regression，而不只靠创作者肉眼看片。代码、权重、benchmark 已开放。

### 链路四：物理脚本 → Isaac Sim/真实实验 → 关系不变量 → 世界模型验收

开发者用代码定义“两物体必须满足的相对关系”，Principia 管线生成或采集输入，再从生成视频中测量关系一致性。规则系统提供物理真值，生成模型负责外观和潜在动力学。可用于机器人合成数据、驾驶危险场景和训练模拟器；目前适合离线门禁，不适合逐帧实时反馈。

### 链路五：单图/文本 → RGB-D 与重力状态 → 点云/碰撞代理 → 可遍历空间

Puffin-World 按相机轨迹生成 RGB-D 和物理朝向，代码将结果重建为点云，并进一步生成导航网格、遮挡和碰撞代理；传统 Unity/Unreal/Godot 仍负责确定性物理与交互逻辑。可构建空间展览预览、数字孪生草模和机器人训练关卡。模型已开源，但目前是静态场景且商业许可受限。

### 链路六：多人语音 → 位置感知音频 → 对话 agent → 物理化身

麦克风阵列、人物位置、机器人姿态和 SLAM 决定监听通道；VAP 决定谁取得话轮；LLM 生成建议或总结；WebRTC 和机器人状态机输出声音、口型、视点与动作。ERICA/Teleco 证明这是比“单一会说话头像”更接近真实数字员工的架构，已完成展会 PoC。

### 链路七：视觉生成 → 结构化 HTML/CSS → 浏览器验收 → 可持续运行的品牌体验

图像模型生成视觉方向和难以编码的资产，coding agent 维护真实文本、组件、图层和交互逻辑，浏览器截图和确定性检查负责验收。当前开源案例以平面设计为主；把状态机和 WebGL/Three.js 加入同一结构，可进一步形成可编辑品牌展厅或互动信息空间。后半段属于**本报告推断**。

## 9. 系统架构与技术趋势判断

**明显升温：**

1. 世界状态从单一视频 latent 转向“全局持久上下文 + 事件流 + RGB-D/物理辅助状态”。
2. 评测从 FVD/VBench 转向动作执行、回环、物理不变量和人类偏好一致性。
3. coding agent 从一次性产出脚本转向生成 DSL、维护状态、运行浏览器/模拟器并自动验收。
4. 神经函数逐渐成为可构建、缓存、版本化的软件组件。

**正在成为主流的架构：**

`用户/agent → 受限动作协议 → 状态与权限服务器 → 生成世界/角色模型 → 实时媒体分发 → reward/physics verifier → 日志与回滚`

其中代码保存确定性真值、权限、库存、任务进度、多人同步和安全规则；生成模型承担感知外观、开放式表演、语音与不可枚举的环境变化；传统引擎继续负责碰撞、导航、计费和必须可复现的物理。

**仍未解决：**

- 滑动上下文导致的长时身份、物体和空间状态遗忘；
- 24fps 不等于低输入延迟，公开材料缺少端到端 p50/p95 延迟；
- 开放式文本动作难以映射为稳定、可测试的状态变化；
- 视觉合理但物理错误，且现有 VLM verifier 本身不可靠；
- 并发成本、GPU 利用率、故障恢复、内容审核、肖像授权和水印基本未披露；
- 生成 RGB-D/点云与工业级 mesh、碰撞体、CAD/BIM 资产之间仍有明显缺口。

**营销或工程包装风险：**

GWM Worlds 2 的视频证据很强，但“无限世界”“机器人仿真”仍主要是官方场景演示；简单旗帜导航不足以证明复杂 agent 训练价值。Text-Audiobox 的“full-duplex”指联合生成双通道对话，不应自动解读为实时可打断 API。Editable Visual Design 已有完整工具链，但当前证据集中在固定画布设计，将其推广到持续运行的 3D 世界仍需工程验证。

## 10. 论文精读候选

1. **[GWM Worlds 2 技术发布](https://runway.com/research/introducing-gwm-worlds-2)**  
   值得读：最完整的实时生成世界产品架构。重点读 WorldPrompt、Real-Time Generation、Model Overview、Using the Model 和 Limitations。差异在于原生音视频与角色/场景寻址；风险是无论文、权重和第三方评测。

2. **[Puffin-World](https://arxiv.org/abs/2609.04196)**  
   值得读：将物理、几何和外观作为原生状态。重点读 Omni-Camera、physics propagation、Puffin-16M 和 closed-loop exploration。差异是联合 RGB-D/重力生成；复现风险是模型复杂、显存未披露、仅非商业许可。

3. **[WorldReward](https://arxiv.org/abs/2609.03952)**  
   值得读：直接可用于世界模型 CI 和 RL。重点读 action-aligned chunking、数据审计、WorldReward-Bench、HY-WorldPlay post-training。风险是训练标签部分来自前沿 VLM，可能继承 judge 偏差。

4. **[Principia](https://arxiv.org/html/2609.04200)**  
   值得读：给出“画质不等于物理”的强证据。重点读关系不变量、真实数据采集、Isaac Sim pipeline 和 per-phenomenon results。风险是可测现象仍以刚体经典力学为主。

5. **[Compile by Training](https://arxiv.org/html/2609.04199)**  
   值得读：展示神经能力如何成为软件构建产物。重点读异步编译服务、缓存、Avatar Director DSL 和延迟实验。差异是将教师模型移出运行时；风险是语义评分依赖 LLM judge，且完整编译基础设施开放程度有限。

## 11. 下周跟踪与可行动建议

### 持续跟踪问题

1. GWM Worlds 2 是否会开放实时 API、Unity/Unreal 插件或 WebRTC 输入接口？
2. 其输入到画面的 p50/p95 延迟、每会话 GPU 和分钟成本是多少？
3. WorldPrompt 是否形成公开 schema，能否保存、回放和确定性比较世界状态？
4. Puffin-World 在消费级 GPU 上的显存、生成速度和点云可用性如何？
5. WorldReward 对非相机动作、角色交互、对白和对象状态变化能否泛化？
6. Principia 数据、Isaac Sim 场景和评分代码何时完整开放？
7. Text-Audiobox 是否发布流式版本、权重或实时因子明细？
8. 角色身份授权、水印和事件日志能否进入生成世界的标准运行时协议？

### 本周可动手实验

#### 实验一：世界模型的自动化动作回归测试

- **目标：**验证 WorldReward 能否发现自用生成模型的相机动作退化。
- **组件：**WorldReward、20 个首帧、四类相机轨迹、两个模型版本。
- **难点：**统一帧率与动作分段，控制内容风格差异。
- **成功判据：**奖励排序与人工三轴判断一致率超过 75%，并能定位至少三类稳定回归。

#### 实验二：可审计的自然语言 3D 角色控制

- **目标：**复刻“神经意图解析 + 确定性 DSL + 浏览器角色”架构。
- **组件：**本地小模型或 PAW demo、动作 DSL、Three.js/GLTF、JSON Schema 验证器。
- **难点：**组合动作、超时、越权命令和自然语言歧义。
- **成功判据：**50 条指令中至少 90% 正确执行；全部未注册动作在渲染前被拒绝并留下日志。

#### 实验三：RGB-D 世界资产进入传统引擎

- **目标：**判断 Puffin-World 输出能否变成可导航而非仅可观看的空间。
- **组件：**Puffin-World、点云清理、mesh/碰撞代理生成、Unity 或 Godot。
- **难点：**尺度、孔洞、漂浮几何、商业许可。
- **成功判据：**单图生成场景可在引擎中稳定自由移动，碰撞误触率低于 10%，重返起点时主要结构无明显错位。

#### 实验四：公共空间多人数字员工最小闭环

- **目标：**验证噪声环境下两名用户、一个虚拟角色的轮次体验。
- **组件：**四通道麦克风、增量 ASR、VAP、LLM、流式 TTS、Web avatar。
- **难点：**重叠说话、回声、错误抢话、端到端延迟。
- **成功判据：**噪声场景 CER 不高于 10%，错误抢话率低于 10%，用户停止讲话至角色开始回应的 p95 小于 1.5 秒。
