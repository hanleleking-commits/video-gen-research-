# 数字人、世界模型与互动作品研究日报：2026-10-23

检索窗口：2026-10-17 至 2026-10-23。  
信息截点：2026-10-23 09:00（Asia/Shanghai）。论文日期按 arXiv 原始提交时间记录；已与 10 月 17—22 日日报去重。

## 1. 本日摘要

最近七天最明确的变化，是世界模型开始从“单用户视频生成器”走向带有多人控制协议、显式状态和可测试运行时的系统。LiveAct首次用统一模型接收游戏按钮和机器人关节指令等异构、多主体动作流，并在单 GPU、512×448 下达到作者报告的 17.70 FPS；但GPU型号、端到端输入延迟和并发数据尚未披露。

WorldStream代表另一条更偏工程的路线：大模型负责分层规划，确定性代码负责编译地形、道路和实体，持久化 world record 保存对象身份、修改和跨区边界。它说明可持续生成世界未必需要逐帧神经渲染全部状态，程序化系统仍是可靠交互的核心。

CADRE进一步指出，世界模型的延迟不仅由生成器决定，视频autoencoder的时空压缩方式会直接决定一次动作需要等待多久；导航与固定相机操作甚至需要相反的压缩策略。

数字人方向没有新的高质量语音驱动头像、口型同步或全双工情感模型。新增主要来自可编程角色资产：RealMe以稀疏低清拍摄生成2K、跨视角一致的体积视频，RLMuscle则开放了可实时运行的肌肉形变物理引擎。

Coding × 互动作品方面，GenXR-Bench把coding agent放进真实XR运行时测试，最强配置Pass@1仍只有50.9%，主要失败于异步传感器生命周期、物理落地和具身交互语义。这表明“能生成代码”与“能生成持续可靠的空间应用”之间仍有明显差距。

VoxProg、AutoPhyX和Pair-Free C2R共同勾勒出一条可落地资产管线：agent生成几何程序，语言生成材料属性，传统引擎执行物理，视频模型负责最终视觉提升。该链路的组件正在出现，但端到端集成仍主要属于本报告推断。

证据总体以论文作者实测和开放代码为主，尚未发现本周期新增的客户试点或规模化产业部署。直播数字人、企业数字员工和实时虚拟主播本周期暂无足以改变成熟度判断的新增。

## 3. 最值得关注的 11 个进展

### 1. LiveAct：实时、多主体、异构动作世界模型

- **类型 / 日期 / 主线：**论文、项目demo、dataset；2026-10-21；世界模型、Coding × 互动。
- **官方链接：**[论文](https://arxiv.org/abs/2610.29408)、[项目页](https://liveact-ai.github.io/)。
- **相对上期的新变化：**首次收录。相较上期Multics侧重多玩家通信，LiveAct进一步统一了按钮、车辆控制与连续机器人关节指令。
- **核心贡献：**用语言描述每个主体及控制槽含义，再以主体感知空间调制和逐主体cross-attention，把不同动作流绑定到正确角色。训练覆盖四款游戏和两个多机器人数据源，共17,951条轨迹、119.54小时。
- **作者实测：**DMD蒸馏版本在512×448、单GPU、每块4步去噪下达到17.70 FPS；游戏/机器人主体归因准确率分别为0.898/0.942。GPU型号和动作到显示的p95延迟未披露。
- **Coding接口：**动作可表示为“主体描述＋控制schema＋逐帧数值流”，适合由游戏服务器、机器人中间件或网络会话层生成；截至截点未见可下载代码或权重。
- **场景：**多人生成式游戏观察、协作机器人仿真、多角色互动表演。
- **成熟度 / 证据：**可运行官方demo；论文作者实测。
- **重要性 / 阅读：**高 / 必读。

### 2. WorldStream：用代码编译持久、开放的3D世界

- **类型 / 日期 / 主线：**论文、系统原型；2026-10-20；世界模型、Coding × 互动。
- **官方链接：**[论文](https://arxiv.org/abs/2610.28827)。
- **相对上期的新变化：**首次收录。它把上期“显式状态＋生成表现”的判断落成了较完整的程序世界架构。
- **核心贡献：**Macro planner规划聚落、生态、水系和交通，Micro planner细化地块语义；确定性代码将计划编译为地形、道路、植被和实体。world record持久保存seed、对象身份、边界约束、修改和NPC状态。
- **Coding接口：**typed decision state、tile compiler、对象属性编辑和重访重编译，本质上是可版本化的世界数据库加程序化构建器。
- **场景：**无限开放世界、长期品牌空间、数字孪生导览、可持续NPC社区。
- **限制：**未见代码、SDK、帧率、内存预算或大规模玩家测试。
- **成熟度 / 证据：**论文与作者demo级原型。
- **重要性 / 阅读：**高 / 必读。

### 3. CADRE：为互动世界模型重新设计视频autoencoder

- **类型 / 日期 / 主线：**论文、模型权重、live demo；论文提交2026-10-21，官方博客2026-10-22；世界模型基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2610.30129)、[官方发布](https://kyutai.org/blog/2026-10-22-cadre/)。
- **相对上期的新变化：**首次把autoencoder压缩方式与动作等待时间直接绑定，而非只评测重建画质。
- **核心贡献：**构建多种时空压缩率的因果扩散表示autoencoder，并以一至数步蒸馏decoder降低解码成本。作者发现固定相机操作适合更强时间压缩，移动相机导航更依赖空间压缩；粗空间token可能先损伤运动而非静态画质。
- **Coding接口：**可作为世界模型runtime中可替换的codec层；官方已列出模型和live demo入口。
- **场景：**机器人遥操作、低延迟可玩视频、世界模型服务。
- **成熟度 / 证据：**开放模型与demo；论文作者实测。
- **重要性 / 阅读：**高 / 必读。

### 4. GenXR-Bench：在真实XR运行时测试coding agent

- **类型 / 日期 / 主线：**论文、benchmark、GitHub；2026-10-21；Coding × XR互动作品。
- **官方链接：**[论文](https://arxiv.org/abs/2610.29014)、[CC BY 4.0仓库](https://github.com/whuang37/genxr-bench)。
- **核心贡献：**112项任务覆盖24个功能实现、21个bug修复和67个完整XR应用生成；测试同时使用脚本化/自适应交互、程序断言和视觉断言。
- **结果：**测试器与124个候选应用的盲评专家判断达到96.5%一致；10个模型中最强配置总体Pass@1为50.9%。
- **Coding接口：**基于XR Blocks SDK、Harbor、Docker和自动verifier；单任务容器要求约4 GB内存、10 GB存储。
- **场景：**XR培训、空间导览、互动原型和空间计算应用CI。
- **成熟度 / 证据：**benchmark已开源；论文实测。
- **重要性 / 阅读：**高 / 必读。

### 5. RealMe：稀疏低清拍摄生成2K体积视频

- **类型 / 日期 / 主线：**论文、demo、待开放代码；2026-10-21；数字人、4D表示。
- **官方链接：**[论文](https://arxiv.org/abs/2610.30023)、[项目页](https://zju3dv.github.io/realme/)、[仓库](https://github.com/zju3dv/RealMe)。
- **核心贡献：**从720p稀疏多视角素材构建粗4D表示，再由高分辨率视频扩散模型生成2K增强视图；时间、视角和空间位置共同编码，以改善人物面部、毛发、服装和跨视角一致性。
- **Coding接口：**预期管线为捕获视频、辅助新视角渲染、扩散增强和4D重建优化；仓库明确写明代码仍在内部审核。
- **场景：**体积人像、虚拟演出、自由视角教育内容、影视数字替身。
- **成熟度 / 证据：**论文和demo；代码未发布，PRL v1.0仓库不等于可运行实现。
- **重要性 / 阅读：**高 / 必读。

### 6. RLMuscle：开放的实时肌肉驱动角色形变

- **类型 / 日期 / 主线：**论文、GitHub、dataset、物理引擎；2026-10-21；数字人、角色运行时。
- **官方链接：**[论文](https://arxiv.org/abs/2610.30033)、[项目页](https://chunleili.github.io/project-page-rlmuscle/)、[代码](https://github.com/chunleili/rlmuscleV2)。
- **核心贡献：**RL控制器在轻量1D Hill肌肉代理中学习逐肌肉激活，再将同一激活送入3D XPBD体积求解器；EMG先验约束肌肉募集模式。
- **工程数据：**公开实现基于NVIDIA Warp，支持USD、PLY和Houdini `.geo`；作者在RTX 4090上报告172K顶点人体仿真18 ms/帧、约98 MiB峰值GPU内存，不含CUDA/Warp上下文。
- **Coding接口：**JSON配置、Python示例、USD导出和3.32 GB资产集，可接入DCC或引擎资产流程。
- **场景：**游戏角色、数字替身、体育训练可视化、影视肌肉形变。
- **成熟度 / 证据：**代码和资产已开放；研究级物理组件。
- **重要性 / 阅读：**高 / 必读。

### 7. Looking Ahead：用未来块监督训练世界演化

- **类型 / 日期 / 主线：**论文、代码、权重；2026-10-21；世界模型基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2610.29989)、[GitHub](https://github.com/TencentARC/Looking-Ahead)、[项目页](https://hellorpg.github.io/looking-ahead/)。
- **核心贡献：**Future Chunk Prediction让当前表示直接预测隔开的未来块，避免teacher forcing仅依赖相邻帧冗余；训练结束后删除辅助分支，不增加推理开销。
- **Coding接口：**已开放训练与推理代码、Wan系1.3B/5B权重和demo数据；官方环境为Linux、Python 3.12、CUDA 12.8，并在H200上测试。
- **场景：**长时视频、世界模型预训练、交互视频后端。
- **成熟度 / 证据：**已开源研究组件；论文作者实测。
- **重要性 / 阅读：**高 / 必读。

### 8. VoxProg：用可执行体素程序完成3D放置

- **类型 / 日期 / 主线：**论文、benchmark、项目demo；2026-10-21；Coding × 3D。
- **官方链接：**[论文](https://arxiv.org/abs/2610.30127)、[项目页](https://voxprog.github.io/)。
- **核心贡献：**VLM先生成evidence program，在局部体素网格中构造边界、支撑面和槽位，再生成pose program计算SE(3)放置；运行结果可反馈给agent修改程序。
- **作者实测：**在71项VoxProg-Bench任务上，Intent Alignment rank score为83.10，物理有效率95.8%。
- **Coding接口：**自然语言转Python几何程序；项目页显示代码“Coming soon”。
- **场景：**场景布置、机器人放置、自动关卡搭建、空间商品陈列。
- **成熟度 / 证据：**论文与demo，尚不可独立复现。
- **重要性 / 阅读：**高 / 必读。

### 9. AutoPhyX：语言生成可仿真的3D材料属性

- **类型 / 日期 / 主线：**论文、GitHub、dataset；2026-10-21；世界模型、物理仿真。
- **官方链接：**[论文](https://arxiv.org/abs/2610.29517)、[项目页](https://hb-pencil-zero.github.io/AutoPhyX/)、[代码](https://github.com/HB-pencil-zero/AutoPhyX)。
- **核心贡献：**以文本消除“外观相似但刚度、密度不同”的歧义，预测Young模量、Poisson比和密度的稠密体素场；结果可转移至mesh、点云、Gaussian Splatting和NeRF。
- **Coding接口：**开放数据增强、训练、checkpoint验证和物理属性导出脚本；可将输出交给MPM或FEM求解器。
- **场景：**数字孪生、软体仿真、机器人操作、物理互动资产。
- **成熟度 / 证据：**已开源研究组件；未披露推理延迟和引擎插件。
- **重要性 / 阅读：**中高 / 必读。

### 10. Pair-Free C2R：用普通真实视频训练“引擎画面到写实视频”

- **类型 / 日期 / 主线：**论文、待发布模型；2026-10-20；Coding × 虚拟制作。
- **官方链接：**[论文](https://arxiv.org/abs/2610.28954)。
- **核心贡献：**先用易获取的“真实图像—粗糙图像”对训练DINO-R2C，再把普通真实视频变成伪粗糙视频，训练粗糙动画到写实视频的转换器；推理时直接接收游戏或仿真渲染序列。
- **Coding接口：**理论上可把Unity、Unreal、Blender或机器人仿真的低成本render pass作为控制输入。
- **场景：**虚拟制作、游戏宣传片、训练仿真写实化、互动电影视觉层。
- **成熟度 / 证据：**论文原型；作者承诺发布模型，但截至截点尚不可复现。
- **重要性 / 阅读：**中高 / 可读。

### 11. CausalAlign：用3D表示修正长时相机运动漂移

- **类型 / 日期 / 主线：**论文；2026-10-21；世界模型、机器人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.29915)。
- **核心贡献：**通过探针和因果干预定位视频模型中相机运动信息的有效层，再把相邻帧变化的delta-token与3D基础模型对齐。
- **作者声称：**在Wan2.2实验中几何一致性相对基线提升超过20%，RoboCasa365移动操作任务的WAM成功率提升10个百分点。
- **Coding接口：**属于模型微调方法，尚无公开代码或runtime接口。
- **场景：**第一人称可玩视频、移动机器人预测、虚拟摄影。
- **成熟度 / 证据：**论文作者实测；重要性中高 / 可读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**本周期没有新的高质量talking-head、audio-driven portrait或lip-sync模型。不要把体积视频和角色物理误写成实时对话数字人的突破。
- **3D/4D表示：**RealMe降低了高质量体积人物对密集相机和高分辨率采集的依赖，但仍需多视角输入和离线优化。
- **全身动画：**RLMuscle补上了骨骼动作到肌肉激活、再到体积形变的可编程链路；它比纯神经表面变形更适合需要生物力学解释的角色。
- **实时交互：**RLMuscle的18 ms/帧意味着物理形变本身可进入实时预算，但完整角色还需骨骼、皮肤、毛发、服装、碰撞和渲染。
- **音视频与情感表达：**本周期暂无高质量新增。
- **工程部署：**RLMuscle可直接验证；RealMe仍缺公开代码。两者均不是开箱即用的数字员工或虚拟主播系统。
- **安全与身份治理：**本周期未发现新增的肖像授权、撤回、水印、溯源或深伪检测闭环。

## 5. 世界模型进展

- **架构与训练：**LiveAct为动作流增加主体和schema语义；Looking Ahead强迫模型学习远期演化；CADRE针对动作延迟选择时空压缩。
- **可控与可玩：**LiveAct已证明一个模型能接收2—4个主体的离散或连续动作，但241帧长rollout仍出现姿态和位置误差累积。
- **长时与持久状态：**WorldStream不依赖视频上下文保存全部历史，而是通过world record保存seed、对象身份、编辑和NPC状态，再确定性重建返回区域。
- **物理一致性：**AutoPhyX解决材料参数输入，CausalAlign解决相机运动保持；二者分别作用于传统仿真和神经视频预测。
- **空间表示：**体素程序、材料场、显式world record和动作schema正在成为模型与代码之间的中间协议。
- **实时部署：**LiveAct给出17.70 FPS吞吐，但缺少输入采集、网络、解码和显示后的端到端延迟。FPS不能替代交互延迟。
- **评测：**GenXR-Bench表明视觉正确性、功能正确性和运行时正确性必须分别检查。

## 6. Coding × 新型互动作品

### 链路一：多人生成式游戏与机器人观察器

**玩家/机器人动作 → 服务器生成主体描述和动作schema → LiveAct → 多主体共享视频 → 客户端播放**

代码负责房间、身份、权威状态、动作校验、网络同步和失败回退；模型负责预测共享视觉未来；传统引擎仍应保存碰撞、得分和库存。已有实时demo证据，但无公开服务实现。

### 链路二：可持续扩展的开放3D世界

**用户移动或语言编辑 → Macro/Micro planner → typed world record → 确定性tile compiler → 引擎渲染**

代码负责持久状态、边界、对象ID、存档和重访；模型负责规划和解释开放语言；传统引擎负责几何、物理和渲染。WorldStream有系统原型证据，尚无开源实现。

### 链路三：从自然语言到物理可交互资产

**自然语言摆放要求 → VoxProg生成体素程序 → SE(3)放置 → AutoPhyX生成材料场 → MPM/FEM或游戏物理 → 互动道具**

代码负责几何测量、碰撞检查和求解器调用；模型负责语义解释与材料先验；传统物理负责真实演化。各组件有论文或代码证据，端到端链路属于本报告推断。

### 链路四：高保真数字角色

**动捕/生成骨骼动作 → RLMuscle激活控制 → XPBD体积形变 → USD → DCC/引擎 → 实时角色表演**

代码负责骨骼映射、仿真参数和资产导出；RL控制器负责肌肉激活；引擎负责最终渲染、服装与交互。核心物理组件已有公开代码，可立即验证。

### 链路五：低成本引擎预演到写实互动影像

**Unity/Unreal粗糙渲染 → Pair-Free C2R → 写实视频层 → 事件系统叠加UI/数字人 → 互动电影或虚拟制作**

引擎保持镜头、人物轨迹和规则；视频模型负责最终视觉；代码负责镜头切换、交互分支和回滚。目前只有论文证据，模型尚未发布。

### 链路六：XR应用的agent开发与自动验收

**需求 → coding agent修改XR项目 → Docker构建 → 模拟/真实交互 → 程序与视觉断言 → 失败反馈修订**

GenXR-Bench已提供运行证据。其50.9%最佳Pass@1说明agent适合辅助实现和修复，但尚不适合在无人审核条件下交付安全关键XR应用。

## 9. 系统架构与技术趋势判断

明显升温的方向是：多主体动作协议、显式持久状态、世界模型专用codec、可执行3D程序、语言条件物理属性和真实运行时评测。

逐渐成为主流的系统分层是：

1. **权威状态层：**数据库、world record或传统引擎保存身份、规则、物理状态和权限。
2. **规划与编程层：**LLM/VLM生成typed plan、体素程序、SE(3)姿态或资产配置。
3. **预测层：**动作条件世界模型预测视觉未来或机器人结果。
4. **表现层：**体积视频、写实化视频、数字人、语音和角色形变产生用户可见输出。
5. **执行层：**游戏引擎、XR runtime、XPBD、FEM/MPM和RTC保证确定性与低延迟。
6. **验收层：**功能断言、视觉judge、物理有效性、延迟与长rollout回归阻止错误进入生产。

正在降温的是“用一个端到端视频模型替代引擎”的简单叙事。WorldStream、VoxProg和AutoPhyX均把代码、结构化状态或传统求解器放回系统核心；模型更适合负责不确定的规划、视觉和先验，而不是独占全部规则。

仍未解决的问题包括：多人权威状态与生成观察的一致性、数分钟后的动作漂移、世界模型的端到端p95延迟、可恢复存档、数字人实时服装/毛发、引擎插件、商业许可证、肖像授权和规模化服务成本。

RealMe的仓库尚无实现，VoxProg代码仍为Coming soon，WorldStream只有论文；这些项目不应按“已开源”采购。LiveAct的17.70 FPS也不能直接推导为低延迟商业服务。

## 10. 论文精读候选

1. [LiveAct](https://arxiv.org/abs/2610.29408)：重点读HAI、主体空间调制、schema-guided action adaptation和DMD蒸馏；与Multics的主要差异是动作接口异构性与主体绑定。复现风险是代码、权重和GPU配置未公开。
2. [WorldStream](https://arxiv.org/abs/2610.28827)：重点读typed decision model、world record和tile streaming；价值在于展示模型规划与确定性编译的边界。风险是缺少开放实现和量化运行时数据。
3. [CADRE](https://arxiv.org/abs/2610.30129)：重点读时空压缩消融、因果decoder和导航/操作的差异；复现风险是多套codec与世界模型组合成本高。
4. [GenXR-Bench](https://arxiv.org/abs/2610.29014)：重点读真实设备测试、程序/视觉断言和失败分类；区别于传统代码benchmark的是持续传感器与空间交互。风险是模型API成本和设备环境差异。
5. [Looking Ahead](https://arxiv.org/abs/2610.29989)：重点读FCP目标、双源监督和物理一致性评测；区别于普通teacher forcing的是远期、隔块生成监督。风险是H200环境和长序列训练成本。

## 11. 下周跟踪与可行动建议

继续追踪：

1. LiveAct是否开放代码、权重、数据许可证、GPU型号及动作到显示的p95延迟。
2. WorldStream是否发布world record schema、tile compiler和可运行demo。
3. CADRE各压缩配置的许可证、显存、动作延迟及与现有世界模型的适配方式。
4. RealMe何时开放代码、RealVV数据和完整采集要求。
5. VoxProg代码与VoxProg-Bench何时发布，物理有效性是否能由第三方复现。
6. Looking Ahead在非H200 GPU和超过训练长度的rollout表现。
7. RLMuscle与Unity、Unreal、Houdini之间的USD往返、碰撞和服装耦合成本。
8. GenXR-Bench中coding agent失败是否能通过专用runtime skill、状态检查器或多轮执行反馈显著降低。

本周适合实施的小实验：

- **实时肌肉角色最小闭环：**运行RLMuscle人体示例并导出USD，导入现有DCC或引擎。难点是资产映射和坐标系；成功判据是稳定达到30 FPS以上且无明显骨骼穿透。
- **XR coding agent回归测试：**在GenXR-Bench选择一个功能、一个bug和一个完整应用任务。难点是视觉verifier与异步事件；成功判据是三类任务均能自动构建、执行并输出可复现失败日志。
- **语言材料到软体仿真：**用AutoPhyX为同一网格生成“硬塑料”和“软橡胶”两套属性，再送入FEM/MPM。难点是单位和网格属性映射；成功判据是相同外力下形变排序符合文本，且结果无数值发散。
- **世界模型codec对照：**选固定相机操作和移动相机导航各一段动作序列，对比不同CADRE时空压缩。难点是统一下游生成器；成功判据是同时记录动作延迟、显存、运动误差和画质，验证两类任务的最优压缩配置确实不同。
