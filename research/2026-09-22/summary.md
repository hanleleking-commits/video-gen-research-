## 1. 本日摘要

本日最强信号来自世界模型工程化：Astronex-World 同时开放代码和权重，将相机轨迹、64 维连续动作、运行中事件注入和长时 KV cache 汇聚为可编程接口；这是本周期最完整的“代码驱动持续生成世界”资源。ZYT-World 则面向自动驾驶闭环，把七路异构相机、车辆动作、交通布局和地点记忆统一起来，官方报告两张 GPU 可达到七路约 720p、4 FPS，但尚未开放代码或生产级验证。

数字人侧没有新的完整 talking-head 产品，主要增量在身体语言和无障碍交互：GestureFAR 将实时共语手势降低到 9.3 ms/运动 token，SignGPT 首次以统一模型连接手语输入、LLM 回答和手语输出。OmniVBench 的发布则说明身份、动作、风格和叙事多参考绑定已成为视频角色系统的新评测对象，但训练数据版权和商业许可仍不清晰。

机器人世界模型继续从“预测漂亮视频”转向任务相关状态：MT-WAM 用点轨迹和视觉特征训练一次前向表示，部署时不生成未来视频；SkelWAM 用统一骨架状态实现跨机器人本体迁移；ME-Dex 把未来触觉与视频、动作一起预测。Coding 的职责也更明确：维护权威状态、动作协议、传感器映射、事件、约束、缓存和回退；模型负责连续媒体、未来状态或候选动作；传统物理引擎与 verifier 负责不可违反的接触和安全规则。

除 Astronex、CRISP 和 OmniVBench 外，多数新增只有论文或项目演示，缺少稳定代码、许可证、端到端延迟和并发数据。因此，本周期的研究增量较强，但可直接产品化的新增仍有限；身份授权、水印、深伪检测和数字人肖像治理方面暂无高质量新增。

## 3. 最值得关注的 11 个进展

### 1. Astronex-World 1.0：开放可编程实时世界模型

- **类型 / 日期 / 主线：**模型、GitHub、权重；2026-09-17；世界模型、Coding × 互动作品。
- **官方链接：**[论文](https://arxiv.org/abs/2609.20034)、[GitHub](https://github.com/Astronex-Robotics/Astronex-World)、[权重](https://huggingface.co/Astronex-Lab/Astronex-World)。
- **相对上期：**补录；此前日报未覆盖，本次确认代码、权重和后训练脚本均已开放。
- **核心贡献：**基于 Wan2.2-TI2V-5B，支持相机内外参、逐帧轨迹、64 维连续动作、32 种本体 ID，以及 rollout 中途插入文本事件；块因果注意力、滑动窗口和 sink frames 让显存不随时长增长。作者报告 832×480、24 FPS，可在单张 L20 48GB 上实时运行。
- **Coding 接口：**Python CLI、轨迹 DSL、事件帧参数、相机/action/SFT 三种 LoRA 后训练 recipe、动作输出头及环境变量式权重路径。
- **场景：**可探索视频、互动电影预演、生成式游戏原型、机器人/自动驾驶视觉仿真。
- **成熟度 / 证据：**已开源，Apache-2.0；作者实测，尚无第三方复核或生产 SLA。
- **重要性 / 阅读：**高 / 必读。

### 2. ZYT-World：七相机实时闭环自动驾驶世界模型

- **官方链接：**[论文](https://arxiv.org/abs/2609.21712)、[项目页](https://zyt-aim.github.io/ZYT-World/)。

- **Coding 接口：**设计上可接车辆控制、相机标定、感知框、航向和信号灯状态；但代码、数据和运行 API 未公开。
- **场景：**端到端驾驶策略闭环测试、长尾交通场景生成、跨轨迹地点回访。
- **成熟度 / 证据：**研究 demo；指标和“实时”均为官方/论文声称。
- **重要性 / 阅读：**高 / 必读。

### 3. GestureFAR：流式连续共语手势降至 9.3 ms/token

- **类型 / 日期 / 主线：**论文、demo；2026-09-18；数字人。
- **官方链接：**[论文及完整实验](https://arxiv.org/html/2609.21576v1)。
- **相对上期：**首次收录。
- **核心贡献：**以因果连续 motion latent 取代离散动作码本；只蒸馏 flow head，将八步采样压缩为一步。BEAT2 实验报告从 24.4 降至 9.3 ms/token，FGD 由 3.17 改善至 3.08。
- **Coding 接口：**适合封装为 `streaming audio → SMPL-X motion token` 服务，再连接 Unity/Unreal 骨骼重定向和 IK。
- **场景：**实时虚拟主播、数字员工、对话 NPC、远程化身。
- **成熟度 / 证据：**论文实测；项目页当前返回 404，未确认代码或权重。
- **重要性 / 阅读：**高 / 必读。

### 4. SkelWAM：统一骨架状态支持零样本跨本体操作

- **类型 / 日期 / 主线：**论文、benchmark、真实机器人实验；2026-09-18；世界模型。
- **官方链接：**[论文](https://arxiv.org/abs/2609.21983)。
- **相对上期：**首次收录。
- **核心贡献：**用机械臂中心线、TCP 位姿和夹爪命令形成统一 25 维状态，再由本体专用 decoder 转成关节或连续体机器人控制。LIBERO-Cross10 上，Franka 训练模型对十种目标本体取得 43.3% 成功率，论文称领先最佳基线 36.2 个百分点。
- **Coding 接口：**`统一骨架动作 → embodiment decoder → 关节控制`，无需一一对应关节。
- **场景：**机器人技能市场、设备换型、异构机器人统一控制层。
- **成熟度 / 证据：**研究原型与少量真实机器人验证；项目页访问不稳定，未确认代码。
- **重要性 / 阅读：**高 / 必读。

### 5. MT-WAM：训练时预测未来，部署时不渲染未来

- **类型 / 日期 / 主线：**论文；2026-09-18；世界模型、实时部署。
- **官方链接：**[论文](https://arxiv.org/abs/2609.21474)。
- **相对上期：**首次收录；与上期 MoWAM 方向一致，但新增点轨迹和视觉特征双重监督。
- **核心贡献：**训练阶段预测未来二维轨迹及视觉 feature，部署时只复用 video/motion cache 生成动作。论文报告 LIBERO-Plus 73.7%，比 Fast-WAM 高 23.8 个百分点；四项真实任务平均成功率由 67.0% 提升到 77.8%。
- **Coding 接口：**可作为 replanning 服务嵌入现有策略循环，不要求渲染视频。
- **场景：**低延迟机器人控制、候选动作筛选。
- **成熟度 / 证据：**论文实测；未发现公开代码或部署延迟。
- **重要性 / 阅读：**高 / 必读。

### 6. ME-Dex 1.0：把未来触觉加入世界—动作联合预测

- **类型 / 日期 / 主线：**论文、数据引擎；2026-09-18；世界模型、机器人。
- **官方链接：**[论文](https://arxiv.org/html/2609.21449v1)。

- **Coding 接口：**agentic data engine 回放轨迹并记录力传感器，形成视频—触觉—动作配对数据。
- **场景：**精密装配、双手协作、软物体和不可见接触操作。
- **成熟度 / 证据：**仿真及真实机器人研究验证；单次训练 seed，代码未公开。
- **重要性 / 阅读：**高 / 必读。

### 9. OmniVBench：评测多参考视频是否“正确绑定”角色与动作

- **类型 / 日期 / 主线：**benchmark、dataset；2026-09-18，资源于 9 月 21—22 日上线；数字人基础设施。
- **官方链接：**[论文](https://arxiv.org/abs/2609.22069)、[OmniVBench 数据](https://huggingface.co/datasets/wxli318/OmniVBench)。
- **相对上期：**首次收录。
- **核心贡献：**覆盖七类、18 项 R2V 任务，以 12,172 条 case-specific checklist 检查身份、动作、风格、结构和叙事是否正确解耦并绑定。已开放部分为 813 个案例、1,041 张参考图和 421 个参考视频，共约 3.96GB；论文另称训练集有 34 万样本。
- **Coding 接口：**JSON case ID、双语提示、参考角色映射，适合接入视频模型 CI。
- **场景：**多角色短片、品牌角色、互动叙事和数字人身份回归测试。
- **成熟度 / 证据：**benchmark 已开放但需同意条款，仅限非商业学术研究；训练集完整性与来源许可仍需核验。
- **重要性 / 阅读：**高 / 必读。

### 11. CompAdapt：自然语言编译为复合物理过程

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**GestureFAR 的真正增量不是画面清晰度，而是严格只看已到达语音的连续全身动作生成；这使数字人可以边听边动，而不必等待整句语音。
- **3D/4D 表示：**本日没有高质量 3D/4D 头像重建新增。GestureFAR 和 SignGPT 均输出 pose/motion，最终角色外观仍依赖 SMPL-X、mesh、Gaussian 或引擎 avatar。
- **实时交互：**9.3 ms/token 是动作 latent 的生成成本，不包含语音编码、骨骼解码、IK、渲染和 RTC，因此不能直接等同于端到端响应延迟。
- **音视频与情感表达：**GestureFAR增强手臂、手部和身体共语表现；SignGPT强调手、脸和身体共同承载语言。口型、视线、情绪、手势和可打断对话仍缺少统一公开评测。
- **工程部署：**已有清晰的服务接口形态，但两项新模型都没有可核验的代码和权重，暂不能进入产品验证。
- **安全与身份治理：**本周期暂无新的肖像授权、水印、溯源或深伪检测成果。OmniVBench能测试身份保持，但不解决身份是否获得授权。

## 5. 世界模型进展

- **架构与训练：**蒸馏和结构化中间状态成为两条主线。Astronex、ZYT-World把多步双向视频模型改造成因果生成器；MT-WAM、SkelWAM则把重点移到点轨迹、骨架和任务相关 feature。
- **可控/可玩生成：**Astronex 已提供逐帧相机命令、中途事件及连续动作向量，是本周期与 coding 连接最强的通用接口。ZYT-World 的布局控制更接近生产感知栈，但没有开放接口。
- **长时与物理一致性：**固定窗口和 sink frames 控制计算成本，地点记忆或 submap 负责回访一致性。它们改善视觉漂移，但不能证明碰撞、守恒和因果规律正确。
- **空间表示：**Adaptive World Memory 将 3D Gaussian、SLAM、回环和可学习记忆合并，代表生成式世界与传统几何系统重新融合。
- **机器人/仿真：**SkelWAM解决本体差异，ME-Dex补充触觉状态，MT-WAM减少部署推理；三者共同说明机器人世界模型正变成结构化策略组件。
- **实时部署与评测：**Astronex 的单卡实时和 ZYT 的七相机 4 FPS 是最强速度信号，但仅 Astronex具备公开复现入口；真实控制周期、p95 延迟和故障恢复仍未披露。

## 6. Coding × 新型互动作品

### 链路一：代码驱动的持续生成世界

**游戏/网页事件 → 相机轨迹与 64 维动作 → Astronex 因果生成器 → 流式画面 → 新观察继续驱动**

代码维护玩家位置、输入映射、剧情变量、权限和失败回退；模型生成连续视觉结果；传统引擎仍负责权威碰撞和胜负规则。代码、权重和事件示例已开放，可运行证据充分，但模型画面尚不能替代确定性状态服务器。

### 链路二：多路摄像头闭环驾驶仿真

**驾驶策略动作 → 自车轨迹/交通布局 → ZYT-World 七路画面 → 驾驶策略下一动作**

车辆软件维护标定、时间戳、控制和交通规则；模型模拟传感器外观与其他参与者响应；安全 verifier 比较跨视角几何和违规行为。已有项目 demo 和内部指标，缺少代码、开放数据及第三方闭环验证。

### 链路三：实时数字人的身体表演

**流式语音 → GestureFAR motion token → IK/骨骼重定向 → Unity/Unreal avatar → RTC**

模型负责连续、与语音节奏相关的身体动作；引擎负责骨骼约束、地面接触、碰撞、LOD 和渲染；应用代码负责话轮、中断、角色状态和降级。论文证明 motion token 足够快，但端到端引擎集成属于**本报告推断**。

### 链路四：手语原生数字员工

**用户视频 → pose 提取 → SignGPT 翻译 → LLM/业务工具 → SignGPT 手语动作 → avatar renderer**

代码负责账户、业务工具、审核和对话状态；SignGPT连接语言与动作；渲染器产生最终角色。已有 12 人探索性研究，但无实时 SDK，当前只能视为研究型无障碍交互原型。

### 链路五：跨设备机器人技能编排

**任务程序 → 统一 25 维骨架动作 → SkelWAM → 本体 decoder → 机器人控制器**

世界—动作模型输出与机器人型号无关的中心线、TCP 和夹爪状态；设备 adapter 再映射到关节或连续体控制。代码负责约束、标定、急停和日志。论文已有跨十种仿真本体和连续体机器人验证，离工业认证尚远。

### 链路六：世界模型与传统物理引擎协同

**模型提出候选动作 → ME-Dex/MT-WAM预测任务相关未来 → CRISP验证接触 → 控制器执行**

生成模型负责候选和非线性预测，CRISP负责不可违反的碰撞与摩擦约束，verifier负责选择和拒绝。这比让视频模型独占世界状态更适合精密装配；当前各组件已分别验证，端到端组合属于**本报告推断**。

## 9. 系统架构与技术趋势判断

1. **明显升温：可编程条件接口。** 相机轨迹、连续动作、骨架、触觉、布局和中途事件正在取代纯文本 prompt，成为世界模型的真实软件接口。
2. **实时路线趋同：**双向多步教师模型负责质量，块因果学生、少步蒸馏、KV cache 和轻量 VAE 负责运行时。
3. **部署时不必生成未来视频：**MT-WAM延续 MoWAM 的方向——视频预测可作为训练监督，但部署只消费压缩后的运动或视觉 feature。
4. **可复用系统架构：**`权威状态/传感器 → 结构化动作协议 → 生成或预测模型 → 物理/安全 verifier → 执行器 → 事件日志与记忆`。数字人、NPC、机器人和自动驾驶只是不同的输入输出 adapter。
5. **传统引擎不会消失：**CRISP、SLAM、IK、碰撞和控制器负责精确约束；生成模型负责难以手写的外观、动作先验和未来候选。
6. **关键未解问题：**长时因果漂移、多人/多对象身份绑定、端到端 p95 延迟、并发成本、真实物理校准、故障恢复、数据许可和肖像治理。
7. **需要降级看待：**ZYT-World 的“生产相机等价”、GestureFAR 的“实时”和 AWM-3DFM 的“将开放”目前分别是官方或论文层证据；没有代码、权重和独立复核前不能视为正式产品。
8. **研究包装风险：**只展示连续视频而不提供动作协议、状态读取、失败回退和闭环指标的项目，仍更接近视频 demo；本周期 Astronex 是少数真正把接口、代码和资源一起交付的例外。

## 10. 论文精读候选

1. **[Astronex-World 1.0](https://arxiv.org/abs/2609.20034)**  
   值得读：完整回答世界模型如何变成可脚本化运行时。重点看块因果转换、DMD/DMD2、PRoPE、动作接口和长时 cache。与一般可玩视频模型相比，它开放了后训练和事件控制。复现风险是 24GB 显存只是接近下限，完整实时性能仍需 L20 级硬件。

2. **[ZYT-World](https://arxiv.org/abs/2609.21712)**  
   值得读：多相机传感器等价、地点回访和闭环实时被放进同一系统。重点看 RigCritic、TinyVAE、隐式记忆和七视角同步。复现风险是数据、代码与内部相机系统均未开放。

3. **[GestureFAR](https://arxiv.org/html/2609.21576v1)**  
   值得读：把连续 flow 与严格 token-causal 生成结合。重点看 causal VAE、head-only distillation、stateful deployment 和 latency 表。与离散 gesture token 方法相比，它减少表示上限。风险是暂无代码，且未报告完整 avatar 链路延迟。

4. **[MT-WAM](https://arxiv.org/abs/2609.21474)**  
   值得读：展示世界模型训练目标如何围绕动作质量重构。重点看 motion/feature 双流、结构化 attention mask、cache 和真实机器人实验。风险是缺少代码、吞吐量及多 seed 统计。

5. **[ME-Dex 1.0](https://arxiv.org/html/2609.21449v1)**  
   值得读：触觉不再只是条件，而是需要预测的未来状态。重点看 Canonical Hand Model、H-Bridge、Agentic Tactile Data Engine 和 zero-tactile 消融。复现风险包括异构传感器标定、单 seed 以及代码未开放。

## 11. 下周跟踪与可行动建议

### 继续跟踪

1. Astronex 在 RTX 5090/24GB 上能否达到稳定实时，以及首帧、动作到画面、事件切换三类 p50/p95 延迟。
2. Astronex 的 64 维动作输出头何时提供已训练 checkpoint，而不是当前零初始化接口。
3. ZYT-World 是否开放代码、数据、具体 GPU 型号及七路图像从生成到驾驶策略输入的总延迟。
4. GestureFAR 项目页、代码、权重和 Unity/Unreal 骨骼示例是否上线。
5. AWM-3DFM 仓库何时可访问，以及动态物体是否会污染长期 world memory。
6. Omni-R2V 34 万训练样本的真实开放范围、版权来源和商业使用条件。
7. SkelWAM 的 LIBERO-Cross10、decoder API 与真实连续体机器人结果是否可独立复现。
8. ME-Dex 在多 seed、真实触觉噪声和传感器失效情况下是否仍保留收益。

### 本周可动手实验

1. **Astronex 事件化互动世界**
   - 目标：验证运行中事件是否能局部改变场景而不破坏先前状态。
   - 组件：Astronex consumer 配置、24GB 以上 GPU、简单键盘/WebSocket 事件层。
   - 难点：块边界、事件缓存失效、输入到显示延迟。
   - 成功判据：连续运行 60 秒；动作和事件可动态修改；显存不随时长增长；无明显场景重置。

2. **多参考角色回归测试**
   - 目标：检查现有视频模型是否把人物身份、动作和风格绑定到正确对象。
   - 组件：OmniVBench 的 multi-content/cross-aspect 子集、当前 R2V 模型、自动结果归档脚本。
   - 难点：评测 checklist 尚未全部开放、生成成本高。
   - 成功判据：形成按 case ID 可复跑的失败分类，至少区分身份串位、动作串位、风格泄漏和叙事不服从。

3. **世界模型候选 + CRISP 接触门禁**
   - 目标：验证“模型提出、物理引擎拒绝、控制器执行”的混合架构。
   - 组件：CRISP 插销示例、简单候选轨迹生成器、碰撞/接触规则。
   - 难点：坐标系、接触容差、预编译核心包的可扩展范围。
   - 成功判据：非法轨迹在执行前被稳定拒绝，合法轨迹成功率高于无门禁基线，且记录可复现的拒绝原因。

4. **流式数字人动作预算模拟**
   - 目标：判断 9.3 ms/token 的 GestureFAR 指标是否足以支撑实际 RTC 数字人。
   - 组件：7.5Hz 虚拟 motion-token producer、SMPL-X/引擎骨骼、TTS/RTC 延迟注入器。
   - 难点：抖动、缓冲、IK 和渲染延迟会累加。
   - 成功判据：在模拟网络抖动下动作连续、无回改已发姿态，端到端 p95 保持在团队设定的交互阈值内。
