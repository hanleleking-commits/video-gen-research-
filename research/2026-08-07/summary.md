# 数字人、世界模型与互动作品研究日报：2026-08-07

检索窗口：2026-08-01 至 2026-08-07。  
检索截止：2026-08-07 09:00（UTC+8）。8 月 6 日晚至 7 日晨可检索的一手新增主要来自 8 月 5 日提交、随后进入 arXiv 新批次的工作。经与 8 月 3—6 日日报去重，本日只有 7 个条目达到收录门槛，未用旧闻补足数量。

## 1. 本日摘要

本日最重要的变化，是数字人与世界模型第一次在同一批新增中明确汇合到“可被事件触发的社会角色”：HelloWorld 让视频世界中的人物响应按键、转身、注视和问候，虽然动作集合和代码仍有限，却把可玩世界从相机控制推进到角色交互。数字人侧，EmpaAva 的研究贡献并非新的单体生成模型，而是把语音识别、情绪感知、LLM、情感 TTS、FLAME 动作和 3D Gaussian 渲染编排成具有 JSON 状态、独立 worker、健康检查和运行清单的完整系统，是本周期 Coding 连接最强的新增。世界模型侧，DreamWAM、CoCo 和 PhysMind 分别回答三个不同问题：训练时应该预测哪些结构化未来、如何证明动作真的改变未来、以及如何把视频转换为可编辑和可执行的物理世界。DreamWAM 已开放训练、评测代码与权重，并在真实机器人视觉扰动下提供作者实测；CoCo 提出反向动作、零动作和镜像场景的反事实约束，但尚无公共实现；PhysMind 用 mesh、6D pose 和连续时间动力学建立可查询世界，代码仍为占位仓库。Coding 的角色因此进一步清晰：维护权威状态、事件、计划、约束、取消和观测；生成模型负责外观、动作候选和难以手写的未来表征；传统几何、动力学或渲染系统负责可验证执行。本日仍没有 Unity、Unreal、Godot 或 WebGPU 的新增官方插件，也没有新增客户试点或规模化部署。所有核心结果仍来自作者论文、项目页或仓库，尚无第三方复现，应避免把“开放代码”直接解释为生产成熟。

## 3. 最值得关注的 7 个进展

### 1. EmpaAva：把数字人拆成可观测、可替换的 agent 与 worker 系统

- **类型 / 日期 / 主线：** 论文、GitHub、demo、运行时；2026-08-05；数字人、Coding × 互动作品。
- **官方链接：** [论文](https://arxiv.org/abs/2608.04709)、[项目页](https://empaava.top/)、[GitHub](https://github.com/1114531938/EmpaAva_System)。
- **相对上期的新变化：** 全新条目；相较上期单独的情绪头像或动作生成，首次提供完整 perception—planning—rendering 系统。
- **核心贡献与技术：** PerceptionAgent 将语音、声学情绪、可选视觉和历史转成结构化用户状态；ResponseAgent 输出包含文本、情绪、声音、角色、表情和背景的计划；RenderAgent 串联 EmotiVoice、DEEPTalk、FLAME 和 GaussianAvatar。
- **Coding 接口：** agent 通过可读 JSON 交换状态；FastAPI/本地 worker 使用独立端口并提供健康检查；CLI 输出 `manifest.json`，记录模型版本、阶段耗时、异常、fallback 和随机种子。
- **互动/工业场景：** 情感陪伴研究、教育讲师、数字员工前端、远程服务角色。医疗或心理治疗用途被官方负责使用政策明确排除。
- **成熟度 / 证据：** 已开源研究系统＋在线 demo；完整推理建议 A100/H200，也支持降低分辨率或并发的 RTX 4090，约需 140GB 存储。作者代码为 Apache-2.0，但 GaussianAvatar、ImageBind 等依赖含非商业限制，完整系统不能直接商用。
- **重要性 / 阅读优先级：** 高 / 必读。

### 2. HelloWorld：视频世界中的角色开始响应运行时事件

- **类型 / 日期 / 主线：** 论文、benchmark、demo；2026-08-05；世界模型、数字人、Coding × 互动作品。
- **官方链接：** [论文](https://arxiv.org/abs/2608.05070)、[官方仓库](https://github.com/AlayaLab/HelloWorld)。
- **相对上期的新变化：** 全新条目；上期可玩世界主要控制相机、轨迹和环境，本期首次把“面对用户的社会动作”作为世界模型控制维度。
- **核心贡献与技术：** 用户按下 `F` 后，角色可转向镜头、挥手、点头或短句问候。训练以自蒸馏生成同时含相机运动与社会互动的数据；推理时用跨注意力时间 mask 将互动 prompt 限制到按键窗口。
- **Coding 接口：** 当前明确接口是键盘事件、相机轨迹、交互文本和时间窗口；可进一步映射到游戏事件总线或剧情状态机。
- **互动/工业场景：** 可回应观众的互动电影、生成式 NPC、虚拟导览、品牌角色体验。
- **成熟度 / 证据：** 作者 demo；HelloWorldBench 含 400 个样本及动作、时机、注视等指标，但仓库明确标注代码和 benchmark “Coming soon”。
- **重要性 / 阅读优先级：** 高 / 必读。

### 3. DreamWAM：用结构化未来训练机器人，但部署时保持 RGB-only

- **类型 / 日期 / 主线：** 论文、GitHub、权重、实机实验；2026-08-05；世界模型、机器人。
- **官方链接：** [论文](https://arxiv.org/abs/2608.04996)、[GitHub](https://github.com/hustvl/DreamWAM)、[项目页](https://hustvl.github.io/DreamWAM/)、[权重](https://huggingface.co/hustvl/DreamWAM)。
- **相对上期的新变化：** 全新条目；与上期 SUV 的多流未来相近，但 DreamWAM 更强调“结构化监督只服务训练，部署不要求额外传感输出”。
- **核心贡献与技术：** VideoDiT 联合去噪 RGB 和 optical flow，并以 Depth Anything 3 深度、DINO 语义特征提供 gated residual；ActionDiT 经共享注意力读取未来状态。推理时关闭辅助分支。
- **Coding 接口：** MIT 仓库提供数据预计算、八卡训练入口、LIBERO/LIBERO-Plus 评测脚本和 checkpoint；基础模型为 Wan2.2-TI2V-5B。
- **互动/工业场景：** 机器人策略训练、视觉扰动鲁棒性评测、仓储或桌面操作的策略预验证。
- **成熟度 / 证据：** 已开源、作者仿真及实机研究。作者报告 LIBERO-Plus 从匹配基线的 69.16% 提升至 75.47%；真实机器人视觉扰动平均成功率由 55.6% 提升至 74.4%，每设置 30 次试验。尚无独立复现或工业现场证据。
- **重要性 / 阅读优先级：** 高 / 必读。

### 4. PhysMind：从视频重建一次、可反复查询和修改的可执行世界

- **类型 / 日期 / 主线：** 论文、项目 demo；2026-08-05；世界模型、Coding × 物理推理。
- **官方链接：** [论文](https://arxiv.org/abs/2608.04575)、[项目页](https://physmind.github.io/)、[GitHub](https://github.com/ccyydd/PhysMind)。
- **相对上期的新变化：** 全新条目；不同于生成未来帧，它把视频编译为显式对象、几何、轨迹和动力学。
- **核心贡献与技术：** 先进行对象分割、mesh 重建和 6D pose tracking，再拟合连续时间解析动力学和隐式物理参数。问题到来后可检查、延续或修改世界，而不必重新理解原视频。
- **Coding 接口：** 理想接口是 `video → executable scene → inspect/edit/rollout → event trace`；代码可对“移除物体、改变质量、继续运动”等操作进行确定性编排。
- **互动/工业场景：** 物理教学沙盒、视频事故分析、仿真初始化、设计评审和机器人反事实预检。
- **成熟度 / 证据：** 作者 benchmark 与 demo；项目页报告 CLEVRER 相比同 VLM 直接 CoT 提升 38.23 个百分点，但 92.31% 的错误来自世界构建阶段。GitHub 当前只有 README，代码与模型待发布。
- **重要性 / 阅读优先级：** 高 / 必读。

### 5. CoCo：用反事实测试防止世界模型“无视动作”

- **类型 / 日期 / 主线：** 论文、benchmark；2026-08-05；世界模型、评测。
- **官方链接：** [论文](https://arxiv.org/abs/2608.04653)。
- **相对上期的新变化：** 全新条目；为上期 WorldExam 等评测补充更直接的动作因果性测试。
- **核心贡献与技术：** 对同一状态分别施加原动作、反向动作和零动作，并加入场景镜像及动作变换一致性，迫使预测依赖动作而不是视觉惯性。同步提出 Action Response Consistency、Drift Energy 和 Mini-SSMB。
- **Coding 接口：** 可进入世界模型 CI：固定初始状态，批量生成动作对和零动作，比较对象位移方向、响应差异及静止漂移。
- **互动/工业场景：** 可玩视频回归测试、机器人动作模型验收、游戏控制响应检查。
- **成熟度 / 证据：** 论文作者评测，无确认代码。作者报告 VP2 平均规划成功率 73.1%，Mini-SSMB 的 Drift Energy 相比基线下降 17.07%。
- **重要性 / 阅读优先级：** 高 / 必读。

### 6. 分层音乐世界模型：面向共同创作 agent 的低延迟建议器

- **类型 / 日期 / 主线：** 论文、在线 demo；2026-08-05；Coding × 互动作品。
- **官方链接：** [论文](https://arxiv.org/abs/2608.04378)、[在线 demo](https://drscotthawley-midi-rae-jepa-son.hf.space/)。
- **相对上期的新变化：** 全新条目；扩展“世界模型＋agent”到符号音乐互动创作。
- **核心贡献与技术：** 2.55M 参数 Swin V2 编码器以 JEPA 类目标学习 MIDI piano-roll 的短时细节与长时乐句结构，再以条件 flow matching 生成或局部补全。
- **Coding 接口：** LLM 负责创作意图、区域选择和轮次管理；用户通过图形 mask 指定改写区域；模型返回音乐建议。
- **互动/工业场景：** 人机共创乐器、游戏配乐草图、音乐教育和互动演出。
- **成熟度 / 证据：** 可运行在线 demo；作者报告 CPU 2.8 秒、Apple MPS 0.6 秒生成一次建议。没有产品 SLA 或多人协作证据。
- **重要性 / 阅读优先级：** 中 / 可读。

### 7. 隐私感知课堂动作识别：生成数据与轻量运动推理结合

- **类型 / 日期 / 主线：** 论文、拟发布 benchmark；2026-08-05；支撑基础设施、工业应用。
- **官方链接：** [论文](https://arxiv.org/abs/2608.05115)。
- **相对上期的新变化：** 全新条目。
- **核心贡献与技术：** 将生成式 CCTV 视频与真实 pose 数据组合，按方向、速度、加速度和强度建立分层运动表示，再把多阶 teacher 蒸馏为轻量单阶 student。
- **Coding 接口：** 可部署为只处理姿态和运动学特征的事件检测服务，减少原始人脸视频在下游流转。
- **互动/工业场景：** 教育安全提醒、训练场异常动作检测；不是数字人生成能力本身。
- **成熟度 / 证据：** 论文原型，作者称计算量低于大型基线的十分之一；代码和 benchmark 仅承诺后续公开。
- **重要性 / 阅读优先级：** 低 / 仅跟踪。

## 4. 数字人 / 虚拟形象能力进展

**生成与驱动。** EmpaAva 没有发明新的 talking-head 基座，而是证明现有开放组件可以通过结构化计划组成完整表演链。语音和情绪进入 Response Plan，随后被编译为 TTS、逐帧 FLAME 参数和 Gaussian 渲染任务。

**3D/4D 表示。** 本日高质量新增只有 EmpaAva 对已有 3D Gaussian avatar 的系统化使用，没有新的单图/少样本 3D 或 4D 重建突破。其 FLAME-to-Gaussian 转换是可编排接口，但人物资产仍有授权和非商业许可证限制。

**实时交互。** EmpaAva 的“live”是按轮次生成和播放，不等同于连续 30 FPS 生成、低首帧或可随时打断。HelloWorld 的按键响应更接近事件驱动实时交互，但代码、生成时延和连续多次触发稳定性尚未公开。

**音视频与情感表达。** EmpaAva 将声学情绪、回复策略、情感 TTS 和表情参数绑定到同一计划，工程意义高于单独优化口型指标。仍需验证用户插话、active listening、注视反馈和多语言时的端到端表现。

**工程部署。** 可进入产品验证的是 JSON stage contract、worker 隔离、健康检查、阶段耗时、fallback 和运行 manifest。尚不能直接进入商业产品的是其默认头像渲染资产及部分第三方模型许可证。

**安全与身份治理。** 本日没有新的水印或深伪检测突破。EmpaAva 至少把人物、声音、模型版本和输出记录放进 manifest，并明确禁止未经授权的身份/声音克隆，但这是流程治理，不是技术防伪保证。

## 5. 世界模型进展

**架构与训练。** DreamWAM 表明结构化未来可以只在训练时出现：flow、depth 和 DINO 特征塑造表示，部署仍接收 RGB。相较部署时持续生成多种输出，这种设计更节约在线算力。

**可控/可玩生成。** HelloWorld 把角色响应变成时间化事件；CoCo 则追问不同动作是否真的造成不同未来。前者增强体验，后者增强可验证性，二者缺一不可。

**长时与物理一致性。** 本日没有新的长时视频记忆突破。PhysMind 选择避开长视频像素 rollout，将对象状态和连续动力学持久化；优势是可编辑，风险是重建错误会成为整个世界的系统性错误。

**空间表示。** mesh、6D pose、depth、optical flow、DINO 语义和 FLAME 参数继续取代纯 RGB，成为代码可以读取或校验的中间状态。

**机器人/仿真。** DreamWAM 已提供最强的可运行新增；PhysMind 可作为离线反事实层；CoCo 可作为动作模型验收层。三者仍不能取代低层控制、安全约束和实机急停系统。

**实时部署与评测。** DreamWAM 公开训练/评测入口但未披露在线动作延迟；PhysMind 披露单问题成本而非世界构建耗时；HelloWorld 未披露交互延迟。实时性证据总体不足。

## 6. Coding × 新型互动作品

1. **用户语音/摄像头 → EmpaAva JSON 感知状态 → LLM 回复计划 → TTS/FLAME/3DGS worker → 情感数字人。**  
   代码负责权限、会话、stage contract、超时、fallback 和审计；模型负责情绪判断、语言及动作生成；传统渲染负责相机和合成。已有开源系统证据，但商业许可证未打通。

2. **键盘/手柄事件 → HelloWorld 时间窗口和交互 prompt → DiT 角色响应 → 互动电影或生成式 NPC。**  
   代码负责事件总线、剧情条件、冷却时间和状态；模型负责角色面向、注视与社会动作；传统游戏系统负责碰撞、任务和多人同步。当前仅作者 demo。

3. **摄像头 RGB → DreamWAM 结构化未来训练表示 → ActionDiT → 机器人动作。**  
   训练代码利用光流、深度和语义监督；部署侧保持 RGB-only；机器人控制器继续施加速度、空间和安全约束。已有代码、权重和作者实机结果。

4. **视频 → PhysMind 对象/mesh/6D pose → 可执行动力学 → 用户修改条件 → 反事实教学沙盒。**  
   coding agent 可把自然语言问题编译为删除对象、改变参数或延续轨迹；解析系统负责执行；前端将事件结果可视化。本报告推断应用，核心代码未发布。

5. **同一状态＋动作集合 → CoCo 反事实 rollout → ARC/DE 自动验收 → 世界模型发布门。**  
   这是面向生成式游戏和机器人世界模型的测试工程链路：模型升级后，CI 自动发现“按左和按右画面几乎相同”或“零动作仍漂移”。论文有指标，工具尚未开放。

6. **MIDI 编辑区域 → 分层音乐表示 → flow 建议器 → 人类选择/继续编辑 → 共创作品。**  
   代码保留乐曲历史、mask、版本和接受/拒绝反馈；模型负责提出变化而非接管完整创作。已有在线交互 demo。

## 8. 可复现资源与开发者入口

- [EmpaAva](https://github.com/1114531938/EmpaAva_System)：作者代码 Apache-2.0，第三方组件许可证混合。最低成本先运行 mock UI/API 和一秒样例，检查 JSON 计划、worker 健康状态和 manifest；完整推理再使用 24GB 以上 NVIDIA GPU。**最值得做系统级复现，但不可默认商用。**
- [DreamWAM](https://github.com/hustvl/DreamWAM)：代码及权重标注 MIT，推荐 Python 3.10、CUDA 12.x；依赖 Wan2.2、RAFT、DINOv2、Depth Anything 3、LIBERO。最小路径是下载 checkpoint，先跑单个 LIBERO suite，再对 RGB-only 基线做视觉扰动对比。**最值得做模型复现。**
- [HelloWorld](https://github.com/AlayaLab/HelloWorld)：目前只有论文、README 和 demo，代码、benchmark 均为“Coming soon”。**仅准备事件协议，等待开源。**
- [PhysMind](https://github.com/ccyydd/PhysMind)：仓库只有占位 README。**暂不可复现。**
- [音乐共创 demo](https://drscotthawley-midi-rae-jepa-son.hf.space/)：可直接验证 mask inpainting 和交互延迟，代码许可证与训练资源尚需进一步核查。**适合轻量体验验证。**
- CoCo 与课堂动作识别尚未发现公共代码入口。后者明确使用“will release”，不能计为已开源。

## 9. 系统架构与技术趋势判断

明显升温的是“生成模型外部的可执行协议”：EmpaAva 的 JSON reply plan、HelloWorld 的事件时间窗、PhysMind 的对象—mesh—动力学、CoCo 的反事实动作组和 DreamWAM 的结构化训练目标，都让代码不再只能操作 prompt 和像素。

正在形成的可复用架构是：

`用户/传感器事件 → agent 生成结构化计划 → 权威状态与规则检查 → 专用生成 worker → 传统渲染或执行系统 → 指标/安全门 → manifest 与回放`

数字人的实用路线正在从单一端到端视频模型，转向 ASR、情绪、LLM、TTS、动作和渲染的可替换组合。世界模型则分化为三路：生成可观看未来、学习供动作头读取的 latent、构建可编辑的显式世界。工业系统大概率同时使用后两种，而不会把像素生成器直接当作权威状态。

仍未解决的核心问题包括：首帧和中断延迟、连续多轮角色状态、世界重建的置信度、动作反事实正确性、多用户并发、跨 GPU 性能、可观测性标准以及人物/声音/资产许可证。

应降级看待“仓库已建立但代码 Coming soon”“只报告平均 FPS 或 benchmark”“开源主仓库但关键资产受非商业许可证约束”的项目。EmpaAva 的价值是真实的系统工程增量，但其核心生成组件多为已有工作，不宜描述成新的基础模型突破。

## 10. 论文精读候选

1. [EmpaAva](https://arxiv.org/abs/2608.04709)：重点读 Tri-Agent、Response Planning、自动/人工评测和端到端时序。与普通 talking-head 的差异是可检查的多模态编排；风险是系统复杂、依赖许可证混合。
2. [HelloWorld](https://arxiv.org/abs/2608.05070)：重点读自蒸馏数据流程、temporal cross-attention mask 和 HelloWorldBench。差异是把角色社会响应加入视频世界控制；风险是动作空间小且代码缺失。
3. [DreamWAM](https://arxiv.org/abs/2608.04996)：重点读 RGB/flow 联合去噪、depth/DINO gated residual、共享注意力和 LIBERO-Plus 协议。差异是训练结构丰富、部署输入简化；风险是八卡训练成本和实机规模有限。
4. [PhysMind](https://arxiv.org/abs/2608.04575)：重点读动态场景重建、解析连续动力学、反事实执行和错误分析。差异是一次建世界、多次执行；风险是世界构建占绝大多数错误且无代码。
5. [CoCo](https://arxiv.org/abs/2608.04653)：重点读 counterfactual consistency、ARC、Drift Energy 和 Mini-SSMB 构造。差异是直接测量动作因果响应；风险是指标与开放世界复杂交互的相关性尚未验证。

## 11. 下周跟踪与可行动建议

继续跟踪：

1. HelloWorld 何时开放模型、代码和 HelloWorldBench，按键到首个响应帧的延迟是多少。
2. HelloWorld 连续触发、取消触发以及多人角色场景是否会出现状态错乱。
3. EmpaAva 完整模式的端到端时延、首包时间、并发和每轮 GPU 成本。
4. EmpaAva 是否提供商用兼容的 mesh/3DGS renderer 和已授权人物资产替代方案。
5. DreamWAM 是否能在单卡或少卡推理，以及动作 latency 是否适合真实控制频率。
6. DreamWAM 的真实机器人结果能否由第三方在未知背景、遮挡和相机位移下复现。
7. PhysMind 是否开放代码，以及能否输出世界构建置信度和可视化错误定位。
8. CoCo 的 ARC/DE 是否能迁移到第一人称游戏、驾驶和长时交互模型。

本周可动手验证：

1. **EmpaAva 编排层烟雾测试。**  
   目标：验证其 JSON stage contract 是否适合作为自有数字人底座。组件：官方 mock 模式、样例音视频、worker 健康检查。难点是区分 mock 通过与完整模型可运行。成功判据：每轮均生成完整 manifest，能替换一个 worker，并正确记录超时和 fallback。

2. **数字人许可证清单实验。**  
   目标：建立从 avatar、voice、motion 到 renderer 的机器可读授权门。组件：EmpaAva `models/manifest.json`、第三方许可证、简单 CI 脚本。难点是资产身份权与代码许可证不同。成功判据：任何含非商业或未知条款的构建自动阻止进入商业发布环境。

3. **DreamWAM 最小鲁棒性复现。**  
   目标：验证结构化未来监督是否确实改善视觉扰动。组件：官方 checkpoint、LIBERO-Plus 小子集、Fast-WAM 基线。难点是依赖体积和环境版本。成功判据：在光照、背景、相机三类扰动中至少两类稳定优于匹配基线，并记录动作延迟和显存。

4. **反事实世界模型 CI 原型。**  
   目标：实现 CoCo 思路的工程化最小版本。组件：任一动作条件视频模型、同状态的正向/反向/零动作输入、光流或对象跟踪器。难点是自动区分合理惯性与错误漂移。成功判据：自动发现零动作持续运动、相反动作同向响应和镜像动作不一致三类失败。
