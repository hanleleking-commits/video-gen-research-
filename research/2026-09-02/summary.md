# 数字人、世界模型与互动作品研究日报：2026-09-02

检索窗口：2026-08-27 至 2026-09-02。  
去重基线：已检查最近数期日报，特别是 2026-09-01 日报；Magpie、ABot-Recon、WM-R1、Bitmagic GDK、Phaser 源码导出、Procedura、4DAnyone 等若无实质更新，本期不重复收录。

## 1. 本日摘要

本周期最强新增来自世界模型的“记忆—状态—执行”三层分化：Matrix-Game 3.5 用显式三维 Patch Memory 保持场景几何，用独立参考 token 保持动态主体身份，再通过因果蒸馏实现流式生成，说明单一像素缓存正被结构化记忆取代。LayerRecall则进一步表明，长时记忆不仅要决定“检索什么”，还要决定“注入视频 DiT 的哪一层”。

Coding × 世界模型出现两条值得重视的路线。Code-as-World 让 agent 从视频反推、执行并验证物理代码，把像素观察转换成可查询的状态、参数和动力学；WebWorld则直接把浏览器定义为不可被视觉模型“糊弄”的可执行世界模型，通过交互契约和验收证书筛选训练数据。Lucida和CE3D++把这一思想推进到三维生产流程：前者让VLM在3D编辑器中闭环放置可编辑资产，后者让LLM在多轮对话中调度最多30种视觉工具完成3D/4D编辑。

数字人专门方向本周期仍无足够强的新模型发布。DreamX-Creator的原生音视频联合生成、LayerRecall的身份召回机制，可能成为数字人基础组件，但前者尚未开放权重和推理代码，后者也不是数字人专用系统。BLARM提供了无显式骨骼的视频驱动网格动画路线，更直接受益的是游戏道具和非人角色，而非完整人体数字人。

产业证据仍以论文、开源研究组件和交互demo为主；本周期未发现新的客户规模化部署。趋势已经非常清晰：模型负责视觉、声音和候选状态，代码负责规则、资产结构和调用编排，浏览器、仿真器或传统引擎负责执行与验收。

## 3. 最值得关注的 9 个进展

### 1. Matrix-Game 3.5：用三维 Patch Memory 支撑分钟级交互世界

- **类型**：论文 / 模型 / GitHub / 权重 / demo
- **官方链接**：[论文](https://arxiv.org/abs/2608.29910)、[代码与权重入口](https://github.com/Riemann-Dynamics/Matrix-Game-3.5)
- **发布或更新时间**：论文 2026-08-30；代码和基础、蒸馏模型在本窗口开放。
- **所属主线**：世界模型 / Coding × 互动作品
- **相对上期的新变化**：首次收录；补足上期Magpie偏外部引擎状态、模型内部记忆不足的问题。
- **核心贡献**：将历史观察提升为可见性约束的三维patch记忆；Warped PRoPE引入相机投影；静态场景和动态主体分别通过几何记忆与多视角参考token维持；两阶段蒸馏把双向扩散模型转为少步因果生成器。
- **Coding接口**：Python推理脚本、相机轨迹配置、第一/第三人称checkpoint、基础模型与三步蒸馏模型。
- **互动及工业场景**：生成式漫游、可玩视频、互动电影预演、XR环境。
- **成熟度**：已开源研究系统；单卡至少40GB显存，704×1280峰值约40GB，仍非消费端运行时。
- **证据 / 重要性 / 阅读优先级**：论文实测＋官方代码 / 高 / 必读。

### 2. Code-as-World：让agent发现并验证可执行物理世界

- **类型**：论文 / GitHub / 模型权重 / demo
- **官方链接**：[论文](https://arxiv.org/abs/2608.27549)、[代码](https://github.com/MirroS-Lab/Code-as-World)
- **发布日期**：2026-08-27；4B/9B权重与在线demo在窗口内开放。
- **所属主线**：世界模型 / Coding
- **相对上期的新变化**：与上期Code World Model互补：后者用代码驱动生成画面，本项目从真实视频反推可执行物理代码。
- **核心贡献**：agent循环执行“提出假设—运行模拟—渲染—验证—修正”，把对象状态、物理参数和动力学写成可执行表示，并用于训练定量物理推理VLM。
- **Coding接口**：Python、MuJoCo示例、QuantiPhy评测、4B/9B本地推理及vLLM的OpenAI兼容服务。
- **互动及工业场景**：从视频生成物理沙盒、机器人仿真初始化、物理教学、游戏机制逆向与验证。
- **成熟度**：已开源、开放权重和demo；当前公开示例仍以弹道足球和定量问答为主。
- **证据 / 重要性 / 阅读优先级**：论文实测＋官方代码 / 高 / 必读。

### 3. Lucida：从杂乱实拍视频生成可编辑、可仿真的场景副本

- **类型**：论文 / 项目demo / Real-to-Sim系统
- **官方链接**：[论文](https://arxiv.org/abs/2608.30821)、[项目页](https://lucida-r2s.github.io/)
- **发布日期**：2026-08-31
- **所属主线**：世界模型 / Coding × 仿真
- **相对上期的新变化**：从ABot-Recon的连续几何重建推进到对象级、可编辑场景资产。
- **核心贡献**：把视频解析为携带多视角证据的场景图，为每个实例生成完整资产，再由GizmoAct VLM在3D编辑器中逐步操作局部坐标轴并自主判断对齐是否完成。作者报告R2S-Scene场景F-Score由SAM3D的0.794提升到0.924。
- **Coding接口**：场景图、对象资产、可执行gizmo操作及最多12步闭环放置。
- **互动及工业场景**：机器人数字孪生、可编辑虚拟场景、关卡重建、仿真数据生产。
- **成熟度**：研究原型和网页3D demo；未发现完整代码发布。
- **证据 / 重要性 / 阅读优先级**：论文实测 / 高 / 必读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动**：本周期暂无新的高质量speech-driven avatar、lip-sync或全身数字人专用模型。DreamX-Creator能够联合生成声音和视频，但没有证明身份锁定、口型准确度、会话打断或持续数字人控制。
- **3D/4D表示**：BLARM展示了从视频获得紧凑运动分解的可能性；CE3D++可编辑单目4D场景，但二者都未完整解决人体关节、手部、服装和毛发。
- **实时交互**：没有新系统公开完整的采集—模型—编码—传输端到端数字人时延。Matrix-Game 3.5的实时性属于世界生成，不能直接外推到对话头像。
- **音视频与情感表达**：DreamX的原生跨模态注意力有助于声音事件和视觉动作同步；其数字人情绪和语义表达仍缺少专用评测。
- **工程部署**：本周期最现实的产品路线仍是传统实时数字人渲染器叠加生成式离线素材，而非让大视频模型逐帧承担直播。
- **安全与身份治理**：没有新的肖像授权、声音同意、水印或撤回机制成果。DreamX仓库为Apache-2.0并不自动解决训练数据及人物身份权利。

## 5. 世界模型进展

- **架构与训练**：Matrix-Game 3.5把几何、主体和生成速度分层；LayerRecall把长期KV检索变成按层路由。
- **可控/可玩生成**：Matrix-Game支持第一/第三人称相机轨迹和主体参考图；但动作规则、碰撞和任务逻辑仍应由代码或传统引擎维护。
- **长时与物理一致性**：显式3D patch适合解决回访几何，Code-as-World的可执行状态适合解决数值和因果机制，两者处理的是不同层次的一致性。
- **空间表示**：Lucida输出独立、可编辑的对象mesh及场景图，比不可拆分的神经场更适合机器人和内容管线。
- **机器人/游戏/仿真**：Code-as-World把视频转成MuJoCo式假设；Lucida解决真实场景资产化；二者可分别承担动力学发现和仿真场景初始化。
- **实时部署与评测**：Matrix-Game虽开放蒸馏模型，但40GB显存仍限制广泛部署。GUI-CC证明评测必须覆盖自回灌、多步状态和动作可执行性。

## 6. Coding × 新型互动作品

### 链路一：代码状态＋三维记忆＋神经画面

**游戏服务器/传统引擎维护规则 → Matrix-Game接收相机、主体参考和历史patch → 生成720p流式画面 → 可重访的生成式漫游与互动电影。**

代码负责碰撞、库存、任务和会话；模型负责外观及视角展开；传统引擎是最终状态真源。模型和权重已开放，但混合引擎集成属于本报告推断。

### 链路二：真实视频→可执行物理代码→互动沙盒

**视频观察 → Code-as-World agent提出对象与动力学代码 → MuJoCo执行和渲染验证 → 用户改变参数或施加动作 → 物理教学、游戏机制原型和机器人仿真。**

代码同时承担世界表示和验证标准，VLM负责从证据提出假设。已有弹道足球示例和开放权重；自动恢复复杂接触、流体和软体规则尚未证明。

### 链路三：实拍空间→可编辑资产→可运行数字孪生

**多视角视频 → Lucida场景图与对象资产 → GizmoAct操作3D编辑器 → 物理属性和交互脚本 → 机器人训练、虚拟制片和数字展陈。**

生成模型补全被遮挡资产；VLM完成放置；传统模拟器负责碰撞、质量、关节和传感器。已有网页演示和论文结果，完整自动化代码尚未开放。

### 链路四：自然语言→工具编排→3D/4D多轮修改

**用户对话 → CE3D++ LLM选择分割、深度、修复、姿态等工具 → Hash-Atlas回写场景 → 持续可编辑的虚拟制作镜头。**

LLM负责规划，视觉模型负责局部生成，Hash-Atlas保持跨视角映射。已有代码，但100GB级完整显存需求使其更接近工作站研究工具。

### 链路五：需求→浏览器执行→验收证书→持续自改进作品

**创作者提出网页体验 → coding agent生成HTML/JS → WebWorld编译交互契约 → 浏览器执行点击、输入和状态检查 → 通过后进入训练或发布候选。**

生成模型不再兼任最终裁判；浏览器和测试脚本成为确定性世界。适用于网页游戏、品牌互动和生成式UI；当前证据主要来自论文实验。

### 链路六：数字角色素材→长时记忆→跨镜头身份恢复

**角色参考和剧情脚本 → 视频生成器 → LayerRecall检索身份/服装历史KV → 镜头切换后恢复外观 → 长剧情数字人或互动叙事。**

模型负责视觉连续性，代码负责角色ID、镜头、剧情状态和记忆索引。LayerRecall已有代码与demo，但用于可打断实时数字人仍属本报告推断。

## 9. 系统架构与技术趋势判断

明显升温的方向是：

1. **显式记忆与神经生成协同。** 三维patch、KV路由、主体参考token分别保存几何、历史与身份。
2. **代码成为世界表示。** Code-as-World和WebWorld均把可执行程序视为比像素更可靠的因果层。
3. **生成系统必须有外部验收者。** 浏览器、MuJoCo、3D编辑器和Android模拟器正在成为模型不可绕过的验证环境。
4. **场景输出从不可编辑神经场转向对象级资产。** Lucida的独立mesh更容易进入机器人、游戏和虚拟制作管线。
5. **agent角色从一次性生成器转为运行时控制器。** LoopArena报告最佳完整任务严格成功率仅24.69%，说明长时间编排和停止判断仍远未成熟。

正在形成的可复用架构为：

`用户/agent意图 → 结构化任务与状态 → coding agent或工具规划 → 可执行代码/引擎/编辑器 → 神经视觉与音频生成 → 浏览器/仿真器/测试契约验收 → 状态与记忆持久化 → 下一轮交互`

关键未解问题包括：跨分钟真实端到端延迟、多人会话隔离、可回滚状态、模型与物理引擎的双向同步、生成资产的许可证继承、数字人肖像授权和可撤回性。

需要降级看待的项目主要是DreamX-Creator：报告中的7B、2K和原生音视频能力有研究价值，但仓库当前只有路线图，不能按已开源模型或可部署系统表述。BLARM和Lucida同样不应因项目演示而被描述为工业产品。

## 10. 论文精读候选

1. **[Matrix-Game 3.5](https://arxiv.org/abs/2608.29910)**  
   重点读Patch Memory、Warped PRoPE、静态—动态解耦和蒸馏章节。它与纯KV记忆的核心差异是显式引入投影几何。复现风险是40GB显存和多项第三方组件。

2. **[Code as Worlds](https://arxiv.org/abs/2608.27549)**  
   重点读agentic discovery loop、模拟验证和物理监督构造。与Code World Model不同，它从观察反推出可执行机制。风险是当前示例世界较简单。

3. **[Lucida](https://arxiv.org/abs/2608.30821)**  
   重点读场景图解析、资产生成接口、GizmoAct闭环策略和失败分析。价值在于把Real-to-Sim输出变成可编辑资产。风险是完整代码未开放。

4. **[WebWorld](https://arxiv.org/abs/2608.30530)**  
   重点读interaction contract、acceptance certificate和质量棘轮。它把浏览器测试从后处理工具提升为训练数据准入机制。风险是论文结果仍需公开环境复验。

5. **[LayerRecall](https://arxiv.org/abs/2608.28460)**  
   重点读层级上下文偏好分析、路由器和CHPM。其增量不是更大缓存，而是更精细的记忆注入位置。风险是人物身份改善能否迁移到实时世界模型仍待验证。

## 11. 下周跟踪与可行动建议

继续跟踪：

1. DreamX-Creator何时开放真实权重、推理代码和许可证细节。
2. Matrix-Game 3.5在4090、A6000等非H100级硬件上的真实FPS和输入延迟。
3. Patch Memory在动态物体移动、遮挡后回访时是否会读取过期几何。
4. Code-as-World能否从复杂接触、关节、软体或流体视频恢复有效机制。
5. Lucida是否开放完整代码及可直接导入Unity、Unreal、USD或URDF的资产。
6. WebWorld的交互契约能否覆盖Canvas/WebGL和实时多人网页。
7. LayerRecall对同脸不同服装、多人同框和镜头跳切的身份混淆率。
8. CE3D++能否通过按需加载或远程服务，把100GB显存降到可用工作站范围。

本周建议小实验：

- **生成世界回访测试**：用Matrix-Game设计“进入房间—绕行—离开—返回”的固定相机轨迹；记录FPS、回访物体位置误差和主体身份漂移。成功判据是两次回访主要几何和关键物体保持一致。
- **视频到物理沙盒测试**：运行Code-as-World弹道足球示例，修改重力、摩擦和初速度；成功判据是代码参数变化产生方向正确、可重复的轨迹差异。
- **长视频人物记忆测试**：用LayerRecall构造三镜头人物离场—场景切换—人物重现序列；成功判据是身份、服装和配件召回优于同骨干无记忆版本，同时当前动作不被冻结。
- **互动作品验收闭环**：为一个HTML小游戏定义“开始、移动、得分、重开、旧能力不回归”五项交互契约，用Playwright执行；成功判据是coding agent每轮修改都必须通过浏览器状态断言后才能合并。
