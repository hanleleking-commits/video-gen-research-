# 数字人、世界模型与互动作品研究日报：2026-10-15

检索窗口：2026-10-09 至 2026-10-15。  
信息截点：2026-10-15（Asia/Shanghai）。已与 10 月 9—14 日日报去重；论文日期以 arXiv 提交记录为准。

## 1. 本日摘要

本日高质量增量高度集中于机器人世界模型：研究重点从“生成看起来合理的未来视频”转向“预测结果能否指导动作、匹配真实执行，并在部署后持续改进”。  
GreenWAM 是最完整的新增：它统一 20 类机器人动作空间，同时开放四组 checkpoint、评测代码和策略服务端，并把真实人形机器人策略蒸馏到单张 RTX 4090 上 35.4 ms、28.3 Hz。  
Thinker-WM、UniW(A)M 分别通过共享 RGB—深度—动作表示和 MoE 能力路由，把 world model、inverse dynamics 与 policy 收进同一参数体系，但尚缺开放代码或闭环第三方验证。  
WAVE-0 代表另一条更务实的路线：不生成像素，而用 257M 潜空间模型预测动作后果，在三项实机任务中把 π0.5 的平均成功率由 38.3% 提至 73.3%。  
LoopWAM、ForceWAM 与 ACCRUE 共同表明，部署中的失败、次优轨迹、无任务 play data 和在线强化学习正在成为训练资产，而非需要丢弃的噪声。  
WorldOracle 首次把世界模型输出与“同初始状态、同低层动作”的真实机器人录像成对比较，补上仅靠视频美学指标无法识别“生成成功、现实失败”的评测缺口。  
数字人方向本日没有达到收录门槛的新模型、API 或产业部署；相较上期 bitHuman、FaceGAN、LTX-Avatar，暂无实质新增。  
Coding 侧的重要变化是世界模型开始提供策略服务器、benchmark client、配置文件和可复现 checkpoint；但除 GreenWAM 与 HyperFrames 外，多数项目仍只有论文或 demo，距离稳定工业运行仍缺延迟、并发、安全门禁与第三方复现。

## 3. 最值得关注的 9 个进展

### 1. GreenWAM：同一世界基础模型跨机器人承担预测与控制

- **类型 / 日期 / 主线：**论文、GitHub、模型权重、策略服务；2026-10-13；世界模型、Coding、机器人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.18774)、[项目页](https://greenvla.github.io/GreenWAM/)、[代码与复现指南](https://github.com/GreenVLA/GreenWAM)。
- **相对上期的新变化：**首次收录；相比此前针对单一机器人或任务的 WAM，新增跨 20 类机器人身体的统一动作协议和完整评测入口。
- **核心贡献：**将不同机器人的关节布局映射到 79 个解剖动作槽，基于 Cosmos 3 Edge 联合训练视觉预测、动作条件生成和 world-action 模式；策略适配时分离 action expert，但保持逐层联合注意力。
- **关键结果：**作者报告 RoboTwin 2.0 平均成功率 67.54%、LIBERO-plus 零样本 86.8%；蒸馏学生在 RTX 4090 上单步 35.4 ms、28.3 Hz。真实机器人证据仅覆盖一台人形机器人和一项连续装袋任务，不能外推为通用部署。
- **Coding 接口：**提供 RoboTwin、CALVIN、LIBERO 的 Python 策略服务器、WorldArena rollout、benchmark client、配置与统计文件；可作为 RPC 式机器人策略后端。
- **场景：**工业机器人策略验证、跨本体技能迁移、数字孪生、机器人训练回放。
- **成熟度 / 证据：**已开源评测代码和四组 checkpoint；论文实测，尚无第三方复现。
- **重要性 / 阅读：**高 / 必读。

### 2. WorldOracle：让世界模型预测与真实执行逐帧对账

- **类型 / 日期 / 主线：**benchmark、dataset 计划；2026-10-13；世界模型评测。
- **官方链接：**[论文](https://arxiv.org/abs/2610.18826)。
- **相对上期的新变化：**把 MultiWorldBench 的共享状态评测扩展到真实机器人执行一致性。
- **核心贡献：**以相同初始观察和低层动作序列，比较模型 rollout 与真实执行，评测物理状态正确性、交互空间对齐、关键交互区域保真度和多视角动作一致性；测试包含成功及失败轨迹。
- **Coding 接口：**可嵌入策略发布 CI：记录真实执行，再让候选 world model 重放动作并计算差异，拒绝“视觉自然但物理结果错误”的版本。
- **边界：**论文评测七个模型；数据、评测代码和 leaderboard 仍写作“will release”，截至截点未核验到公开仓库。
- **场景：**机器人策略预验证、仿真替代评估、模型版本回归测试。
- **成熟度 / 证据：**论文 benchmark；作者实测。
- **重要性 / 阅读：**高 / 必读。

### 3. WAVE-0：用轻量潜空间未来预测增强 VLA

- **类型 / 日期 / 主线：**论文、实机研究；2026-10-13；世界模型、机器人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.18568)。
- **相对上期的新变化：**延续 LeWAM、PLaW-VLA 的潜空间路线，但更明确地让预测未来表示成为 action expert 的输入。
- **核心贡献：**257M 世界模型把 VLM 产生的潜动作计划变成未来视觉表示，再条件化动作生成；直接用真实机器人动作训练，并以反事实排序区分不同动作计划，无需像素重建或大规模视频预训练。
- **关键结果：**作者报告 RoboTwin 2.0 为 91.47%、LIBERO 为 98.7%；三项实机任务平均成功率从 π0.5 的 38.3% 提升至 73.3%。
- **Coding 接口：**适合封装为 `observation + instruction → latent plan → predicted consequence → action chunk`；但尚无可核验代码。
- **场景：**算力受限的机器人规划、工业动作决策、低成本数字孪生。
- **成熟度 / 证据：**实机研究原型；论文实测。
- **重要性 / 阅读：**高 / 必读。

### 4. ForceWAM：把未来力觉变成可执行条件

- **类型 / 日期 / 主线：**论文、项目 demo；2026-10-13；世界模型、力控机器人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.18852)、[项目页](https://force-wam.github.io/)。
- **相对上期的新变化：**相较 DreamTrue、Grounded-Dreamer 的视觉与物理验证，进一步把六轴力/力矩作为显式预测模态。
- **核心贡献：**ForceWM 从成功示范学习任务需要的视觉—力觉未来；inverse dynamics model 同时从示范和无任务 play data 学习动作响应。运行时缓存较慢更新的未来参考，并用最新力觉快速修正动作。
- **关键结果：**作者报告滑动、翻箱、受扰翻箱和套环四种条件成功率为 85%—95%；play data 带来 15—45 个百分点增益，每项为 20 次实机试验。
- **Coding 接口：**`任务 → 视觉/力觉参考轨迹 → 快速 IDM → 安全控制器`；慢规划和快反馈可以作为两个独立进程部署。
- **边界：**arXiv 摘要称代码可用，但项目页仍标注 “Code coming soon”，故代码状态按**待发布**处理。
- **成熟度 / 证据：**实机研究 demo；作者实测。
- **重要性 / 阅读：**高 / 必读。

### 5. LoopWAM：从成功、次优和失败部署轨迹共同学习

- **类型 / 日期 / 主线：**论文、项目 demo；2026-10-13；世界模型、持续部署。
- **官方链接：**[论文](https://arxiv.org/abs/2610.18873)、[项目页](https://loop-wam.github.io/)。
- **相对上期的新变化：**把上期“失败样本后训练”推进为多轮部署—采集—再训练闭环。
- **核心贡献：**来源相关噪声采样、质量 steering 与质量加权监督允许模型保留全部视频后果，但不盲目模仿失败动作；视频和动作 token 在并行去噪中持续交互。
- **关键结果：**作者报告 RoboChallenge Table30-V2 经三轮循环由 23.67% 提至 43.33%；衬衫折叠经两轮由 13.20% 提至 55.56%。
- **Coding 接口：**需要 rollout 数据仓、质量标注器、训练调度器、版本注册和可回退部署系统；模型只负责学习后果与动作联合分布。
- **成熟度 / 证据：**实机/benchmark 研究原型；作者实测，未核验到公开代码。
- **重要性 / 阅读：**高 / 必读。

### 6. Thinker-WM：RGB、度量深度与动作共享动力学表示

- **类型 / 日期 / 主线：**论文、项目 demo；v1 2026-10-13，v2 2026-10-14；世界模型。
- **官方链接：**[论文](https://arxiv.org/abs/2610.18447)、[项目页](https://thinkercosmos.ubtrobot.com/)。
- **相对上期的新变化：**产品名称早于本窗口出现；本次纳入原因是窗口内首次发布完整架构论文并修订。
- **核心贡献：**统一动力学 Transformer 联合生成 RGB、metric depth 和动作，同一参数支持 world prediction、policy、action-to-video、video-to-action 和 inverse dynamics。
- **证据边界：**训练语料约含 2 万小时第一视角视频、1 万小时真机和 1 千小时仿真；榜单结果均为作者报告，真实机器人闭环策略和长时漂移尚未充分量化。
- **Coding 接口：**从架构上可通过模式 token 选择预测或控制功能，但未见公开 SDK、权重或稳定服务接口。
- **场景：**工业机器人多模态预测、三维状态检查、动作恢复。
- **成熟度 / 证据：**研究 demo / 官方声称与论文实测。
- **重要性 / 阅读：**中高 / 必读。

### 7. UniW(A)M：用 MoE 原子能力统一多种 WAM 接口

- **类型 / 日期 / 主线：**论文；2026-10-13；世界模型、运行时路由。
- **官方链接：**[论文](https://arxiv.org/abs/2610.18697)。
- **相对上期的新变化：**把“选择哪个模型”改成“同一模型中按执行 chunk 选择接口”。
- **核心贡献：**共享专家学习公共动力学，原子能力专家服务不同条件和输出接口；PAIR 路由器可在冻结主干的情况下，为每个执行块选择合适的 WAM 接口。
- **关键结果：**作者报告三项实机任务平均成功率 88.3%，最强基线 76.7%；PAIR 将 OOD 成功率从 63.3% 提至 76.7%。样本规模和差异显著性仍需独立复核。
- **Coding 接口：**路由器可以按延迟预算、传感器可用性和任务阶段选择 policy、inverse dynamics 或 action-conditioned prediction。
- **成熟度 / 证据：**论文原型；无公开代码。
- **重要性 / 阅读：**中高 / 可读。

### 8. ACCRUE：让机器人部署后学习新任务而少遗忘旧任务

- **类型 / 日期 / 主线：**论文、实机 demo、持续学习；2026-10-13。
- **官方链接：**[论文](https://arxiv.org/abs/2610.18596)、[项目页](https://accrue-rl.github.io/)。
- **相对上期的新变化：**补上 world/VLA 模型部署后的持续 RL 生命周期。
- **核心贡献：**跨任务继承轻量 actor—critic；critic 只用当前任务 transition 适配，actor 通过少量旧轨迹蒸馏保持旧行为；固定视觉特征避免基础模型更新破坏 replay 表示。
- **关键结果：**作者报告实机训练时间降低 31.0%—68.5%，六项旧任务最终平均成功率 98.3%。
- **Coding 接口：**适合作为基础策略外部的可升级适配层，配合 replay store、模型注册、旧技能回归测试和人工接管。
- **成熟度 / 证据：**实机研究原型；项目页代码仍为 coming soon。
- **重要性 / 阅读：**中高 / 可读。

### 9. EgoExplorer 与 HyperFrames：补齐动作数据和代码化创作调试

- **类型 / 日期 / 主线：**dataset/capture toolkit；开源创作运行时更新；均为 2026-10-13。
- **官方链接：**[EgoExplorer 论文](https://arxiv.org/abs/2610.18872)、[项目页](https://internrobotics.github.io/egoexplorer.github.io/)、[HyperFrames v0.8.151](https://github.com/heygen-com/hyperframes/releases/tag/v0.8.151)。
- **相对上期的新变化：**EgoExplorer 新增视觉—全身—手指—触觉同步数据入口；HyperFrames 新增实时预览检查和时间线查询能力。
- **核心贡献：**EgoExplorer 发布 100+ 小时、2,715 段人类移动操作数据的项目说明，以五个追踪器恢复 SMPL-X，并同步手指与触觉；HyperFrames 新增 element map、live inspection、Node runtime、时间线查询和区间快照。
- **Coding 接口：**前者适合作为动作生成、retarget 和 humanoid world model 数据源；后者让 coding agent 能检查具体组件、时间线和渲染快照，而非只根据最终视频盲改代码。
- **边界：**EgoExplorer 页面仍称 dataset、capture toolkit 与 reconstruction code “will be released”；HyperFrames 是离线/预览式媒体工程组件，不是低延迟互动世界运行时。
- **成熟度 / 证据：**项目 demo / 正式开源工具更新。
- **重要性 / 阅读：**中 / 可读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**本周期今日暂无新的 talking-head、speech-driven avatar 或 portrait animation 模型达到高质量收录标准。
- **3D/4D 表示：**暂无新的人体 Gaussian、NeRF、mesh 或自由视点数字人资产管线。EgoExplorer 提供 SMPL-X 动作重建，但目标是机器人示范数据，并非人物外观生成。
- **实时交互：**没有新的双工数字人系统披露语音到动作延迟、打断恢复、倾听行为或多并发数据。
- **音视频与情感：**相较上期 LTX-Avatar、FaceGAN、Sonic-AMG 和 PAGE，今天没有新的口型、情绪、眼神或手势控制结果。
- **工程部署：**HyperFrames 的 live inspector、时间线查询和区间快照能改善代码生成视频的调试与回归，但不生成数字人本身。
- **安全与身份治理：**本日没有新的授权、撤回、水印、C2PA、深伪检测或肖像治理发布。

结论：数字人今天应标记为“无高质量新增”。已有系统正从视频生成器走向可控会话组件，但低延迟双工、身份授权和长时间稳定性仍未形成统一开放栈。

## 5. 世界模型进展

- **架构与训练：**出现三种收敛路线：GreenWAM/Thinker-WM 的统一多模态模型，UniW(A)M 的专家路由，以及 WAVE-0 的轻量潜未来预测。
- **可控与可玩：**本日没有新的消费级可玩视频世界；控制增量主要发生在机器人 action chunk 和策略接口。
- **长时与物理一致性：**LoopWAM利用部署失败持续改进；ACCRUE解决连续学习遗忘；但生成 rollout 的长时误差累积仍未解决。
- **空间与物理表示：**RGB 已不再够用。深度、机器人状态、六轴力矩、共享解剖动作槽和触觉正在进入显式接口。
- **机器人/仿真：**这是今日证据最强方向，已有多项实机结果；但任务规模仍小，无法等同于工厂规模化部署。
- **实时部署：**GreenWAM 的 28.3 Hz 是最明确的新数据；其他项目普遍未披露端到端 p95、并发、故障恢复或持续运行时长。
- **评测：**WorldOracle 的关键价值是把“模型预测的未来”与真实执行绑定；未来 benchmark 应同时报告预测误差、任务成功、安全违例和校准误差。

## 6. Coding × 新型互动作品

### 链路一：可检查、可回退的机器人世界模型服务

**传感器与任务指令 → GreenWAM 策略服务器 → action chunk → 机器人/模拟器 → 执行录像 → WorldOracle 对账 → 模型注册或回退**

代码负责请求协议、动作限幅、日志、版本和发布门禁；模型负责预测未来与提出动作；传统控制器负责硬实时和安全。GreenWAM 已有可运行代码，WorldOracle 评测代码尚待发布。

### 链路二：低成本“先想后做”控制

**VLA 语义计划 → WAVE-0 潜未来 → action expert → 执行首段 → 新观察重规划**

代码负责任务状态、预算和安全约束；潜世界模型负责预测动作后果；无需把未来解码成视频。本链路已有实机论文证据，但没有开放实现。

### 链路三：触觉化训练与虚拟调试

**EgoExplorer 人类示范 → 全身/手指/触觉重建 → retarget → ForceWAM 视觉—力觉未来 → 快速 IDM → 机器人**

生成模型负责补全动作和未来接触状态；代码负责坐标转换、时间同步与安全控制；物理引擎负责平衡、碰撞和关节约束。ForceWAM已有实机证据，EgoExplorer数据和工具仍待完整发布。

### 链路四：从失败中持续进化的数字员工或机器人

**生产部署 → 成功/次优/失败日志 → 质量标注 → LoopWAM 再训练 → ACCRUE 在线适配 → 旧技能回归 → 灰度发布**

代码承担数据 provenance、权限、人工接管、旧技能测试和回滚；模型从全部视觉后果学习，但只对高质量动作赋予较强模仿权重。机器人场景有实测；迁移到长期游戏 NPC 或数字员工属于**本报告推断**。

### 链路五：Coding agent 驱动的可检查互动叙事

**agent 生成 HTML/时间线 → HyperFrames live inspector → 查询组件与关键帧 → 区间快照 → 自动视觉测试 → 发布视频或互动页面**

代码负责确定性布局、时间线和资产依赖；生成模型可负责角色视频、语音和背景；运行时负责预览、定位和导出。本周期已有开源工具证据，但与实时 world model 的联动仍属**本报告推断**。

## 9. 系统架构与技术趋势判断

- **明显升温：**world-action model、部署数据闭环、失败轨迹利用、力觉/深度等非 RGB 模态、真实执行一致性评测。
- **相对降温：**单纯追求视频观感的机器人世界模型；今日高价值工作都要求预测进入控制、评测或训练闭环。
- **主流技术路线：**统一表示不是唯一答案。复杂系统正在分化为三种可复用架构：统一多模态 Transformer、共享主干加专用 action expert、轻量潜空间预测器加传统执行层。
- **可复用系统栈：**`传感器 → 状态/任务服务 → world model 或 latent predictor → action expert → 安全控制器 → 执行日志 → 真实对照评测 → 数据回流`。
- **代码的角色：**持有任务状态、接口契约、权限、质量标签、回放和回滚；生成模型负责提出视觉/状态未来与动作候选；传统引擎或控制器负责确定性物理、安全边界和硬实时。
- **关键未解问题：**长时 rollout 漂移、跨机器人动作标准、开放训练数据、模型置信度校准、异常接管、p95 延迟、并发和成本。
- **营销风险：**统一六种功能不等于每种功能都达到工业质量；榜单第一不等于真实闭环安全；少量实机任务不能证明规模化部署。
- **产业判断：**最近最可落地的是“模型提出动作、传统控制器执行、真实录像做回归”的混合系统，而非完全由生成模型接管工厂或互动世界。

## 10. 论文精读候选

1. **[GreenWAM](https://arxiv.org/abs/2610.18774)**  
   值得读：开放度和系统完整性最高。重点看共享动作槽、action expert、蒸馏与 OOD 失败分析。与既有 WAM 的差异是跨本体统一和保持 world-model mode 的策略适配。风险是训练数据与 recipe 未开放。

2. **[WorldOracle](https://arxiv.org/abs/2610.18826)**  
   值得读：重新定义“世界模型预测正确”。重点看四项指标、失败执行样本和多视角协议。风险是数据和官方 evaluator 尚未发布。

3. **[WAVE-0](https://arxiv.org/abs/2610.18568)**  
   值得读：展示不生成像素也能让未来预测参与控制。重点看 prediction bottleneck、反事实排序和实机设置。风险是无代码，难以核验训练成本与基线公平性。

4. **[ForceWAM](https://arxiv.org/abs/2610.18852)**  
   值得读：把视觉未来、力觉未来和快速反馈明确分工。重点看 slow–fast executor、play data 消融和 joint future conditioning。风险是每项仅 20 次试验、代码未开放。

5. **[LoopWAM](https://arxiv.org/abs/2610.18873)**  
   值得读：部署数据闭环最完整。重点看质量 steering、来源相关噪声以及三轮训练曲线。风险是数据筛选、标注成本和多轮实验可复现性。

## 11. 下周跟踪与可行动建议

### 继续跟踪

1. WorldOracle 是否真正开放数据、评测代码和 leaderboard。
2. GreenWAM checkpoint 能否在非 H100 环境量化或裁剪运行。
3. GreenWAM 的 28.3 Hz 是否包含视觉编码、网络传输与控制器时间。
4. WAVE-0、LoopWAM、ForceWAM、ACCRUE 何时开放代码和训练配置。
5. ForceWAM 的力觉预测能否迁移到装配、打磨和柔性材料操作。
6. Thinker-WM 是否开放权重，以及 RGB—深度—动作统一表示能否改善真实闭环成功率。
7. EgoExplorer 数据的许可、隐私处理、触觉校准和下载规模。
8. 世界模型评测能否统一报告 p95 延迟、安全违例、校准误差和长时漂移。

### 本周可做的小实验

1. **GreenWAM 策略服务烟雾测试**  
   目标：验证权重、配置、服务端和 benchmark client 是否形成可运行闭环。  
   组件：GreenWAM、对应 checkpoint、RoboTwin 或 WorldArena。  
   难点：多环境依赖和 GPU 显存。  
   成功判据：固定请求可重复返回动作，并能生成一条带时间统计的完整 rollout。

2. **真实执行一致性迷你版**  
   目标：提前实现 WorldOracle 的核心思想。  
   组件：十条真实/仿真执行录像、同动作条件的模型预测、对象检测与关键区域相似度。  
   难点：时间对齐和“视觉相似但任务状态错误”。  
   成功判据：自动识别至少三个“生成成功、现实失败”反例。

3. **潜未来与像素未来的成本对比**  
   目标：比较 WAVE-0 式 latent predictor 与视频世界模型在策略选择中的价值。  
   组件：小型 latent dynamics、视频预测 baseline、同一 action-ranking 任务。  
   难点：确保两者使用相同观察和动作数据。  
   成功判据：报告成功率、每次规划 GPU 时间和显存，而不只比较视频质量。

4. **Coding agent 创作回归测试**  
   目标：验证 agent 是否能利用 HyperFrames inspector 修复时间线错误。  
   组件：HyperFrames v0.8.151、含字幕/数字人/转场的测试项目、视觉快照。  
   难点：把视觉缺陷转换为可执行断言。  
   成功判据：agent 能定位错误组件和时间点，修改后区间快照测试稳定通过。
