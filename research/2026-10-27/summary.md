# 数字人、世界模型与互动作品研究日报：2026-10-27

检索窗口：2026-10-21 至 2026-10-27。  
信息截点：2026-10-27（Asia/Shanghai）。已与 10 月 21—26 日日报去重。多项论文的 arXiv v1 时间为 10 月 22—23 日，但进入 10 月 26 日工作日发布批次，晚于上期日报截点，故计为本日新增。

## 1. 本日摘要

本日最强增量是世界模型开始形成更清晰的“统一控制协议＋显式几何接口＋持续运行状态”。UniAction把力、相机、手部姿态和机器人姿态编码为同一种稀疏动作元素，并同步开放代码、权重和训练数据，使不同控制器可以接入同一个视频模型。

UniWorld则把深度轨迹定义为模拟器与生成式渲染器之间的通用接口，并维护同步的视觉历史与几何历史；但其所谓实时仅指8张H100上的DiT前向吞吐，不包含VAE、输入处理、网络和事件到显示延迟。

数字人侧出现两个互补进展：AudioLift从单图和语音生成可360°观察的全头Gaussian头像；PASPA用固定大小的持久状态减轻长时共语手势的风格漂移。前者已开放推理代码和权重，但需至少48 GB显存且是离线两阶段流程；后者已证明十分钟级动作生成的状态效率，但代码仍待正式开放。

Coding × 互动作品的核心信号来自WorldMirror和SceneBloom：前者让coding agent迭代编写、执行和验证机器人数字孪生程序，后者把扩散模型提出的室内布局编译为JSON、GLB和Habitat可运行场景。这里代码不再只是生成资产，而是在维护世界状态、约束、依赖和验证结果。

ViT-H进一步证明“视频→动作生成→物理跟踪反馈→偏好优化”可以落到Unitree G1真机，并报告平均250 ms、低于400 ms的视频遥操作延迟；这是窗口内最强的真实运行证据之一，但仍是作者实验而非规模部署。

DirCast显示持续互动作品还需要“实时导演层”：模型每秒查看多路玩家相机，选择播出镜头并生成解说，说明生成式直播的可编程对象可以从单一画面扩展到镜头调度、发言时机和上下文生命周期。

产业成熟度仍未跃迁到客户规模化部署。新增项目主要是论文、开源研究管线和真机demo，未披露生产级并发、P95延迟、SLA或单位会话成本。

安全侧只有Spectra这样的检测研究新增；身份授权、可撤回肖像凭证、生成水印和跨供应商溯源仍无高质量进展。

## 3. 最值得关注的 12 个进展

### 1. UniAction：世界模型的统一动作协议

- **类型 / 日期 / 主线：**论文、GitHub、模型、dataset；v1 2026-10-23，10月26日批次；世界模型、Coding。
- **官方链接：**[论文](https://arxiv.org/abs/2610.32977)、[项目页](https://uniaction.github.io/)、[代码](https://github.com/KBRASK/UniAction)、[模型](https://huggingface.co/BowenXue/UniAction)。
- **相对上期：**全新条目。
- **核心贡献：**把动作表示为“离散语义ID＋连续时空坐标”，用同一机制覆盖力、相机、手部姿态和机器人姿态；作者报告联合训练模型优于分别训练的专家。
- **Coding接口：**Python `UniActionPipeline`；提供`force`、`camera`、`hand_pose`、`robot_pose`条件构造器，可接游戏输入、姿态跟踪或机器人中间件。
- **场景：**可控视频世界、虚拟摄影、手势交互、机器人预测。
- **成熟度 / 证据：**已开源；作者论文实测。Apache-2.0代码，40,000样本训练集约70.7 GB，底座及源数据许可证另行约束。
- **重要性 / 阅读：**高 / 必读。

### 2. UniWorld：用深度轨迹连接模拟器与生成式渲染

- **类型 / 日期 / 主线：**论文、系统原型；2026-10-23；世界模型、运行时。
- **官方链接：**[论文](https://arxiv.org/abs/2610.32381)。
- **相对上期：**全新条目。
- **核心贡献：**以参考图提供外观、以深度序列提供几何演化；通过重叠窗口与滚动深度latent同步维护视觉和几何历史，已提交内容不会被后续窗口改写。
- **Coding接口：**上游引擎只需输出对齐的深度轨迹；同一接口支持估计深度、模拟器原生深度和按需生成的几何分支。
- **场景：**持续漫游、模拟器写实化、互动预演、分支世界。
- **成熟度 / 证据：**研究原型；作者实测。报告960×544为14.472 FPS、672×384为21.361 FPS，但使用8×H100，且计时排除了VAE、打包和输出等环节。
- **重要性 / 阅读：**高 / 必读。

### 3. WorldMirror：coding agent迭代构建可执行数字孪生

- **类型 / 日期 / 主线：**论文、agent系统；2026-10-22；Coding × 世界模型、机器人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.31834)。
- **相对上期：**全新条目。
- **核心贡献：**把real-to-sim定义为“可执行世界程序”的反复修正。coding agent编排重建、标定、布局和回放工具，通过类型化失败信息回退到依赖阶段。
- **Coding接口：**结构化world state、固定构建图、可调用专用agent、候选更新提交/回滚协议及轨迹回放验证。
- **场景：**机器人训练数据、策略测试、工厂数字孪生、操作教学。
- **成熟度 / 证据：**论文原型；作者在少量DROID场景实测。未公开代码，未验证下游策略学习或跨任务泛化。
- **重要性 / 阅读：**高 / 必读。

### 4. AudioLift：单图与语音生成全头3D Gaussian头像

- **类型 / 日期 / 主线：**论文、GitHub、权重、demo；2026-10-22；数字人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.31747)、[项目页](https://zhuoyuanjiang.github.io/audiolift-page/)、[代码](https://github.com/ZhuoyuanJiang/AudioLift)。
- **相对上期：**全新条目。
- **核心贡献：**先生成五路同步视频，再逐帧提升为Gaussian头像；不依赖3DMM/FLAME或单身份优化，能保留帽饰并支持360°渲染。
- **Coding接口：**`inference.py --reference --audio --out`，两阶段可分别重跑，输出正面、视角扫描、360°环绕视频和运行元数据。
- **场景：**自由视角数字讲师、虚拟演出、影视预演、XR头像。
- **成熟度 / 证据：**已开源推理代码和权重；作者实测。默认至少48 GB VRAM、无训练代码，不是实时对话avatar。
- **重要性 / 阅读：**高 / 必读。

### 5. ViT-H：视频直接驱动人形机器人

- **类型 / 日期 / 主线：**论文、真机demo；2026-10-23；数字化身、机器人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.32966)、[项目页](https://awfuact.github.io/vit-h/)。
- **相对上期：**全新条目。
- **核心贡献：**扩散模型直接由单目视频生成G1参考动作，绕过人体重建和重定向；再按物理跟踪结果对候选动作做DPO。
- **Coding接口：**视频条件、自动回归动作生成器与运动控制器构成闭环；跟踪结果可作为后训练奖励。
- **场景：**机器人化身、远程表演、危险环境遥操作、动作资产迁移。
- **成熟度 / 证据：**真机研究demo；作者报告平均250 ms、低于400 ms，但未开放代码或安全控制栈。
- **重要性 / 阅读：**高 / 必读。

### 6. SceneBloom：把生成布局编译为Habitat场景

- **类型 / 日期 / 主线：**论文、GitHub、3D场景生成；2026-10-23；Coding、仿真。
- **官方链接：**[论文](https://arxiv.org/abs/2610.32978)、[代码](https://github.com/Tinaliu0123/scenebloom)。
- **相对上期：**全新条目。
- **核心贡献：**扩散先验提出房间布局，约束编译器提取关系、拟合几何并修正姿态；作者报告五类房间中未检测到mesh碰撞或越界对象。
- **Coding接口：**CLI接受房间prompt，输出`scene_layout.json`、渲染图、`scene.glb`并可直接导入Habitat。
- **场景：**机器人训练、程序化关卡、空间设计、虚拟展厅。
- **成熟度 / 证据：**已开源研究管线；依赖OpenRouter、FLUX.1-dev、Genesis及约45 GB模型/资产。
- **重要性 / 阅读：**高 / 必读。

### 7. PASPA：长时共语动作的固定大小状态

- **类型 / 日期 / 主线：**NeurIPS 2026论文；2026-10-23；数字人。
- **官方链接：**[论文](https://arxiv.org/abs/2610.32373)。
- **相对上期：**全新条目。
- **核心贡献：**将过去动作压缩为持久状态，当前块仍使用双向注意力；prefill/decode缓存避免上下文随时长持续增长。
- **Coding接口：**适合作为SMPL-X/骨骼动画服务的流式动作模块，状态可与会话ID绑定。
- **场景：**长时数字讲师、虚拟主播、NPC闲聊和陪伴角色。
- **成熟度 / 证据：**论文原型。作者在4090上测试最长600秒；十分钟动作生成约56秒、峰值约0.47 GB（不含完整数字人渲染）。代码承诺发布但本次未确认可访问。
- **重要性 / 阅读：**高 / 必读。

### 8. Ψ-0.6：把几何和想象变成可选择的推理步骤

- **类型 / 日期 / 主线：**论文、统一模型；2026-10-23；世界模型。

- **场景：**空间规划、可解释关卡agent、机器人预演、交互设计检查。
- **成熟度 / 证据：**研究原型、代码与权重待发布；物理控制仍只是视觉代理动作。

### 9. DirCast：持续运行的多镜头导演与解说agent

- **类型 / 日期 / 主线：**论文、数据集、demo；2026-10-22；Coding × 互动直播。
- **官方链接：**[论文](https://arxiv.org/abs/2610.31734)。
- **相对上期：**全新条目。
- **核心贡献：**每秒低分辨率扫描十路玩家画面，决定保持或切换镜头，再高分辨率读取选中画面并生成解说；只保留播出历史以限制长流成本。
- **Coding接口：**事件流、镜头选择器、发言门控和持久上下文，可接OBS、游戏观战API或直播服务器。
- **场景：**电竞直播、体育自动制作、多人互动演出。
- **成熟度 / 证据：**论文demo；作者基于27场Dota 2比赛实测，无生产直播或故障切换证明。
- **重要性 / 阅读：**中高 / 必读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**AudioLift将单图talking head提升为可自由观察的全头动态Gaussian；PASPA关注长会话中身体风格不漂移；ViT-H把真人视频动作直接映射到机器身体。三者分别解决外观空间化、长时动作和物理可执行性。

- **3D/4D表示：**Gaussian序列正在成为视频扩散与实时渲染之间的中间资产，但AudioLift当前输出更接近逐帧动态表示，尚未证明可直接编辑骨骼、表情blendshape或碰撞体。

- **实时交互：**ViT-H有平均250 ms真机闭环证据；PASPA的动作生成速度快于实时，但不包括LLM、ASR、TTS、面部、渲染和网络。AudioLift明确属于离线生成。

- **音视频与情感：**语音到手势和语音到全头表情均有进展，但可打断倾听表情、视线、turn-taking和跨语言情绪仍没有端到端新增。

- **工程部署：**AudioLift值得进入离线原型；PASPA适合等待代码后接入SMPL-X管线；ViT-H只适合受控实验，不能按消费级avatar SDK理解。

- **安全与身份治理：**Spectra改善检测侧研究，但未解决授权、撤回、可验证水印和肖像使用记录。AudioLift的单图输入进一步提高滥用风险，产品层必须增加授权凭证和输出标识。

## 5. 世界模型进展

- **架构与训练：**UniAction表明异构动作可共享一个条件空间；Ψ-0.6进一步尝试让文本、图像、几何和模拟共享token接口。
- **可控/可玩生成：**相机、力、手、机器人动作不再需要四套模型，但UniAction仍是81帧离线生成范式，未证明按键到画面的实时闭环。
- **长时与物理一致性：**UniWorld用不可改写的已提交latent和滚动深度状态约束长时生成；WorldMirror则把物理一致性放到可执行程序与轨迹回放中验证。
- **空间表示：**深度、Gaussian、mesh、JSON布局、GLB和物理碰撞体正在形成模型与引擎之间的中间协议。
- **机器人/游戏/仿真：**WorldMirror、SceneBloom和ViT-H均把生成结果交给仿真器或控制器验证，证据强于只展示视频的世界模型。
- **实时部署与评测：**“实时”仍需拆解。UniWorld为8×H100的模型前向吞吐；ViT-H为真机视频遥操作延迟；两者不可直接比较。

## 6. Coding × 新型互动作品

### 链路一：统一动作驱动的生成世界

**游戏/机器人事件 → UniAction动作元素 → 视频世界模型 → 行为一致性评测 → 可控互动画面**

代码负责实体ID、动作权限、坐标和时间；模型负责视觉结果。代码、权重和接口已存在，但仍是离线片段生成。

### 链路二：传统引擎状态的生成式写实化

**物理引擎/关卡代码 → 深度轨迹 → UniWorld持续渲染 → 已提交历史锁定 → 玩家观看**

引擎维护碰撞、规则和权威状态，模型负责写实外观。已有论文运行证据，端到端输入延迟和成本尚不适合生产游戏。

### 链路三：视频自动编译机器人数字孪生

**机器人示范视频＋轨迹 → WorldMirror coding agent → 资产/相机/物理程序 → 回放验证 → 定向修复**

代码既是世界表示，也是可审计的构建产物；生成模型只负责特定资产和几何。论文证明链路可运行，开放复现仍缺失。

### 链路四：文本生成可训练室内世界

**房间prompt → FLUX布局候选 → 关系抽取与约束编译 → JSON/GLB → Habitat导航训练**

模型负责提出多样布局，编译器负责无碰撞、边界和资产放置，Habitat负责真实交互。SceneBloom已有开源最小闭环。

### 链路五：长时数字讲师

**LLM台词 → TTS音频 → PASPA持久动作状态 → SMPL-X角色 → 引擎渲染**

会话系统维护角色记忆和中断；PASPA生成身体动作；传统角色系统处理骨骼约束和渲染。动作模块有论文证据，完整实时数字人组合属于本报告推断。

### 链路六：多镜头生成式直播

**游戏观战API/多摄像头 → DirCast镜头选择 → 解说生成 → TTS/数字主播 → OBS或直播服务器**

代码负责多路流同步、切镜、延迟预算、禁播规则与人工接管，模型负责叙事判断和语言表达。论文demo可运行，生产安全与版权流程未验证。

## 9. 系统架构与技术趋势判断

正在升温的是四层可复用架构：

1. **权威世界层：**引擎、world state、JSON布局、物理参数和轨迹保存可检查事实。
2. **统一接口层：**动作元素、深度序列、Gaussian、mesh和GLB连接不同模型与运行时。
3. **生成表现层：**视频扩散、头像模型和多视图生成负责外观与运动细节。
4. **agent工程层：**coding agent、工具路由、验证器、持久记忆和回滚负责持续运行。

世界模型正从“模型内部隐式学会所有物理”转向“外部代码维护规则，生成模型实现视觉和动作先验”。WorldMirror、SceneBloom与UniWorld均支持这一判断。

数字人也从单独优化嘴型转向全头空间表示、长时身体状态和可执行动作，但面部、身体、语音、记忆和实时打断仍未由一个开放系统完整打通。

需要降级看待的说法包括：把8×H100的DiT吞吐称为产品实时；把单图离线Gaussian序列称为实时3D avatar；把少量机器人demo称为可泛化工业部署；以及只承诺未来开源而无当前入口的系统。

## 10. 论文精读候选

1. [UniAction](https://arxiv.org/abs/2610.32977)：重点读动作元素、cardinality-calibrated attention和联合训练消融。与LiveAct的差异是更通用且已开源，但不是实时多主体运行时。

2. [UniWorld](https://arxiv.org/html/2610.32381v1)：重点读噪声对齐重叠续写、rolling depth state和运行时计时边界。复现风险是8×H100及多个大模型组件。

3. [WorldMirror](https://arxiv.org/abs/2610.31834)：重点读world state、router合法转移、失败回退和轨迹回放。它比单次3D重建更像软件工程系统；风险是代码未开源、评测场景少。

4. [PASPA](https://arxiv.org/html/2610.32373v1)：重点读Past-as-State/Present-as-Attention、prefill-decode缓存及长时漂移曲线。风险是运动指标不等同于完整数字人的感知质量。

5. [ViT-H](https://arxiv.org/abs/2610.32966)：重点读跟踪反馈如何构造DPO偏好及在线自动回归变体。风险是真机安全、网络延迟和失败恢复细节不足。

## 11. 下周跟踪与可行动建议

继续跟踪：

1. UniAction是否增加键鼠/控制器流式接口、多主体ID和动作到显示延迟。
2. UniWorld是否开放代码，并补齐VAE、输入处理和网络后的端到端P50/P95。
3. WorldMirror是否开放世界状态schema、构建技能和模拟器适配器。
4. AudioLift能否输出可编辑Gaussian、mesh或骨骼绑定，而不只是渲染视频。
5. PASPA代码与checkpoint何时开放，能否处理语音中断和说话人切换。
6. ViT-H是否披露失联、跌倒和不安全动作的运行时保护。
7. SceneBloom生成的GLB能否稳定进入Unity/Unreal，而不仅是Habitat。
8. 新型单图3D头像是否配套授权证明、水印和删除传播机制。

本周可动手实验：

- **统一动作API：**用UniAction分别接WASD、鼠标拖拽力和MediaPipe手部轨迹。难点是坐标及81帧时间对齐；成功判据是动作启动误差不超过两帧，且三类控制无需更换模型。

- **文本到可运行房间：**用SceneBloom生成办公室并导入Habitat。难点是模型下载、API依赖和资产许可；成功判据是agent可连续导航十分钟，无穿模、越界或不可达关键对象。

- **全头头像复现：**用AudioLift测试正脸、侧脸、帽饰三组输入。难点是48 GB显存和两套环境；成功判据是三个固定视角均保持身份和口型，360°旋转无明显几何断裂。

- **长时数字人状态原型：**将PASPA式固定状态思想应用到现有骨骼动作服务，保存`character_id → motion_state`。难点是打断后的状态重置；成功判据是30分钟会话内动作风格不单调漂移，重新连接可从最近安全姿态恢复。
