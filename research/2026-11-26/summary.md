# 数字人、世界模型与互动作品研究日报：2026-11-26

检索窗口：2026-11-20 至 2026-11-26。已对照 11 月 22—25 日日报去重；日期以官方公告、arXiv 提交记录和仓库更新为准。

## 1. 本日摘要

本日最重要的新增是 ABot-World 0.5：它把动作导致的物理后果持续传递到后续生成块，并开放可在单张 RTX 5090 上运行的 5B 权重、代码和交互界面，是本周期“可本地复现的实时世界模型”最强信号。

NIO WorldModel 3.0则提供了更接近工业规模的证据：4D时空压缩、观测空间与潜空间双闭环强化学习已经进入量产车部署计划；但全部性能数字仍来自厂商，实际推送需等待备案。

数字人侧补录的 BASE 不再绑定特定语音模型内部状态，而是把PCM语音流定义为通用“表演接口”，使云端语音API、开源全双工模型和传统ASR—LLM—TTS管线都能驱动同一套实时全身3D角色。

MAGI-2进一步提高了原生音视频生成的镜头长度、参考控制和角色表演能力，并已经出现异步API；不过生成仍需数分钟，适合互动作品的镜头预生成或分支缓存，不适合逐帧实时世界。

Coding侧的关键增量来自两个评测：3D GameDev Arena表明长时游戏开发可能消耗上千次模型调用，代码通过并不等于玩家喜欢；Movie2Game-Bench则证明coding agent更擅长复刻视觉符号，较弱于把电影情境变成玩家动作和后果。

因此，当前更现实的互动系统不是由单一模型包办，而是由代码保存规则和状态、世界模型渲染或预测、数字人表演层处理语音与动作、传统引擎执行物理和安全约束。

产业成熟度出现两极分化：NWM 3.0已有明确量产计划，ABot-World 0.5和BASE仍是研究或开发者原型，MAGI-2则处于商业API可用但技术报告与完整权重未开放的阶段。

本周期仍没有新的肖像授权凭证、强制水印、身份撤销或数字人深伪治理闭环，安全能力明显落后于生成和运行时能力。

## 3. 最值得关注的 10 个进展

### 1. ABot-World 0.5：单张桌面GPU上的实时可控世界模型

- **类型 / 日期 / 主线：**模型、权重、GitHub、demo；Iris于11月24日开放、Halo于11月25日公布；世界模型、Coding。
- **官方链接：**[GitHub与模型入口](https://github.com/amap-cvlab/ABot-World)、[项目页](https://abot-world.amap.com/)。
- **相对上期：**此前日报遗漏，本日补录。
- **核心贡献：**用Chain of Causation数据保持动作之间的因果承接，PhysTracer筛选和标注碰撞、跌落、接触等连续物理事件；EventAlign让局部文本事件在指定生成区间生效。
- **性能：**官方称Iris-5B在单张RTX 5090上达到21 FPS；Halo-30B联合生成音视频，在单张B200上以480p达到24 FPS，四张B200支持720p。FantasyDecoder在独立解码测试中获得8.26倍吞吐提升，不能等同于端到端加速。
- **Coding接口：**Python CLI、Gradio、WASD/IJKL输入、运行时Prompt Switch、skill按钮、Docker配置。
- **场景：**可玩视频、生成式游戏原型、品牌互动世界、agent训练环境。
- **成熟度 / 证据：**Iris已开源、可运行demo；Halo仅官方展示。指标为官方实测，v0.5技术报告仍待发布。
- **重要性 / 阅读：**高 / 必读。

### 2. NIO WorldModel 3.0：世界模型进入量产车推送计划

- **类型 / 日期 / 主线：**正式产品公告、产业部署；11月25日；世界模型、自动驾驶。
- **官方链接：**[NIO官方公告](https://www.nio.com/news/20261125001)。
- **相对上期：**全新。
- **核心贡献：**以tubelet时空联合编码实现4D压缩；训练端同时运行观测空间闭环和潜空间闭环，并加入奖励模型。
- **指标：**NIO称端侧注意力计算资源降低36倍、底盘控制延迟降低78%、整车控制延迟降低54%、训练效率提高5倍、相对上一代驾驶员接管减少40%。均为厂商口径，未见第三方测试。
- **Coding接口：**不是开发者API；工程接口是车端感知、规划、底盘控制、安全框架和数据闭环。
- **场景：**辅助驾驶、闭环仿真、车队数据回流与策略评测。
- **成熟度 / 证据：**正式产品、待备案部署；计划从12月起覆盖Banyan、Cedar、Cedar S和Coconut+系统。
- **重要性 / 阅读：**高 / 必读。

### 3. BASE：用语音流作为数字人的通用表演接口

- **类型 / 日期 / 主线：**论文、实时3D数字人；arXiv 11月23日；数字人、Coding。
- **官方链接：**[论文](https://arxiv.org/abs/2611.30388)。
- **相对上期：**此前日报遗漏，本日补录。
- **核心贡献：**数字人层只读取用户麦克风和对话后端输出的PCM语音，不依赖token或隐藏状态；统一处理说话、倾听、空闲、抢话和主动发言，并把角色设定、声音、动作风格和VRM外观解耦。
- **性能：**作者报告运动生成每333毫秒窗口耗时中位96.7毫秒、P95 100.7毫秒，显存1.9GB；在80毫秒语音后端上，表演层约增加0.75秒首帧延迟；用户抢话后中位0.28秒取消回复。
- **Coding接口：**PCM流适配器、VAD事件、A/V packer、状态机、SMPL-X到VRM重定向；可连接Gemini Live、PersonaPlex、FLM-Audio、MiniCPM-o或级联TTS。
- **场景：**数字员工、虚拟讲师、全双工陪伴角色、游戏NPC。
- **成熟度 / 证据：**论文实测、可运行研究系统；未发现公开代码或权重。
- **重要性 / 阅读：**高 / 必读。

### 4. MAGI-2：30秒原生音视频与多参考角色表演

- **类型 / 日期 / 主线：**模型、产品、第三方API；模型11月24日发布，API集成11月25—26日更新；数字人、视频基础设施。
- **官方链接：**[Sand.ai产品页](https://sand.ai/)、[EvoLink API更新](https://evolink.ai/changelog)。
- **相对上期：**此前日报遗漏。
- **核心贡献：**生成最长30秒、1080p的同步音视频，覆盖对白、口型、音效、音乐、微表情和身体动作；API支持文本、首尾帧以及图像、视频、音频参考。
- **Coding接口：**异步任务、轮询或callback；EvoLink提供text-to-video、image-to-video和reference-to-video三个模型ID。
- **场景：**互动电影分支镜头、虚拟演员广告、音乐视频、角色对白素材。
- **成熟度 / 证据：**商业API可用；完整模型权重和技术报告尚未开放。第三方实测生成耗时为数分钟，不能用作实时反馈。
- **重要性 / 阅读：**中高 / 可读。

### 5. 3D GameDev Arena：长时coding agent游戏开发评测

- **类型 / 日期 / 主线：**论文、benchmark、公共arena；11月18日；Coding × 互动作品。
- **官方链接：**[论文](https://arxiv.org/abs/2611.24073)、[项目页](https://www.baibizhe.github.io/gamearena/)。
- **相对上期：**窗口内遗漏，本日补录。
- **核心贡献：**108项从零构建任务覆盖14类游戏；agent需规划、编码、寻找或生成资产、浏览器测试和修复，最终同时接受功能测试、agent试玩和盲测人类偏好。
- **规模：**作者称平均约1,000次LLM调用，最长单次运行达到14,407次调用、21.3亿token和608项资产。
- **Coding接口：**coding agent harness、Agent Skills、子agent、浏览器测试、Meshy资产生成和自包含Web游戏。
- **场景：**自动游戏制作、品牌互动页、训练模拟、游戏开发agent回归评测。
- **成熟度 / 证据：**论文和公共arena；未发现完整benchmark代码。作者结果显示功能正确性与玩家偏好并不一致。
- **重要性 / 阅读：**高 / 必读。

### 6. Movie2Game-Bench：评测“影视内容是否真正变成交互”

- **类型 / 日期 / 主线：**论文、benchmark；11月18日；Coding × 互动作品。
- **官方链接：**[论文](https://arxiv.org/abs/2611.24669)。
- **相对上期：**窗口内遗漏，本日补录。
- **核心贡献：**在22部影片、658个片源特定参考项上，评估coding agent能否把人物、情境和情感发展转化为玩家动作、规则、反馈和后果。
- **结论：**14个受测系统的可玩序列内容保留均值仅37.9/100，低于标志性元素的54.8；说明系统更容易“做得像电影”，较难把电影情节变成机制。
- **Coding接口：**沙箱、图像/视频/语音工具、浏览器游戏运行时及三个GUI模型玩家。
- **场景：**IP改编、互动电影、教育叙事、影视营销游戏。
- **成熟度 / 证据：**论文benchmark；未核验到公开实现，且主要评分依赖模型评委。
- **重要性 / 阅读：**中高 / 必读。

## 4. 数字人 / 虚拟形象能力进展

- **生成与驱动：**BASE把语音流稳定为数字人表演层的公共协议；Motion Mamba 2.0处理长时身体运动；MAGI-2负责短时高质量音视频表演。三者分别对应实时控制、骨骼动作和像素级成片。
- **3D/4D表示：**本日没有新的高质量人物重建或4D Gaussian Avatar。BASE采用SMPL-X并重定向至VRM，部署性强于纯神经视频，但外观质量依赖传统角色资产。
- **实时交互：**BASE支持倾听、抢话和主动发言，但端到端首帧仍约1.31—2.97秒，主要瓶颈是语音后端启动和首个动作窗口积累。
- **音视频与情感：**MAGI-2能联合生成对白、表情、视线和身体语言，但分钟级计算时间使它更适合预生成；BASE则用实时语音韵律驱动动作，却缺少纯语义手势。
- **工程部署：**最可复用的新架构是“对话后端 → PCM流 → 表演状态机 → 动作生成 → VRM/引擎渲染”。替换LLM或语音模型不再要求重训动作层。
- **安全与身份治理：**本周期暂无高质量新增。MAGI-2的多参考角色能力和BASE的任意VRM外观都需要外置授权、内容审核、水印和撤销机制。

## 5. 世界模型进展

- **架构与训练：**ABot-World通过因果连续数据改善动作后果传递；NWM 3.0通过4D tubelet压缩降低端侧序列长度和注意力成本。
- **可控与可玩：**ABot-World同时接受键盘动作和不中断rollout的文本事件，是本周期最直接的开放可玩模型。
- **长时与物理一致性：**Chain of Causation比孤立短片训练更接近持续世界，但官方Physical Score不等同于传统物理引擎的确定性约束。
- **空间表示：**Plan4D输出显式深度、点云和scene flow；NWM 3.0仍是车端闭源系统，未公开内部世界状态格式。
- **机器人、驾驶与仿真：**NWM 3.0是最强产业信号；Plan4D更适合实验室几何验证；ABot-World更适合视觉交互和agent训练。
- **实时部署与评测：**实时FPS正在与动作延迟、物理得分、状态持续性和硬件成本一起评估。只报告视频吞吐已不足以说明可玩性。

## 6. Coding × 新型互动作品

### 链路一：本地可玩生成世界

**代码状态机 / WASD事件 → ABot-World Iris → 连续视频世界 → Prompt Switch事件 → 浏览器互动体验**

代码保存任务、得分、权限和不可违反的规则；世界模型负责视觉和局部物理后果；传统服务负责多人同步和持久化。已有开放权重和本地demo。

### 链路二：可替换大脑的全身数字员工

**语音agent或云API → PCM流 → BASE状态机和手势生成 → SMPL-X/VRM → Unity、Unreal或Web渲染**

agent负责知识、工具调用与回复；BASE负责说话、倾听和抢话表演；引擎负责碰撞、镜头和角色资产。已有论文系统证据，但公开开发包缺失。

### 链路三：量产车中的“世界预测—规划—执行”

**多传感器观测 → NWM 3.0世界表示 → 双闭环训练和奖励评估 → 轨迹规划 → 底盘安全控制**

生成模型负责预测和策略表示；车辆代码负责实时调度、限界、冗余和法规要求。已有官方推送计划，但实际道路效果需上线后验证。

### 链路四：互动电影的缓存式生成运行时

**剧情图 → 参考角色与分镜 → MAGI-2异步API → 分支视频缓存 → 播放器按用户选择切换**

代码负责剧情状态、分支预取、审核和失败回退；模型负责角色表演和视听镜头。API已可调用，但数分钟生成时延决定其更适合预生成而非即时世界。

### 链路五：影片自动改编为游戏

**电影解析 → coding agent生成Web游戏 → GUI agent试玩 → Movie2Game-Bench检查内容—动作—后果映射**

代码负责可验证机制；生成工具负责资产；浏览器运行时负责规则与输入。当前最大缺口不是画面，而是把源内容转成真正可玩的因果机制。

### 链路六：长时自动游戏开发

**文字规格和参考图 → 规划agent → 子agent编码与找资产 → 浏览器测试 → 人类/agent试玩反馈**

3D GameDev Arena证明该流程可运行，但平均约千次调用意味着成本、上下文压缩、资产版权和回归测试成为生产约束，而非单纯模型能力问题。

## 9. 系统架构与技术趋势判断

1. **实时世界模型正在分成桌面和工业两条路线。** ABot-World追求开发者可运行、可控视频输出；NWM 3.0追求端侧压缩、训练闭环和安全控制。
2. **PCM语音流正在成为数字人层的稳定协议候选。** 它比依赖某个对话模型的内部token更容易长期维护和替换后端。
3. **代码继续承担权威状态。** 任务、库存、权限、物理边界和审核结果不能交给视频模型隐式记忆。
4. **模型负责“难以手写的连续性”。** 包括自然动作、表情、视觉质感、候选未来和角色表演；传统引擎继续负责确定性规则。
5. **互动内容评测开始关注玩家体验。** 3D GameDev Arena和Movie2Game-Bench均说明，可运行、视觉相似和真正好玩是不同目标。
6. **成本从单次推理转向整个agent轨迹。** 数百至上万次调用、资产下载、浏览器回归和人工试玩决定自动创作能否经济成立。
7. **仍未解决：** 长时物理稳定、多主体因果、多人同步、生产P95延迟、生成资产版权、身份授权和模型版本回归。
8. **需降级看待：** MAGI-2的完整技术材料未开放；ABot Halo尚无可下载权重；NWM 3.0全部指标来自厂商；BASE没有公开实现。均不能据此直接宣称“已规模化通用部署”。

## 10. 论文精读候选

1. **[BASE](https://arxiv.org/abs/2611.30388)**  
   值得读：给出了对话大脑与数字人身体解耦的清晰接口。重点读§3.1状态管理、§3.2滑动窗口、§4.4延迟分解。复现风险是代码缺失。

2. **[3D GameDev Arena](https://arxiv.org/abs/2611.24073)**  
   值得读：少见地量化长时coding agent构建游戏的调用规模、资产管线和玩家偏好。重点读评测三层结构及开发日志分析。风险是测试由模型适配，完整工具链未开放。

3. **[Movie2Game-Bench](https://arxiv.org/abs/2611.24669)**  
   值得读：把“内容是否存在”推进到“是否成为玩家动作和后果”。重点读movie-specific rubric和GUI playtesting。风险是模型评委占比高、缺少公开实现。

4. **[Plan4D](https://arxiv.org/abs/2611.26516)**  
   值得读：展示视频潜变量与显式4D几何对接的工程路线。重点读模型缝合、同步解码和几何critic。风险是基础模型组合复杂、实时指标不足。

5. **[Motion Mamba 2.0](https://arxiv.org/abs/2611.29897)**  
   值得读：适合评估长时数字角色动作层是否能独立于渲染和语音存在。重点读续接、空间目标与延迟测试。风险是从运动指标到真实角色观感仍有较大差距。

### 本周可动手实验

**实验一：ABot-World长时物理与控制测试**

- 目标：区分“实时视频”与“可持续可玩世界”。
- 组件：Iris权重、RTX 5090或可用高显存GPU、Gradio、输入事件日志。
- 难点：记录动作到视觉反馈延迟，并自动检测物体穿透和状态遗忘。
- 成功判据：连续30分钟运行无崩溃；关键物体状态在10次视角切换后仍保持；动作P95延迟可复现。

**实验二：语音流到VRM的后端无关表演层**

- 目标：验证BASE的核心接口，而非等待完整实现。
- 组件：两个不同语音后端、VAD、PCM流、VRM角色、Unity/Godot或Three.js。
- 难点：首帧缓存、抢话取消、说话与倾听动作平滑切换。
- 成功判据：更换后端不修改角色逻辑；抢话后300毫秒内停止旧动作；音画连续无明显接缝。

**实验三：电影片段到可玩机制**

- 目标：验证coding agent能否把内容转为行动和后果，而不只是复刻画面。
- 组件：一段无版权风险的1—2分钟短片、coding agent、Three.js或Phaser、浏览器自动试玩。
- 难点：定义可检验的“情境—动作—反馈—后果”链。
- 成功判据：至少5个源内容要素通过玩家操作触发，且每项都有状态变化或后果；真人试玩者无需说明即可完成核心目标。

**实验四：异步视频模型的互动分支缓存**

- 目标：判断MAGI-2类分钟级模型能否通过预取用于互动电影。
- 组件：剧情状态机、异步视频API、对象存储、播放器和缓存队列。
- 难点：角色一致性、分支爆炸、审核失败和超时回退。
- 成功判据：三层分支中90%以上选择无需等待即可播放；同一角色跨分支保持可辨身份；单次会话生成成本落在预设预算内。
